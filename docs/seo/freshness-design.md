# 記事の鮮度を保つ仕組み（設計案）

作成: 2026-09-27。実装前の設計です。【要判断】の項目に答えをいただいてから指示書に落とします。

## 何が問題か

- 記事 270 本の更新日（`dateModified`）は、ほぼ全部が公開直後の値のまま。年度や税制改正で内容が古くなっても、ページ上も検索エンジン向けのデータも「更新なし」と見える。
- 税務の記事は「令和 7 年分」「2026 年 4 月以後の取得」など年度に縛られた記述が多く、年が変わると読者にとって誤解のもとになる。
- 既にある部品: 税制改正のチェック（`check-tax-reform.yml`、毎月）、国税庁ページの更新検知（`crawl-nta-sources.yml`、ハッシュ比較）、差し戻し再生成（`regenerate-draft.yml`、部分再生成あり）、記事の出典 URL（`source_url`）と税目（`tax_domain`）。足りないのは「変化 → 該当記事 → 更新」をつなぐ部分。

## 方針

1. **勝手に本文を書き換えない。** 検知と候補出しまでを自動化し、更新は毛利さんの承認を通す（記事承認の手動運用と同じ）。
2. **日付を動かすのは実際に内容を確認・更新したときだけ。** 中身が変わらないのに更新日だけ動かすことはしない（検索エンジンに「更新日が信用できないサイト」と見なされる）。
3. **対象を絞る。** 表示が来ている記事と、物販の中核から優先する（GSC のデータで決める）。

## 仕組み

### 1. 変化の検知（既存の部品を集約）

| 信号 | 出どころ | 該当記事の引き方 |
|---|---|---|
| 出典ページの更新 | `crawl-nta-sources` のハッシュ差分 | `source_url` が一致する記事 |
| 税制改正の項目 | `check-tax-reform` の結果（`data/tax-reform-outline.json`） | `tax_domain` と `category`、本文中の制度名 |
| 年度の切り替わり | `data/tax-calendar.json` と暦 | 本文に「令和 N 年」「20XX 年分」「〜年 4 月 1 日以後」を含む記事 |
| 検索の反応の低下 | 週次の GSC 取り込み（表示・順位の 4 週比較） | 記事 URL |

週 1 回（既存の週次取り込みの後）に `data/freshness/candidates.json` を作り、管理画面の一覧と週次レポートに「更新候補」として出す。1 記事につき「理由」「該当箇所（見出し・行）」「優先度（表示回数 × 理由の重さ）」。

### 2. 更新の実行（承認つき）

- 管理画面の更新候補から「更新する」を選ぶと、既存の**部分再生成**で該当の節だけ書き直した下書きを作る（出典の最新版を渡す）。通常の下書きと同じ承認・公開の流れに乗せる。
- 公開時に `updated_at` を更新し、`dateModified` と sitemap の `lastmod` に反映。ページには「最終更新: YYYY-MM-DD」を表示。
- 「確認したが変更なし」の場合は `reviewed_at` だけ更新し、ページには「内容を確認: YYYY-MM-DD」と表示。`dateModified` は動かさない。【要判断】この表示を出すか。

### 3. 年度の一括切り替え（年 1 回）

- 12 月〜1 月に、「令和 N 年分」「N 年 4 月 1 日以後」を含む記事を一覧化し、記述が翌年も正しいものと、書き換えが要るものに分ける（判定は LLM に下書きさせ、毛利さんが確認）。
- 書き換えが要るものは 2 の流れで更新。数が多いときは物販・3 分野・表示の多い順。

## 段階

| 段階 | 内容 | 目安 |
|---|---|---|
| P1 | 検知の集約と更新候補の一覧（管理画面・週次レポート） | 指示書 1 本、Codex 1 回 |
| P2 | 更新候補からの部分再生成と `updated_at` / `reviewed_at` の扱い、ページ表示 | 指示書 1 本 |
| P3 | 年度の一括切り替えの支援（一覧と判定の下書き） | 12 月まで |

## 【要判断】

1. 「内容を確認: YYYY-MM-DD」の表示を出すか（更新日とは別に「確認日」を見せる）。
2. 更新候補の通知先（管理画面だけか、Chatwork にも週 1 回出すか）。
3. P1 を今の週次取り込みの PR に同乗させるか、別の PR にするか（同乗すると月曜の PR が大きくなる）。
4. 年度切り替えの判定を LLM に下書きさせることの可否（費用は 1 記事あたり数円〜十数円の見込み。【要確認】）。
