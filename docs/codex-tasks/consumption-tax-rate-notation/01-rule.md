# 01 — 消費税の税率表記のルールを足す

## A. どこに足すか

`scripts/lib/article-prompt-static.js` の `STATIC_RULES`（893行目から始まる長いテンプレート
リテラル）の中、

```
═══ 具体的数値・割合・金額を書くときのルール（重要・ハルシネーション防止）═══   ← 1084行目
```

のセクション内。**1144行目の【読者が使う数字だけを書く】ブロックの直後**、
**1155行目の【判断に迷うとき】の直前**に、新しい 【 】 見出しのブロックとして足す。

この位置にする理由は、新ルールが【読者が使う数字だけを書く】の具体例にあたるため。
隣り合わせに置くと、読み手（＝生成AI）が同じ理屈の適用だと理解しやすい。

**`CONDITIONAL_RULES`（224行目）には入れない。** 消費税の税額計算は卸・小売・飲食・
インボイスなど複数の論点で出るので、論点ごとの条件つきルールではなく全記事に効く
静的ルールにする。

## B. 何を書くか

次の内容を、既存ルールの書き方（❌ / ✓ の対比、理由の明示）に揃えて書く。
**以下は内容の指定であって、この文面をそのまま貼れという意味ではない。**

### B-1. 原則

消費税額を割り戻す式を本文に書くときは、**国税・地方税を合算した税率**を使う。

- 標準税率 → `× 10／110`
- 軽減税率 → `× 8／108`

❌ の例として次を挙げる（実際に生成された文面）:

```
❌「税込みの返還等の金額 × 7.8／110」
❌「軽減税率が適用される商品であれば6.24／108を用いる」
✓「税込みの返還等の金額 × 10／110」
✓「軽減税率が適用される商品であれば8／108を用いる」
```

### B-2. 理由

次を含める。

- 読者は消費税率を「10%（軽減は8%）」として認識している
- `7.8／110` は国税分だけを取り出す式で、計算自体は誤りではないが、読者の認識と一致しない
- 同じ記事で「標準税率10%」と書きながら式に `7.8` が出ると、読者は税率が違うと読み違える
- 国税7.8%・地方消費税2.2%という内訳は申告書の記入欄の話であって、読者が使う情報ではない
  （直前の【読者が使う数字だけを書く】と同じ理屈であることに触れてよい）

### B-3. 内訳を本文に書かない

`10／110` と書いたうえで「うち国税は7.8%」のような内訳を括弧書きで足すことも**しない**。
内訳を書くと結局どの数字を使うのか分からなくなる、という点まで書くこと。

### B-4. 「100分の78」を本文に書かない

`消費税額等 × 100分の78`（合計額から国税分を取り出す係数）も本文に書かない。

理由として、**`10／110` は合計額を出す式、`100分の78` は合計額から国税分を取り出す式で
計算の階層が違い、並べると読者が何を控除するのか分からなくなる**ことを明示する。

適格返還請求書・適格請求書に記載された税額を使う方法（積上げ計算）に触れる場合の書き方も
指定する。

```
❌「税込金額に7.8／110を乗じる代わりに、請求書記載の消費税額等に100分の78を乗じた金額」
✓「税込金額から割り戻す代わりに、請求書に記載した消費税額等を積み上げた金額」
```

## C. 触ってはいけないもの

### C-1. L1 の「消費税率 10%（軽減 8%）」（1088行目）

```
【L1：一般常識レベル — 出典なしでも書いてよい】
- 消費税率 10%（軽減 8%）
```

これは**どの数値が出典なしで書けるか**の話で、新ルールと矛盾しない（むしろ整合する）。
消さない・変えない。

### C-2. 【読者が使う数字だけを書く】（1144行目）

削除・改変しない。新ルールはこの直後に**足す**。

### C-3. 簡易課税のみなし仕入率（1095〜1111行目）

90/80/70/60/50/40% は事業区分ごとのみなし仕入率で、税率の話ではない。一切触らない。

### C-4. 税務シミュレーター

`assets/js/` や `scripts/` 配下のシミュレーター計算ロジックは**一切変更しない**。
申告書ベースの計算は国税分と地方消費税分を分けるのが正しいので、内部計算に
このルールを持ち込むと計算結果が壊れる。今回変えるのは**記事本文の表記だけ**。

## D. テスト

このファイルはプロンプトの文字列なので、検証できるのは「ルールが組み立て後のプロンプトに
入っていること」まで。

`scripts/lib/__tests__/` に新規テスト `test-consumption-tax-rate-notation.js` を足す。
既存テストと同じ形（自前の `assert` カウンタ、最後に `PASS / FAIL`）にする。

確認する内容:

- 組み立て後のプロンプト文字列に新ルールの見出しが含まれること
- `10／110` と `8／108` の両方が含まれること（✓ の例が落ちていないこと）
- `7.8／110` と `6.24／108` の両方が含まれること（❌ の例として残っていること）
- `100分の78` に触れた記述が含まれること
- 既存の【読者が使う数字だけを書く】ブロックが**消えていない**こと
- L1 の「消費税率 10%（軽減 8%）」が**残っている**こと

プロンプトの組み立て関数の名前は `article-prompt-builder.js` を読んで確認すること。
`test-law-citation-rule.js`（直近に同じ形で作ったテスト）が参考になる。

**注意:** 全角スラッシュ `／` と半角 `/` を取り違えないこと。既存ルールの表記に合わせる。
