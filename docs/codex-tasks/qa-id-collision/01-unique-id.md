# 01 ファイル名が衝突しないようにする

対象は `scripts/crawl-nta-qa.js`。

## A. 衝突しない id を作る

いまは分割した各部の `qNo` を半角に揃えてファイル名にしている。
全角と半角が同じ名前になるのが原因。

### 満たすこと

1. **同じ実行の中で、別の問が同じ id にならない**
2. **実行のたびに id が変わらない。** pdftotext の読み順は実行ごとに変わるので、
   「先に出てきたほうが素の名前」のような順序に依存する決め方はしないこと
3. **いまある半角の id は変えない。** `jirei-4`（問4 販売奨励金）はそのまま。
   変えると差分が無駄に大きくなり、レビューできなくなる
4. ファイル名は ASCII だけにすること。`jirei-４.json` のような全角混じりは、
   `jirei-4.json` と見分けがつかず事故のもとになる

### 推奨する決め方

**全角で書かれた問番号に印を付ける。** 全角か半角かは PDF の組版で決まっていて、
取得のたびに変わらないので、順序に依存しない安定した区別になる。

```
問4  → jirei-4     （半角。いまと同じ）
問４ → jirei-4w    （全角。w は wide の印）
```

印の文字は任せる。上の4条件を満たし、コメントで**なぜその印なのか**が
分かるようにしてあれば形は問わない。

> 「全角＝飲食料品の範囲の節」という対応は、たまたま今の PDF がそうなっているだけ。
> 節を読み取って `jirei-1-4` のようにする案も考えたが、節見出しを正規表現で
> 拾うのは壊れやすいので採らない。**組版の事実をそのまま印にする**のが素直。

### 全角と半角が混ざらない資料では

暗号資産（`splitByNumberedHeading`）と相続（`splitByParenQuestion`）では
いま衝突は起きていない。**それらの id が変わらないこと**を確かめること。

### それでも衝突したら

将来、全角・半角以外の理由で衝突することがありうる。
そのときは**黙って上書きしない**こと。警告を出し、後から来たほうに
安定した印（例: 表題のハッシュの先頭数文字）を付けて両方残す。

```
[warn] ファイル名が衝突しました: jirei-12
       問12 ○○○ / 問12 △△△
       後者を jirei-12-a3f2 として保存します
```

## B. index に同じファイルを指すエントリを2つ作らない

いま `saved` には、書き込んだものも**見送ったもの**も積まれる。
同じファイルに対して「書き込み」と「見送り」が両方起きると、index に2件入る。

A で id が一意になればこの経路は塞がるが、**index を作るときにも念のため
同じ `file_path` が二重に入らないようにすること**。

同じ `file_path` が2回来たら、後から来たほうは捨て、警告を出す。

## 期待する挙動

```
splitByQuestion が「問４ 家畜の飼料」と「問4 販売奨励金」を返す
  → jirei-4w.json と jirei-4.json の2ファイルになる
  → index も2件で、それぞれ自分のファイルを指す

同じ PDF を読み順を変えて2回処理する
  → できる id の集合が同じ（順序に依存しない）

暗号資産・相続の資料
  → id が従来どおり
```

## 取り直し後に確認すること（Claude 側で実施）

```
index の件数 = ファイルの件数
index に重複 id が無い
index の各エントリの title が、指すファイルの title と一致する
消えていた4件が入る
  問１「軽減税率制度」の概要
  問３ 水産物の販売
  問４ 家畜の飼料、ペットフードの販売
  問８ 水の販売
```
