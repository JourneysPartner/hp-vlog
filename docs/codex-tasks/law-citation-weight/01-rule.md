# 01 — 条番号の書き方のルールを足す

## A. どこに足すか

`scripts/lib/article-prompt-static.js` の `STATIC_RULES`（893行目から始まる長いテンプレートリテラル）の中、

```
═══ 出典・根拠の引用ルール ═══     ← 1061行目
```

のセクションの末尾（1065行目の次、1066行目の空行のあたり）に、新しい 【 】 見出しのブロックとして足す。

**`CONDITIONAL_RULES`（224行目）には入れない。** 条番号は相続・消費税・所得税のどの記事にも出るので、論点ごとの条件つきルールではなく全記事に効く静的ルールにする。

## B. 何を書くか

次の内容を、既存ルールの書き方（❌ / ✓ の対比、理由の明示）に揃えて書く。**以下は内容の指定であって、この文面をそのまま貼れという意味ではない。** 既存ルールの語り口に合わせて整えること。

### B-1. 原則

条番号（○○法第N条）は**原則として本文に書かない**。

理由として次を含める:

- 読者は個人事業主や相続の相談者であって、条文を参照して確認する人ではない
- 条文は「あなたが要件を正しく書くための材料」であって、読者が使う情報ではない
- 括弧書きで足すと文が重くなる（1127行目の【読者が使う数字だけを書く】と同じ理屈であることに触れてよい）

### B-2. 例外

**読者がその番号を第三者に示す場面があるときだけ**書いてよい。

- ✓ 相続放棄の期限（民法第915条）— 家族や専門家との話で読者が根拠として挙げうる
- ❌ 死亡届の届出先（戸籍法第86条第2項）— 窓口で条番号を言う場面は無い
- ❌ 火葬許可証の発行（墓地、埋葬等に関する法律第5条）— 同上
- ❌ 課税の根拠条文・特例の条番号 — 制度の建て付けであって読者は使わない

判断に迷ったら**書かない**側に倒す、と明示すること。

### B-3. 書く場合の表記

例外にあたって条番号を書くときは:

- **正式名称を使う。** 「措法」「所法」などの略称を本文で使わない
- **同じ条文を1記事内で二度書かない。** 初出の1回だけにする
- 条文が渡されていない番号は書かない（既存の捏造防止ガードのまま）

実際に「（租税特別措置法第40条）」と「（措法第40条）」が同じ記事に混在した例があるので、この2点は具体的に書くこと。

## C. 条文の添付は変えない

`scripts/lib/law-sources.js` は**一切変更しない**。

`buildLawProvisionBlock`（375行目付近）が出している次の文言も変えない。これは「ここに無い条番号を捏造するな」という意味であって、「条番号を書け」ではない。

```
═══ 法令の原文（条文はこれだけを根拠にする。ここに無い条番号を書かない）═══
```

新しいルールと矛盾して見えるかもしれないが、矛盾しない。**原文は今までどおり渡し、印字を減らすだけ。** 新ルールの文面でも、条文を渡されていることと本文に番号を書くことは別だと分かるようにしておくこと。

## D. 既存の優先順位の記述

1062行目に次がある。

```
優先順位: 1) 国税庁タックスアンサー（No.XXXX形式、必要な場合に優先参考） 2) 法令・通達（条文番号） 3) 国税庁公式ページ 4) 実務観点の整理
```

ここの「2) 法令・通達（条文番号）」は**根拠として何を優先するか**の話なので、消さない。新ルールと並んでも矛盾しない（根拠としては使う／本文には印字しない）。気になるなら「（条文番号）」の部分に、印字の要否は後述のルールに従う旨を一言添える程度にとどめる。

## E. テスト

このファイルはプロンプトの文字列なので、検証できるのは「ルールが組み立て後のプロンプトに入っていること」まで。

`scripts/lib/__tests__/` に新規テスト `test-law-citation-rule.js` を足す。既存テストと同じ形（自前の `assert` カウンタ、最後に `PASS / FAIL`）にする。

確認する内容:

- `STATIC_RULES`（または `buildArticlePrompt` 等の組み立て後の文字列）に新ルールの見出しが含まれること
- ルール本文に「民法第915条」（✓ の例）と「戸籍法第86条」（❌ の例）の両方が含まれること — 例示が落ちていないことの確認
- 既存の【読者が使う数字だけを書く】ブロックが**消えていない**こと
- `law-sources.js` の `buildLawProvisionBlock` が返す文字列に「ここに無い条番号を書かない」が**残っている**こと（C を壊していないことの確認）

プロンプトの組み立て関数の名前は `article-prompt-builder.js` を読んで確認すること。

## F. 回帰確認

```bash
node scripts/lib/__tests__/test-law-citation-rule.js
node scripts/validate.js
npm run build
git status --short
```

`scripts/lib/__tests__/` にプロンプト関連の既存テストがあれば実行する（`grep -l "STATIC_RULES\|article-prompt" scripts/lib/__tests__/*.js` で探せる）。

`npm run build` は `assets/js/tax-simulator-boot.js` を書き換えることがある。コミット前に `git checkout -- assets/js/tax-simulator-boot.js` で戻すこと。
