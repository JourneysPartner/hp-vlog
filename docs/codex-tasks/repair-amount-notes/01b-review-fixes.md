対象はコミット 5a60df6c（PR #742）。結果は Critical 0・High 0・Medium 1・Low 5。fail-open は無し。Medium 1 件だけを直す（毛利の決定 2026-11-05）。

## F1（Medium）同じ文に 食い違い／期限の書き漏れ が 2 件以上あると、正しい修正も必ず却下される

- 場所: `scripts/lib/fact-check.js` の `repairBody`、R3 の確かめ（1268〜1277 行あたり。許す数字 `allowedNumbers` を指摘 1 件ごとに作っている）。
- 起きること:
  - `repairBody` は、同じ文の指摘には同じ 1 つの置き換えを求める（違えば `同じ文の置き換えが一致しません`）。
  - 一方 R3 は、各指摘を「元の文・その指摘自身の correct・quote_notes・keep_numbers」だけで確かめる。
  - 例: 文「限度額は100万円、控除額は50万円です。」に c1（correct「限度額は200万円です。」）と c2（correct「控除額は60万円です。」）がある。まとめた正しい置き換え「限度額は200万円、控除額は60万円です。」は、c1 から見ると 60万円 が、c2 から見ると 200万円 が許す数字に無く、両方とも `根拠の正しい内容に無い数字を足しています` で却下される。作り直しでも同じ形しか返せないので、また却下される。main では採られていた修正。
- 直し方:
  - 許す数字を、**同じ `f.sentence` を持つ 食い違い・期限の書き漏れ の指摘全部**の、元の文・`correct`・`quote_notes`・`keep_numbers`（corrections の欄。元は `supported_numbers`）に `expandYearDates(normalizedNumbers(text), text)` をかけた数字の和にする。
  - 和を取る範囲は、その回の `repairBody` に渡った `findings` の中だけ（作り直しの呼び出しでは、作り直す指摘だけ）。広げない。
  - 資料なし の指摘（同じ文でも）の correct などは許す数字に入れない。
  - 別の文の指摘の数字は入れない。
  - `quote` の数字は今までどおり入れない。
  - 読めない数字（null）の扱い（置き換え文に null があり、元の文に無ければ却下）は変えない。
  - reason の文字列・`retryReasons`・他の確かめの並びは変えない。

### 新しい試験（`scripts/lib/__tests__/test-fact-repair-notes.js` に足す。グループ名は `R3`）

偽の AI で、通信なしで動くこと。enhanced 偽・真の両方で流すもの（a〜c）は、既存の R3 の試験と同じく `options`・`enhanced` を使う。

- a. **同じ文の 食い違い 2 件**（上の c1・c2 の形）で、修正 AI が両方に同じ「まとめた正しい置き換え」を返すと採られる。作り直しは呼ばれない（呼ばれた task が `repair` だけ）。却下 0、本文がまとめた置き換えになる。
- b. **同じ文の 食い違い ＋ 期限の書き漏れ**: 元の文例「限度額は100万円で、申請できます。」、c1（食い違い、correct `限度額は200万円です。`）、c2（期限の書き漏れ、correct `申請期限は令和9年3月31日です。`）。両方の内容を入れた置き換え（例「限度額は200万円で、令和9年3月31日まで申請できます。」）が採られる。
- c. **どの指摘にも無い数字は引き続き却下**: a の形で、置き換えに c1・c2・元の文のどれにも無い数字（例 `控除額は70万円`）を入れると、c1・c2 とも `根拠の正しい内容に無い数字を足しています` で、本文は変わらない。b の形で別の年（例 令和8年3月31日）を入れた場合も同じ。
- d. **別の文の指摘の数字は許さない**: a の 2 件に加えて別の文に c3（食い違い、correct `別の限度額は90万円です。`）がある。c1・c2 の文の置き換えに 90万円 を入れると（例「限度額は200万円、控除額は90万円です。」）、c1・c2 とも R3 の理由で却下される。c3 の置き換え `別の限度額は90万円です。` は採られる。
- e. **資料なし の指摘は和に入れない**: 同じ文に c1（食い違い、correct `限度額は200万円です。`）と c2（資料なし、claim `控除額は50万円`、correct に `控除額は70万円です。` を入れた偽の値）。置き換え「限度額は200万円、控除額は70万円です。」で、c1 の理由が `根拠の正しい内容に無い数字を足しています`、本文は変わらない。

## 記録だけするもの（直さない。PR 本文にも書く）

レビューの Low 5 件。どれも落とす側に倒れるか、main より悪くなっていない。

1. 日付の細かさが correct と違うと、正しい期限の追記も却下される（correct「令和9年12月31日」に対する「令和9年末まで」「令和9年分まで」、年月だけ、和暦と西暦の換算なし）。`expandYearDates` は年だけの日付を同じ文の年月日へ広げるが、逆向きには広げない。
2. 元の文に読めない数字があると、R3 が何も確かめなくなる（`normalizedNumbers` が文全体を `[null]` で返す）。最後の歯止めは再照合。
3. 禁止表現 `常見`（no-jouken）が「通常見込まれる」「日常見かける」「異常見られず」にも当たる。公開済み記事で当たるものは 0 件。案は前に付く字を除く `(?<![日通非異正尋])常見`。
4. R4 が候補外の資料を引くと、正しい金額が外れて照合が ok で終わることがある（実 AI run 41823394189 で起きた。誤った文は承認されないので fail-open ではない）。
5. 注の拾い方の限界: 句点なしで続く注（例 No.1120「（2）10万円 （注）…」）は拾えない。300 字を超える注は資料表で読点ごとに切られ、最初の断片しか渡らない。

範囲外の既存の弱点（別の作業の候補）: 置き換えが採られたのに再照合で解決しなかった場合、`checkFacts` は本文を元に戻さない（1590 行あたり）。#741 で誤った文が下書きに残った理由。
