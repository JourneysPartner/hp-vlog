# 照合の自動修正で「条件付きの別の額」が落ちる問題（2026-11-04）

## 何が起きたか

2026-11-04 の日次記事（PR #741「せどりの確定申告は雑所得？」）の本文に、照合（fact-check）の自動修正が次の文を書き込んだ。

> 事業所得にして青色申告をする場合、簡易な記帳でもよいとされていますが、最高55万円（令和元年以前は最高65万円）の青色申告特別控除を受けるには、…

正しくは「最高55万円。さらに e-Tax で申告するか優良な電子帳簿で保存していれば最高65万円」。現在も 65 万円の控除はあるのに、「65万円は令和元年以前の話」と読める。毛利が「電子申告をした場合の控除額が抜けている」と指摘した。

## 原因（照合記録 data/fact-check/reselling-income-tax-classification.json で確認）

1. **判定（judgeClaims）**: 元の文「青色申告をする場合は、複式簿記での記帳と…添付が前提です」を、No.2070 を根拠に正しく「食い違い」と判定した。根拠の抜粋（quote）は No.2070 の「…最高55万円（令和元年以前は最高65万円）を控除することとされています。」で終わっている。原文ではすぐ次の文が「（注1）令和2年分以後の…電子帳簿保存またはe-Taxによる電子申告を行っている場合は、最高65万円の青色申告特別控除が受けられます。」だが、basis の文の数の上限（金額は連続2文・要件は4文）のため抜粋に入らない。correct は「最高55万円（65万円）の青色申告特別控除を受けるための要件です」とあいまいだった。
2. **修正（repairBody）**: 修正の AI には correct と quote（注の手前で切れた抜粋）だけが渡る。AI は quote の言い回し「（令和元年以前は最高65万円）」をそのまま写した。置き換え文の数字を確かめる仕組みは「資料なし」の修正にしか無く、食い違いの修正では、correct にも元の文にも無い年分（令和元年）を足しても通る。
3. **再照合**: 新しい文を主張に分けて判定するので、「最高55万円となる」「令和元年以前は最高65万円だった」はどちらも原文にあり「裏付けあり」。条件付きの別の上限（e-Tax なら 65 万円）を書いていないことは、どの規則でも食い違いにならない（期限の書き漏れと、適用時期による段階の書き漏れの規則はあるが、条件による別の額の規則は無い）。

照合の記録は「残った食い違い 1」で承認を止めていた（安全側には働いた）が、誤った文は下書きの本文に残り、人が読んで初めて気づいた。

## 方針

- 制度ごとの手当て（「青色申告特別控除は 65 万円」と規則や資料に足す）はしない。過去に毛利が「別論点でも再発しないように。単純に関係法令を入れればいいわけではない」と決めている。直すのは仕組み（抜粋・修正の確かめ・判定の規則）だけ。
- 落とす側に倒す。新しい確かめで修正が採れないときは、今と同じく元の文を残して承認を止める。
- 照合の方針「案 2」（止めて置き換えるのは数字の事実の資料なしと食い違いだけ、要件・判定・手続の資料なしは人が確かめる箇所）は変えない。

## 同時に入れる言葉の決まり（2026-11-04 毛利指示）

- 「手がかり」は使わない（「一つの手がかり」→「一つのポイント」）。
- 「常見です」は使わない（→「よくあります」）。

data/banned-phrases.json に足す。書く時点の指示（formatForPrompt）・書いた後の置換（sanitizeBannedPhrases）・照合の修正で新しく入れない確かめ（runFactCheckForArticle の validateRepair）の 3 か所に自動で効く。公開済みの記事は変えない。
