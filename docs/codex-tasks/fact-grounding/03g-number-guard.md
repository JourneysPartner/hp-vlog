# 03g 数字の歯止めを締め直す（2026-10-12、Claude の確認で見つかった穴）

## 何が問題か

03f の K1 で、数字の確認を「1 つの引用文」から「採用した根拠の原文（判定に渡した抜粋、最大 4,000 字）全体」に広げた。表の行や複数の数字を含む正しい記述が資料なしになるのを防ぐためだったが、次の穴ができた。

- 日付が「年・月・日」の別々の数として比べられる（`normalizedNumbers('令和9年3月31日')` は 9・3・31）。
- そのため、抜粋の先頭に基準日の行「令和8年4月1日現在法令等」があり、本文に「令和9年3月31日まで」とあれば、誤った主張「令和8年3月31日まで」でも 8・3・31 が全部「原文にある」ことになる。
- 判定の AI がこの誤りを「裏付けあり」と誤った場合に、最後の歯止め（`sufficientQuote`）が止められない。照合の中核の誤り（期限の年の取り違え）そのものなので、塞ぐ。

## M1 日付はひとかたまりで比べる

- 日付の表現を 1 つの値として読む:
  - 和暦: 元号＋年（＋月（＋日））。例「令和9年3月31日」「令和九年三月三十一日」→ 同じ 1 つの値（例 `日付:令和9-3-31`）。「令和元年」は 1 年。
  - 西暦: 4 桁の年＋年（＋月（＋日））。例「2027年3月31日」→ `日付:2027-3-31`。和暦と西暦の換算はしない（違う値として扱う＝落とす側）。
  - 年の無い「3月31日」「翌年3月15日」は `日付:-3-31` のように月日だけの値。
- 日付の一部になった数は、別の数としては数えない。日付以外の数（金額・割合・年数・歳・件数など）は今の読み方（G3・H1・H2）のまま。
- 主張側も根拠側も同じ読み方にする。
- テスト: 「令和九年三月三十一日」と「令和9年3月31日」は一致。「令和8年3月31日」と「令和9年3月31日」は不一致。「令和8年4月1日現在」と「令和9年3月31日」が同じ抜粋にあっても、主張「令和8年3月31日」は一致しない。「2027年3月31日」と「令和9年3月31日」は不一致（換算しない）。

## M2 数字は引用の近くにあることを求める

- K1 の「採用した根拠の原文のどこかにあればよい」を、「**引用（`quote`）が見つかった位置の前後 300 文字の範囲**（同じ抜粋の部分の中）にあればよい」に狭める。表の行や隣り合う文に分かれた数字は拾え、離れた基準日の行や別の制度の数字は拾わない。
- 引用が根拠の原文に実在すること・15 文字以上（または 1 文全体）であることは従来どおり。
- テスト: 1,000万円 と 300万円 が隣り合う文にある（引用は片方の文）→ 裏付けあり。主張の数字が引用から 300 文字より離れた所にしか無い → 資料なし。

## 変更してはいけないもの

- 03f の K2〜K7、案 2 の止める範囲・置き換える範囲、承認の差し止めの 3 経路、fail-closed、`record.error`。
- H1（要約の数字が文にもあること）、H2（割合の読み方）。G3 の「一定」「一般」を数と読まない規則と万・億の合成。
- 既存テストの期待は、日付の読み方の変更で変わるもの（`normalizedNumbers` の出力の形）だけを最小限に直し、最終報告に書く。
