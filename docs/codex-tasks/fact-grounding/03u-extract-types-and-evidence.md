# 03u 抜き出しの種類の名前・年だけの日付・候補の外の資料（安いモデルが主張を捨てる・正しい資料を却下される原因）

## 背景（2026-10-20、毛利さん「案 2 の前に、GLM が多くの主張を捨てる原因をまず突き止める方が良い」）

03t のコードで安いモデル（GLM-5.3 Flash・DeepSeek（1017）・Gemini 3.8 Flash）に照合させた結果（`backlog.md` の「03t のコードでの安いモデルの再試験と案 2 の試算」）、GLM は #644 で 26 件・#680 で 19 件、DeepSeek は #644 で 42 件の主張を抜き出しで捨て、判定では「資料の番号がこの主張の候補でない」で答えを落とされていた（Gemini 11・GLM 7・DeepSeek 5、Opus 0）。抜き出しだけを GLM でやり直す道具（`%TEMP%\hpstatus\ds-test\diag-extract.js`）と、落とした答え（`rejected_answer`）で調べると、**多くはモデルの力ではなく、こちらの指示文と確かめ方が原因**だった。

### U1 抜き出しの種類の名前（捨てた主張の大半）

- 抜き出しの指示文（`extractClaims`）は「要件（対象・条件）・金額・割合・期限（保存期間を含む）・適用年・手続（届出・申請・選択）・番号（条文・通達・タックスアンサー）・判定を対象にします。…type は上記8種類のいずれか」。GLM・DeepSeek はかっこの中の説明を種類の名前として **`"type":"対象・条件"`・`"条件"`** と返す（03t の照合の生の答えで、DeepSeek #644 は 27 回以上、GLM #644 は 20 回）。種類は `TYPES` の 8 語でしか受け付けないので「主張の形式が不正」で捨てる（GLM の抜き出しのやり直しで #644 は 13 件中 12 件、#680 は 9 件すべて）。回ごとに揺れる（同じ DeepSeek でも別の回は「要件」と書き 0 件）。Gemini・Opus はほぼ「要件」と書く。
- **捨てた主張は要件そのもの**で、#644 の既知の誤り「贈与者60歳以上、受贈者18歳以上の直系卑属」（正しくは「直系卑属である推定相続人または孫」）も捨てられ、判定に届いていなかった。03t の比較で「GLM が受贈者の要件を素通りさせた」主因。

### U2 年だけの日付が本文の年月日と一致しない（抜き出し）

- 要約「令和6年以降の贈与から年110万円の基礎控除が新設」の数字は `日付:令和6`、本文の文「令和6年1月1日以降の贈与からは、年間110万円の基礎控除が…」は `日付:令和6-1-1`。抜き出しで主張を本文の文に結びつける所（`extractClaims` の `contains`）が数字の完全一致を求めるため、「本文に見つからない」で捨てる。判定の確かめでは 03o の O4 で年だけの日付を引用の文の中の同じ年の年月日と一致させているが、抜き出しには入っていない。

### U3 判定で、候補の外の正しい資料を却下する

- 判定の資料表（`judgeClaims` の `pages`）には同じ組の全主張の候補のページが並ぶ。安いモデルは、その主張の候補（`evidence_ids`）に無いが**同じ資料表にある、よりふさわしいページ**を根拠に挙げることがあり、`pages.find(p => p.number === evidenceNo && candidates.some(...))` で「資料の番号がこの主張の候補でない」として落とされる。
- 例（03t の記録）: #680 の「年110万円以内なら申告は通常不要」7 件で、Gemini は TA 4402（贈与税がかかる場合）を根拠にした。この主張の候補は 4429・4103・4408・措法70の3の2 で、4402 は入っていない（別の主張の候補として資料表にあった）。一人親方の「納税義務の判定は基準期間の課税売上高」で GLM は TA 6501（納税義務の免除）を挙げた。どちらも内容として正しい根拠。
- Opus は指示文の「各主張の evidence_ids の資料だけを根拠にしてください」を守るので、同じ場面では「資料なし」と答えていると見られる（#680 の Opus は資料なし 19・人が確かめる 30）。

## U1 抜き出しの種類の名前をはっきりさせ、よくある言い換えを受け付ける

- 抜き出しの指示文の種類の説明を、**種類の名前と説明を分けた形**にする。例: 「type は次の8語のどれか1語をそのまま書いてください: 要件・金額・割合・期限・適用年・手続・番号・判定。（要件＝対象・条件、期限＝保存期間を含む、手続＝届出・申請・選択、番号＝条文・通達・タックスアンサー）」。それ以外の指示（漏れなく・s・subject・claim 60 字・設例・期限の書き漏れ・番号だけの引用・形）は変えない。
- 受け取った `type` が 8 語に無いとき、次の言い換えだけを読み替える（前後の空白・全角半角はそろえてから）: `対象・条件`・`対象`・`条件`・`対象者`・`要件・条件` → 要件／`保存期間` → 期限／`届出`・`申請`・`選択`・`届出・申請・選択` → 手続／`条文`・`通達`・`タックスアンサー`・`条文・通達・タックスアンサー` → 番号／`税率` → 割合。これ以外は今どおり「主張の形式が不正」で捨てる。読み替えた主張は行に `type_label`（元の名前）を残す。

## U2 抜き出しで、年だけの日付を本文の文の同じ年の年月日と一致させる

- `extractClaims` で主張を本文の文に結びつける所（数字の主張の `contains`）で、要約の年だけの日付（`日付:令和6`・`日付:2026` のように月が無いもの）は、**その文の中**に同じ元号・同じ年の年月日（`日付:令和6-` で始まるもの）があれば含まれるとみなす。和暦と西暦の換算はしない。基準日の行（`…現在` の日付）は数えない（O4 と同じ）。
- 前後 2 文の中から探す所（`near.filter(contains)`）にも同じ読み方を使う。

## U3 判定で、同じ資料表の候補の外のページも根拠に認める

- 判定の答えの `evidence_id` が、その主張の候補に無くても、**その呼び出しで判定に見せた資料表のページ（`pages`）にあれば**認める。引用の範囲（`basis`）・引用の実在・長さ・数字の確かめ（`sufficientQuote`・`quoteSupportsNumbers`）・数字の主張の範囲 2 文まで、などは今と同じものを、そのページにかける。
- その場合、主張の行の候補（`evidence`）の末尾にそのページの資料を足し（差分照合の使い回し `validRefs`・レビュー画面・公開済みの一括照合が今の形で読めるように）、行に `evidence_outside_candidates: true` を残す。
- 資料表に無い番号は今どおり「資料の番号がこの主張の候補でない」で落とす（文言は変えない）。
- 判定の指示文の「各主張の evidence_ids の資料だけを根拠にしてください」を、「各主張の evidence_ids の資料を優先して根拠にしてください。evidence_ids の資料に根拠が無く、この資料表の別の資料に根拠があるときは、その資料の番号を evidence_id に書いてかまいません」に替える（ほかの文言は変えない）。
