# 03l 本番初稼働（#680）で見えた照合の誤り 2 件と、main で落ちる試験 2 本（2026-10-17）

照合（03i〜03k）は 10/16 の日次生成で本番に初めて動いた。#680（生前贈与の現金のやり方、`data/fact-check/gift-cash-procedure-tax-return.json`）で、正しい記述を消す誤りが 2 種見つかった（`backlog.md` の B7・B8）。あわせて、#677（法令カタログ更新）・#684（通達の取り込み）の後から main で 2 本の試験が落ちている。原因は Claude が切り分け済み（下記）。

## L1（B8 の主因）「パーセント」を「%」と同じ割合として読む

**起きたこと**: 記事「…特定贈与者ごとに累計2,500万円までの特別控除があり、超えた部分には一律20%の税率がかかります。」の主張 c15（割合「一律20%」）が、判定では No.4103 を根拠にしたのに、機械の確認で「引用が短い・数字が引用の近くに無い」として資料なしにされた。No.4103 の原文は「一律20パーセントの税率」。

**原因**: `normalizedNumbers`（`scripts/lib/fact-check.js` 111 行あたり）は数の直後が `%` のときだけ割合として読む。「20%」は `割合:1/5`、「20パーセント」は `20` になり一致しない。国税庁のページ（taxanswer・shitsugi）のうち 199 件が「パーセント」表記（「%」は 92 件）なので、税率・割合の主張の多くが同じ理由で落ちうる。

**直すこと**:

- 数の直後が「パーセント」のときも、`%` と同じ割合（`割合:1/5` など）として読む。全角・半角の違いは今の正規化に従う。
- `range`（範囲の指定）があるときの端の判定（`end` の計算）も、「パーセント」の長さで行う。範囲の端で「パーセント」が切れた場合は、今の `%` と同じく断片として扱う。
- 「2割」などの「割」の読み方は今回は変えない。

**試験**:

1. `normalizedNumbers('一律20パーセントの税率')` が `['割合:1/5']`、`'20パーセント相当額'` も同じ。`'100分の20'`・`'20%'`・`'２０％'` は今のまま `割合:1/5`。
2. #680 の再現: 主張 `{type:'割合', claim:'特別控除を超えた部分には一律20%の税率がかかる', sentence: 上の記事の文}` と、引用に No.4103 の実データ（`data/nta-sources/` の 4103 の本文）の「…一律20パーセントの税率を乗じて算出します。」を含む文を渡すと、`sufficientQuote` が真になる。
3. 範囲を指定した `normalizedNumbers` で、「パーセント」の途中で範囲が切れたら、その数を採らない（今の `%` の扱いと同じ結果）。

## L2（B8 の二次被害）具体を外す修正で、同じ文の裏付けのある数字を消さない

**起きたこと**: 同じ文に主張が 2 件あった。c3（金額「年110万円の基礎控除とは別に…累計2,500万円の特別控除」）は裏付けあり、c15（割合 20%）は L1 の不具合で資料なし。修正の AI には c15 だけが渡され、「資料が無い具体的な…を外し、案内に置き換える」の指示で文全体を「この制度を選んだ場合の控除額や…詳しくは国税庁の『相続時精算課税の選択』のページで確認してください。」に置き換えた。裏付けのある 110万円・2,500万円も一緒に消え、続く「ただし、特定贈与者が亡くなったときは…」が前の文とつながらなくなった。

**直すこと**（資料なしの修正＝具体を外す修正だけが対象。食い違い・期限の書き漏れの修正は今のまま）:

- `repairBody` に渡す各修正に、同じ文の裏付けありの主張を `keep: [{type, subject, claim}]` として付ける（`checkFacts` の 794 行あたりで `record.claims` から同じ `sentence` の `status === '裏付けあり'` を集める）。
- 資料なしの修正の指示文（`repairInstructions` の最後の分岐）に「keep にある裏付けのある内容（数字を含む）は残し、資料が無い部分だけを外す」趣旨を足す。他の指示文は変えない。
- 機械の確認を足す: keep の主張の要約（`claim`）の数字のうち元の文にある数字が、置き換え後の文に全部残っていなければ、その置き換えを採らない（理由「裏付けのある数字を消しています」）。採らない場合の扱いは今の却下と同じ（同じ文の他の指摘も採らない・未解決として承認を止める）。
- 外すべき数字と keep の数字が同じ値のときは、keep を優先する（その数字が残っていても却下しない。再照合が判断する）。

**試験**:

1. #680 の再現: c3（裏付けあり、110万円・2,500万円）と c15（資料なし、20%）が同じ文。偽の修正 AI が文全体を案内に置き換えると却下され、未解決として承認が止まる。110万円・2,500万円を残して 20% の部分だけを外した置き換えは採られる。
2. 修正の AI に渡る `corrections` の c15 に `keep` があり、c3 の要約が入っている。keep が空の文（同じ文に裏付けありが無い）は今の動きと同じ。
3. 食い違いの修正（同じ文に裏付けありの数字がある場合）は今の動きと同じ（keep の確認を掛けない）。

## L3（B7）太字の中の句点で文を切らない

**起きたこと**: #680 の本文

```
1. <strong>その年の受け取りの合計は110万円以内か。</strong> 以内なら、通常は申告不要です。
```

が `<strong>…以内か。` と `</strong> 以内なら、通常は申告不要です。` に切れ、後ろの切れ端が主張になった（c51「その年の受取合計が110万円以内なら通常は申告不要」）。切れ端には 110万円が無いので、要約の数字が文に無いとして資料なしになり、人が確かめる箇所に回った。公開済みの記事にも `<strong>…。</strong>` が約 58 か所、`**…。**` が約 52 か所ある。

**直すこと**:

- `splitUnits`（`scripts/lib/fact-units.js`）で、同じ行の中で閉じている強調（`<strong>…</strong>`・`<b>…</b>`・`<em>…</em>`。属性つきの開きタグも含む。Markdown の `**…**`）を括弧と同じに扱い、その中の「。」では文を切らない。強調の後の「。」では今までどおり切る。
  - 例: `<strong>A。</strong>B。C。` は `<strong>A。</strong>B。` と `C。` の 2 文。
  - 同じ行で閉じていない強調は、今までどおり（強調として扱わない）。
- `material: true`（資料の分割）でも同じ規則でよい（国税庁・法令の原文にはタグが無いので結果は変わらない見込み。変わる場合は報告）。
- 文の区切りが変わるので、`LOGIC_VERSION` を `'03l'` にする（前回の記録を差分照合で使い回さない）。

**試験**:

1. #680 の 189〜192 行の 4 行が、それぞれ 1 文になる（例: `1. <strong>その年の受け取りの合計は110万円以内か。</strong> 以内なら、通常は申告不要です。`）。
2. `<strong>A。</strong>B。C。`・`<strong class="x">A。</strong>B。`・`**A。**B。`・`<em>A。</em>B。` の区切り。閉じていない `<strong>A。B。` は今までどおり `<strong>A。` と `B。`。
3. 括弧の中の「。」で切らない今の動き、表の行、見出し、`material: true` の 300 字の分割が変わらない。
4. 太字を含む 1 文の修正（L2 を含む今の修正の流れ）で、置き換えが本文の正しい位置に入る。

## L4 `test-materials-bundle.js` の期待を今のカタログに合わせる

**原因**: 「01 R2 実データ10-05と4124、項指定でも条の全文」は「措令40の2 が未解決（カタログに無い）」を期待している。#677 で措令の相続税の特例（Chapter_3_2）がカタログに入り、措令40の2 は解決できるようになった（今は法令の予算で除外＝`dropped` に入る）。カタログが良くなった結果で、コードの不具合ではない。

## L5 `test-fact-pages.js` の T1（入力の量）の試験を、資料が増えても意味のある形にする

**原因**: 照合のコード（`fact-check.js`・`fact-evidence.js`・`fact-pages.js`）は 03k から変わっていない。#677・#684 で法令（措令の相続税の特例など）と措置法通達 4 種がカタログに入り、候補に載る資料が増えた。実測（偽の LLM、初回の入力の字数）:

|---|---|---|---|---|
| #642 | 83,483 | 91,973 | 90,000 | 64 → 70 |
| #643 | 36,386 | 41,550 | 45,000 | 10 → 14 |
| #644 | 104,978 | 128,251 | 110,000 | 46 → 53 |

#644 の増加の多くは、結婚・子育て（措令40の4の4）・住宅取得（措令40の4の2・40の5）など主張に関係する施行令（各 4,000〜6,200 字）で、04（主要税法を全条）の狙いどおりの資料。資料が増えるたびに上限の数字だけが外れる試験になっている。候補の数を減らして量を抑えるかは、精度との兼ね合いで別に判断する（`backlog.md` の B9。今回は候補の出し方を変えない）。

**直すこと**:

- 上限の数字を今の実測に合わせて更新する: #642 100,000・#643 45,000（今のまま）・#644 140,000。L3 で文の区切りが変わって実測が動いた場合は、その値で報告する（上限は実測の約 1.1 倍）。
- 上限とは別に、資料の量に左右されない形の確認を足す: 初回の判定の呼び出しで、固定部分（`staticSystem`）が「指示文＋例＋資料表（`pack.block`）」と一致し、可変部分（`dynamicSystem`・`user`）に資料表のどのページの本文も含まれないこと（同じ資料を 2 回送っていない）。
- `T1実測` の出力に、資料の種類別（国税庁のページ・法令・通達）のページ数と字数を足す（次に増えたときに原因がすぐ分かるように）。
