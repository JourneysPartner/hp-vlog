# 02 資料に無い要件・金額・期限を書かない規則

背景は `README.md` の原因 4。規則は出典本文ブロック（`scripts/lib/nta-source-body.js` の `buildSourceBodyBlock`）と、出典が未確定のときの指示（`generate-draft.js` の `sourceUnconfirmed` の文）に入っている。3 経路（新規・差し戻し・更新案）で同じ文が使われることを確かめる。

## R1 【厳守】4 を差し替える

今:

> 4. 本文に書かれていない論点に触れる必要がある場合は、出典を引かずに「一般に」「実務上」等の表現に留め、その旨が分かるように書く。

新:

> 4. 添付した資料（出典・補助出典・参考・法令・通達の原文）に書かれていない論点に触れる場合は、**制度の名前と「詳しくは国税庁の〇〇で確認」程度の案内まで**にする。その論点について、要件・対象者・金額・割合・期限・適用年・届出や申請の期限・条文や通達の番号・判定の基準を書いてはならない（「一般に」「実務上」と付けても書かない）。あなたの記憶にある税制は改正前の古いものである可能性が高い。

## R2 期限と時点の規則を足す（【厳守】7 として）

> 7. 添付資料に適用期限（「〜までの贈与」「〜までに拠出」等）がある制度を書くときは、その期限を必ず本文に書く。今日の日付（可変条件の冒頭）と比べ、期限を過ぎていれば「終了した制度（既に始めた分の扱いは資料のとおり）」として書き、1 年以内に期限が来るなら期限が近いことを明記する。資料の「令和〇年〇月〇日現在法令等」より後の改正は、添付された改正情報がある場合だけ書く。

## R3 法令ブロックの注意（01 R2 と同じ文）

01 R2 の「括弧書き・ただし書きは、その条の主語・対象に限って読む」注意は、法令の原文を添付するすべてのブロックに入れる。

## R4 既存の規則との整合

- `article-prompt-static.js` の【判断に迷うとき】「自分の記憶から書こうとしていると感じたら、その場で抽象化してよい」は、「抽象化する（具体的な要件・金額・期限は書かない）」に言い換える。
- 他のプロンプト文言は変えない。

## テスト（`test-materials-bundle.js` に追記するか、`test-writing-rules.js`）

1. 出典本文ブロックに新しい 4 と 7 が入り、古い 4 の文言が無い。
2. 出典が未確定の場合の指示にも、「要件・金額・期限を書かない」趣旨が入る。
3. 3 経路のプロンプト組み立てで同じ規則文が使われる（文字列の一致で確かめる）。

## 変更してはいけないもの

- 【厳守】1〜3・5・6 の文言、その他の生成プロンプト。
