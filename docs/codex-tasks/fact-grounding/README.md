2026-10-09、9/26〜27 生成の下書き 3 本（#642 アパレル在庫・#643 小規模宅地・#644 贈与税の非課税）を税務の観点でレビューしたところ、3 本とも「直してから承認」で、読者が損をする税務の誤りがそれぞれ 2〜3 点あった。毛利さんの指示（2026-10-09）: 「なぜその間違いが発生したかを調べて、今後その原因による間違いが再度発生しないようにして。別論点の記事であってもです。単純に今回の記事に関係する法令等を入れればいいわけではありません。」

## 原因（生成の記録 run 36203491584・36281420950 と実装から特定）

1. **選んだ資料を書き手に渡していない。** #644 では出典の自動選定が論点ごとに 4 ページ（住宅 4508・教育 4510・結婚子育て 4511・非課税財産 4405）を正しく選んだ。しかし本文を渡したのは主出典 4508 と、別経路の参考 1 件（No.4152「相続税の計算」）だけで、残り 3 ページは**題名だけ**だった（`generate-draft.js` の `supplementalSourceLabels`、`nta-source-body.js` の `buildSourceBodyBlock(…, { maxRefs: 1 })`）。結婚・子育て資金の期限は書き手の記憶で書かれた。
2. **主出典が論点に合っていないことを検出しない。** #642（棚卸資産の評価）の主出典は No.2210「必要経費の知識」で、棚卸資産の評価・評価損・低価法の記述が無い。それでも「出典あり」として生成が進み、中身はほぼ記憶で書かれた。公開済み 269 本のうち、No.1350（33 本）・No.6501（33 本）・No.2210（24 本）・No.2200（16 本）・No.4152（13 本）など、少数の汎用ページを主出典にしている記事が多い。
3. **法令は条文だけで、施行令・通達がつながらない。** #643 では質疑応答事例の関係法令から措法69の4 の条文だけを渡した。二世帯住宅の判定（措令40の2）と建替え（措通69の4-8）は渡しておらず、書き手は条文の括弧書きを読み違え、二世帯は古い取扱い（平成 26 年より前）を記憶で書いた。法令カタログは「相続の手続き」用に条を選んで収録したもので、措置法施行令は一部の条だけ（40の2 は無い）、所得税法・法人税法・消費税法とその施行令は無い。措置法関係通達も無い。
4. **資料に無い論点を記憶で書いてよい規則になっている。** 出典本文ブロックの規則 4 は「本文に書かれていない論点に触れる必要がある場合は…『一般に』『実務上』等の表現に留め」で、要件・金額・期限まで記憶で書くことを止めていない。書き手のモデルは `claude-sonnet-4-6`（GitHub の変数 `CONTENT_MODEL`）で、令和 7・8 年度改正より前の知識で書く。
5. **書いた後に、主張を資料と照合する工程が無い。** 生成後の自動の点検は、重複・禁止表現・長さ・通達番号と条番号の実在・あらかじめ登録した論点別ルールだけ。要件・金額・期限・判定基準が資料と合っているかは誰も確かめず、人のレビューに全部が乗っている。

1〜4 は「間違いが入る入口」で、どれだけ塞いでも新しい論点では別の穴が開く（毛利さんの「別論点でも」）。**5 が無いことが根本原因**で、ここを塞ぐのが本作業の中心。

## 方針

- **公開前の関門（中核）**: 生成したすべての記事（新規・差し戻し再生成・公開中の記事の更新案）について、要件・金額・割合・期限・適用年・届出・条文番号・判定基準を述べた文を抜き出す。それぞれを国税庁ページ・通達・法令の原文と照合し、「裏付けあり／食い違い／資料なし／期限の書き漏れ」を判定する。食い違いと期限の書き漏れは資料に合わせて直し、資料なしの具体的な数値・要件は一般的な案内に置き換える。それでも食い違いが残る記事、または照合が実施できなかった記事は**承認できない**（既存の品質ゲート `recommendation: "revise"` を使う）。
- **照合の根拠は記事ごとの手当てではなく、ローカルのカタログ全体から引く**（国税庁ページ 2,227 件・通達・法令）。生成時に渡した資料に限らない。
- **入口も塞ぐ**: 選んだ補助出典の本文を渡す。国税庁ページの「根拠法令・関係法令」欄から法令・施行令・通達を引いて渡す。主出典が汎用ページのときは論点語で補助出典を必ず探す。資料に無い要件・金額・期限は書かない規則にする。
- **カタログの穴を埋める**: 主要税法（所得税法・法人税法・消費税法とそれぞれの施行令、相続税法施行令）と措置法関係通達を加える（04）。
- **公開済みの記事にも同じ照合をかけられるようにする**（05。実行は毛利さんの判断）。

## 全段階共通の厳守事項

- `content/posts/*.md` を触らない（公開済み記事の修正は 05 の一覧を見て毛利さんが判断する）。
- 既存の選定・重複判定・品質ゲート・禁止表現・論点別ルール・通達番号と条番号の照合を弱めない。新しい関門は追加のみ。
- 照合は**落とす側に倒す**（判定できないものを「裏付けあり」にしない）。根拠の引用が資料の原文に無い判定は「資料なし」として扱う。
- 記事の主題・構成・文体を照合のついでに書き換えない（直すのは該当する文だけ）。既存の本文短縮ガードを守る。
- `fix/draft-supply` の変更（取り下げ記録・次の候補を試す）を壊さない。
- ネットワークは使えない。LLM 呼び出しはテストで偽の関数に置き換える。照合の根拠検索は実データ（`data/`）で試験する。
- 鍵・トークンをログやファイルに出さない。説明・コメント・最終報告は日本語。ファイルは LF。
