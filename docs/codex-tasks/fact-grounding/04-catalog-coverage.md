# 04 カタログの穴を埋める（条を選んで足す方式をやめ、主要税法を全条持つ）

背景は `README.md` の原因 3。これまでは事故のたびに、その記事に要る条を 1 条ずつ `articles` に足してきた（2026-09-10 措法61の4、09-14 農地の納税猶予）。毛利さんの指摘（「単純に今回の記事に関係する法令等を入れればいいわけではない」）どおり、この方式では新しい論点のたびに穴が開く。03 の照合の根拠にもなるので、**税務の主要法令は全条を持つ**。

- `sozokuzei`（相続税法）: 全条になっているか確かめ、なっていなければ全条にする。

## R2 通達カタログ（`scripts/crawl-nta-tsutatsu.js`・`scripts/lib/nta-tsutatsu.js`）

追加する通達:
- 財産評価基本通達（`hyoka`、略称「評基通」）
- 租税特別措置法関係通達（相続税・贈与税関係）（略称「措通」。条番号は「69の4-1」の形）
- 租税特別措置法関係通達（所得税関係・譲渡所得関係）（略称「措通」。所得税の特例）
- 租税特別措置法関係通達（法人税編）（略称「措通」。法人税の特例）

同じ略称「措通」が 3 つの通達で使われるので、番号から一意に決まらない場合は、記事の税目（`tax_domain`）で選ぶ。それでも決まらない場合は全部の候補を返す（照合は複数の根拠を見てよい）。

ページの構成は既存の基本通達と違うことがある。`fixtures/` に Claude が各通達の目次と本文の HTML を 1〜2 ページずつ置くので、それで解析を作って試験する。

## R3 大きさの確認

- 取り込み後の `data/law-sources/` と `data/nta-tsutatsu/` の合計サイズの見積もりを最終報告に書く（条数 × 平均文字数）。1 ファイルが 20MB を超える場合は、法令ごと・章ごとにファイルを分ける形にする【要確認】。
- 生成時に読み込む部分（`refsForTopic`・照合の根拠検索）は、全件を毎回メモリに展開しない作り（索引だけ先に読む）にする。

## R4 01・03 との接続

- 01 R2 の関係法令の連鎖と、03 R2 の根拠検索が、新しい法令・通達を使えること。
- 本文中の番号の照合（`checkCitations` と法令の条番号の照合）が新しい略称（所令・法令・消令・評基通・措通 など）を読むこと。既存の照合を弱めない（カタログに無い番号の警告は従来どおり）。

## テスト

1. 法令の定義: 追加 12 件の key・別名・`law_id` が `fixtures/law-ids.json` と一致。措置法・措置法施行令に `articles` の絞り込みが無い。
2. 通達の解析: `fixtures/` の HTML から、財産評価基本通達・措置法通達 3 種の条番号・見出し・本文が取れる。
3. 略称「措通」の解決: `tax_domain` で選ばれる。決まらなければ複数を返す。
4. 番号の照合: 「所令104条」「所基通47-22」「措通69の4-8」「評基通11」「法令68条」が新しい略称で照合される（データが無い状態ではカタログに無い警告になる＝従来どおり）。
5. 01 R2・03 R2 の部品が新しいカタログを読む（小さな偽カタログで）。

## 変更してはいけないもの

- 既存の法令（民法・戸籍法・不動産登記法等）と手続き機関のページの取り込み。
- 既存の通達（所基通・法基通・消基通・相基通）の解析結果。
