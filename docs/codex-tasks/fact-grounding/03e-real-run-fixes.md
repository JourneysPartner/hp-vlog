# 03e 実際の AI での受け入れ確認の結果を受けた修正（2026-10-12、毛利さん「案2」）

## 何が起きたか

2026-10-12、手動の照合ワークフロー（`fact-check.yml`、`repair=true`）で、実際の AI（`claude-opus-5-5`）を #642〜#644 の下書きにかけた（run 38216137550・38216145442・38216152901）。

| 下書き | 結果 | 中身 |
|---|---|---|
| #642 アパレル在庫 | revise | 主張 40 件中 資料なし 37・上限で未照合 11。32 文を「国税庁の案内で確認」に置き換え、記事が骨抜きになった。既知の誤り「届出がなければ売れ残り在庫を低く評価できない」は食い違いでなく資料なしとして削除された |
| #643 小規模宅地 | revise | 主張 25 件中 資料なし 14。二世帯住宅・措法69の4①の誤りも資料なし。**記事の主出典である質疑応答事例そのものが根拠の候補に入っていない**（根拠は TA 3307・4452・3306 等）。修正は本文の保全条件で破棄 |
| #644 贈与の非課税 | not_run | 主張の抜き出しの応答が JSON として読めない（`SyntaxError`）。`parseJson` は前後のコードフェンスしか外さず、12,000 トークンで切れた可能性もある |

安全側（3 本とも承認できない）には働いたが、既知の誤りを「食い違い＋正しい修正」で捉えたものは 0 件。このままでは毎日の下書きがほぼ全部承認できないか、骨抜きになる。

## 毛利さんの決定（2026-10-12、案 2）

**止めて置き換えるのは「数字の事実」だけ**にする。それ以外の「資料なし」は本文を変えず、レビュー画面に「人が確かめる箇所」として一覧で出す。

## E1 「資料なし」の扱い（案 2）

- 主張の種類を 2 つに分ける:
  - **数字の事実**: `金額`・`割合`・`期限`・`適用年`・`番号`
  - **それ以外**: `要件`・`判定`・`手続`
- 止める（`fact_check_blocking: true`・`status: revise`）のは次のときだけ:
  - `食い違い` または `期限の書き漏れ` が修正後も残った（種類を問わない。従来どおり）
  - **数字の事実**の `資料なし` が、具体を外す修正後も残った（従来どおり）
  - **数字の事実**の主張が上限（`FACT_CHECK_MAX_CLAIMS`）で照合されなかった、または本文に見つからず捨てられた
  - 照合を実施できなかった（`not_run`。`FACT_CHECK_FAIL_OPEN=true` のときだけ止めない。従来どおり）
- 修正（R4）で具体を外して案内に置き換えるのは、**数字の事実**の `資料なし` だけ。`要件`・`判定`・`手続` の `資料なし` は**本文を変えない**。
- `要件`・`判定`・`手続` の `資料なし`、それらの種類の上限超え・捨てた主張は、記録の新しい項目 `review_items`（人が確かめる箇所）に入れる。各項目に 文・見出し・種類・制度名・見た根拠の候補（id・題名・URL）を持たせる。これらは止めない。
- `食い違い` は種類を問わず従来どおり、根拠に合わせて該当文だけ直し、再照合で裏付けが得られなければ止める。
- 抜き出しの上限で落とす順番は、**数字の事実を先に残す**（`金額`・`期限`・`割合`・`適用年`・`番号`、次に `要件`・`判定`・`手続`）。
- 要約（`fact_check_summary`）に「人が確かめる箇所 N 件」を足す。

## E2 根拠の候補に、記事自身の資料を必ず入れる

- 主張ごとの根拠の候補（R2）に、従来の検索の上位 3 件に加えて、**その記事が生成時に渡された資料**を必ず入れる:
  - frontmatter の主出典（`source_url`）と補助出典（`source_supplements` があれば）、`source_bundle` に記録された原文（国税庁ページ・法令の条・通達）。カタログ（`data/nta-sources/`・`data/law-sources/`・`data/nta-tsutatsu/`）で引ける分だけ。
  - 照合導入前の下書き（`source_bundle` が無い）でも、`source_url` は必ず入れる。
- 記事自身の資料は、主張の語で抜粋（1 件 2,000 文字以内、既存の `contiguousExcerpt`）してから渡す。1 つの主張に渡す根拠は合計 6 件まで（記事自身の資料を優先し、重複は除く）。
- 判定の指示文は変えない（「判断できなければ資料なし」「記憶で補わない」等はそのまま）。
- 記事・論点ごとの語の対応（`fact-evidence.js` の `synonyms`・`focus` の手書きの対応）は**これ以上足さない**（README「条を選んで足す方式」と同じ理由）。

## E3 主張の抜き出しの応答を頑健に読む

- `parseJson` は、応答の中の最初の `[` から対応する最後の `]` までを取り出して読む（前置きの文・後ろの説明・コードフェンスがあっても読める）。
- 読めない場合（途中で切れた等）は、本文を見出し（`## `）の境目で 2 つに分けて、それぞれ 1 回ずつ抜き出しをやり直し、結果をつなぐ（id は振り直す）。それでも読めなければ `not_run`（理由は既存の `record.error` に `SyntaxError` 等の種類だけ）。
- 抜き出しの指示に「`claim` は 60 文字以内」を足す（出力を短くして切れにくくする）。これ以外の指示文は変えない。

## E4 レビュー画面

- 「事実の照合」欄に「人が確かめる箇所（資料が見つからなかった記述）」の一覧を足す（`review_items`。文・種類・見た根拠の候補へのリンク）。止める理由ではないこと（承認はできること）を一文で書く。既存の欄の並びは変えない。
- 承認の差し止めの判定（`fact_check_blocking`）とその 3 経路は変えない。

## テスト（`scripts/lib/__tests__/test-fact-real-run-fixes.js`）

1. E1: 偽の AI で、`判定` の資料なし 10 件＋`金額` の裏付けあり 2 件 → `ok`・本文不変・`review_items` 10 件・止めない。`期限` の資料なし 1 件（具体を外す修正が成功）→ 修正され `ok`。`期限` の資料なしが修正後も残る → `revise`。`判定` の食い違いが残る → `revise`。上限超えで `金額` が落ちた → `revise`、`判定` だけが落ちた → 止めず `review_items` に入る。数字の事実が先に残る順番。
2. E2: 実データで、#643 の下書き（`content/posts/2026-09-26-shitsugi-sozoku-10-05.md` を `git show origin/draft/2026-09-26-shitsugi-sozoku-10-05:content/posts/2026-09-26-shitsugi-sozoku-10-05.md` で読む。主出典は `https://www.nta.go.jp/law/shitsugi/sozoku/10/05.htm`。テストを CI でも動かすため、テスト本体は同じ frontmatter の偽記事を使い、git から読む確認は最終報告用に 1 回だけ行う）の主張で、主出典の質疑応答事例が根拠の候補に入る。`source_bundle` の法令の条が入る。合計 6 件まで・重複なし。
3. E3: 前置き・後書き・フェンス付きの応答が読める。途中で切れた応答 → 2 つに分けてやり直して読める。それでも読めない → `not_run`。
4. E4: `review_items` がある記録でレビュー画面に一覧が出る（HTML の文字列、エスケープ済み）。
5. 既存の F・G・H のテストと承認の差し止めの 3 経路のテストがそのまま通る（期待が変わるものは最小限に直し、最終報告に書く）。

## 変更してはいけないもの

- 承認の差し止め（`fact_check_blocking`）とその 3 経路、通知、`not_run` を止める既定（fail-closed）。
- 引用の照合（引用が原文に無い・短すぎる・数字が引用に無い判定は資料なし）、数字の照合（G3・H1・H2）。
- 判定・修正の指示文（E3 の「claim は 60 文字以内」の追加だけは可）。
- 2026-10-12 に Claude が足した `record.error`（鍵を伏せた診断）と、空の system ブロックを送らない修正。
- 新規生成の出典の決め方、生成後の重複判定・論点別ルール・番号の照合。`content/posts/*.md`、`data/` の既存の取り込み結果。
