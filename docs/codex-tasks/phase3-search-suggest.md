# 実装指示書: 検索サジェストからの記事候補づくり（段階3改）【着手待ち】

作成: 2026-08-26（設計: Claude ／ 実装: Codex）
状態: **段階1.5（LLM全件選別）の検収完了後に着手する。それまで実装しないこと。**

## 背景

当サイトはまだアクセスがほぼ無く、Search Console に貯まる自サイトの検索実測は
分母として機能しない。「世の中で何が検索されているか」を Google サジェスト
（検索窓に語を入れたとき補完される、実際に打ち込まれている続きの語）から取り、
記事候補の源泉にする。Search Console は「書いた記事が検索に載ったか」の
答え合わせ役として貯め続ける（本指示書の対象外）。

## 方針（要点のみ。詳細は着手時に確定）

1. **種語辞書**: 顧客カテゴリ×税務論点の組み合わせと、質疑応答・タックスアンサーの
   題名から種語を自動生成（例: 「個人事業主 消費税」「ハンドメイド 確定申告」）
2. **取得**: Google サジェストの補完候補を取得。非公式な入口のため
   **週1回・数百クエリ以内・1件ごとに1.5秒以上の間隔**を厳守し、結果は
   `data/search-suggest/` にキャッシュして再利用する
3. **選別**: 取得した語句を LLM で選別（段階1.5と同じ流儀）。税務と無関係・
   顧客層の外・既存記事と重複するものを落とす
4. **候補化**: 通過した語句を、需要の証拠 `demand_evidence: { kind: 'search-suggest',
   phrases: [実際の検索語], ... }` を持つトピックとして候補プールに接続。
   出典は持たせず、既存の出典解決（対応表→照合→LLM選定→ガード）に委ねる
5. **上限**: サジェスト由来は1日最大1件（質疑応答由来と同じ流儀）
6. **無効化**: `DISABLE_SUGGEST_TOPICS=true`

## 変更してはいけないもの

段階1・1.5と同じ（本文生成ルール・手動承認・既存フィルタ・frontmatter 形式）。
