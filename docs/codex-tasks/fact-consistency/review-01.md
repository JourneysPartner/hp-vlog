## 2. 指摘の一覧

### High

**1. B: `where` が数値だと本文の指摘を全部捨て、`ok` になる（既知）**
- 場所: `scripts/lib/fact-check.js:2025`
- 何が起きるか: `"where": 45` は `''` になって行が捨てられ、`dropped` に数えられるだけです。#796 の見出し・まとめのように本文の単位を指す指摘は、全部が黙って消え、他に止める理由が無ければ `ok` になります。`unitNumber` 自体は数値も `"[45]"` も読めるので、捨てているのは差分側の前処理です。指示書の出力例も `"where": ... または本文の番号` なので、AI が数値で返すのはふつうに起こります（抜き出しの所に「AI は番号を数値・全角・[12] の形でも返す」という注もあります）。B の主な目的が働かなくなるので High としました。
- 直し方: `title`・`summary` 以外は `unitNumber(row?.where)` に元の値をそのまま渡す。数値・`"[45]"` の試験を足す。

### Medium

**2. B: 止めた理由が、後の照合で消える（引き継ぎが無い）**
- 場所: `fact-check.js:2002-2004`、`checkArticle` の 2175 行
- 何が起きるか: B は「その回に直しが入ったとき」だけ動きます。
  - 差し戻しで再生成すると、`previousRaw` 付きの差分照合になります。前回の記録が `revise` でも使い回され、前回の `consistency.findings` は読まれません。
  - 本文の c22 はもう直っているので、新しい直しは無く、B は動きません。
  - 再生成で見出し・要約が直っていなくても、他に止める理由が無ければ `ok` になり、止めが外れます。
  - 再生成の側は照合記録の中身を読んでおらず、要約の「食い違う箇所 2 件」という件数しか伝わりません。
  - 手動の `fact-check.yml --write` で全体を照合し直しても、同じく消えます。
  - 決定の「扱いは今の『残った食い違い』と同じ」とずれています。残った食い違いは、文が残る限り差分照合でも判定し直されます。
- 直し方（指示書の追加が要ります）: `checkArticle` で前回の記録の `consistency.findings` のうち、`text` が今の題名・要約・本文にそのまま残っているものを新しい記録へ引き継ぎ、止める側に入れる。`failed` も、少なくとも引き継ぐ。

**3. A（S1）: 判定・要件・手続・番号の食い違いの `correct` の数字が、資料で確かめられないまま「消す数字」から外れる**
- 場所: `fact-check.js:1233-1237`
- 何が起きるか: 金額・割合などの `correct` は、`sufficientQuote` が数字を引用で確かめます。判定・要件・手続・番号の `correct` は、自由な文のままです。
  - 確かめた例: 判定の食い違いの `correct` が「…所得税は約2万円増えます。」と元の文を言い直していると、同じ文の資料なし（約2万円）の guard が外れました。「約2万円」を残した置き換えが採られ、`rejected` は空でした（資料なしの指摘が 1 つだけなら「資料の無い数字が残っています」で採られません）。
  - 今の設定（書き手の資料なし）では、再照合がもう一段の守りになります。書き手の資料の設定では、`unchanged_numeric` で再照合の資料なしが止めにならないことがあり、すり抜けの道になります。
- 直し方: `siblingNumbers` を、その sibling の `quote`・`quote_notes`（資料の文）にも在る数字だけに絞る。#796 の c42 で要る 10%・195万・330万・20% は全部引用にあるので、A の効き目は落ちません。この例を T3 の並びの試験に足す。

**4. C: 当たる条件が広すぎる（相続税・贈与税を外していない／同じ文を求めていない）**
- 場所: `scripts/lib/article-prompt-static.js:420-423`
- 何が起きるか:
  - 相続税・贈与税の文でも当たります。確かめた例: 題名「相続税の計算方法」で「課税遺産総額が4,000万円の場合、相続税の税率は20%です。」や「贈与額が900万円なら贈与税の税率は30%です。」が当たり、`findUnappliedRules` にも入りました。
  - その文は所得税の速算表の決まりと一緒に部分修正へ回ります。部分修正は「決まりの金額・割合に書き換えてよい」としていて、決まりの文にある 40% などへの書き換えも数字の見張りを通ります。既存の「速算表・累進税率」の条件には相続税・贈与税を外す式がありますが、新しい条件にはありません。
  - 記事全体の判定は「金額がどこか」と「税率がどこか」が別の文でも当たります（例: 「課税所得の考え方を説明します。」と「売上が900万円の年もありました。」）。その場合は部分修正の文が見つからず、止めない警告「論点別ルールが未反映: income_tax_bracket」が出るだけですが、関係ない記事に雑音が出ます。
- 直し方: 既存の条件と同じく相続税・贈与税を外す（ただし「所得税」があれば残す）。金額と語が同じ文にあることを、`__body` を文に分けて確かめる。どちらも R11 の書き換えになるので、指示書を直してから。

**5. B（S4）: 形の違う配列の答えが「全部捨てて `ok`」になり、捨てた件数がどこにも出ない**
- 場所: `fact-check.js:2030-2037`、要約 2069 行、画面
- 何が起きるか: 項目の名前が違う・`correction` が配列といった形のずれは、全部 `dropped` になり、`ok` で通ります。S4 の「形の違う答えは revise」と R7・T11 の「捨てて ok」が、指示書の中でぶつかっています。指摘 1 はその一例です。
- 直し方（どちらかを決める）:
  - (a) 型が違う行（オブジェクトでない、`where` が読めない、`text`・`correction` が文字列でない）は失敗として `revise` にし、中身の確かめ（記事に無い・直した文そのもの・知らない id）で落ちた行だけ捨てる。
  - (b) 少なくとも `dropped > 0` を要約と画面に「AI が挙げたが採らなかった n 件」と出す。

### Low

1. **T10 の前半は B の分岐まで届いていない**（`test-fact-consistency.js:239-243`）。`repair: false` と抜き出し 0 件で `not_run`（「主張を抜き出せませんでした」）で終わります。「直しが入らなかった」場合（直しは有効で、全部が裏付けあり）は試されていません。
2. **試験の足りない所**: T7 は `corrections` の件数を見ていません。中断のときに例外をそのまま投げる所（R9）、`error` に応答の文が入らないことの試験もありません。
3. **見出しそのものが指摘のとき、画面の場所が一つ前の節の見出しになる**（`fact-check.js:2010/2043`、`review-page.js:110`）。指示書どおりですが紛らわしいので、見出しの単位なら「本文の見出し」と出す方がよいです。
4. **短い本文の単位を取りこぼす**（2036 行）。`after.includes(unit.text)` が成り立つと、直した文と関係ない単位でも捨てられます（例: 「はい。」）。採りこぼしの側です。
5. **C の副作用**: `runFactCheckForArticle` の `validateRepair` は `findUnappliedRules` を使っています（`generate-draft.js:2748`）。照合の直しが新しく区切りの金額を本文に入れると、直し全体が採られません。止める側なので害は小さいです。

**範囲外（前からの穴）**: 表の行では A のまとめ直しが効きません。食い違いの直しが「消す数字の無い列」を書き換えると、資料なしの列の見張りが「外さない列を書き換えています」で弾き、同じ行の食い違いも採られません（確かめ済み）。今回の差分で悪くなったものではありません。

- `article_meta` を渡すのは `checkArticle` だけですが、B が動く道（日次の下書き・再生成・手動の照合）は全部 `checkArticle` を通ります。
