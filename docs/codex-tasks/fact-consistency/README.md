# 照合の直しで残る誤り・新しい食い違いを防ぐ（2026-11-18）

## 背景

2026-11-18 の日次下書き PR #796（インフルエンサーの確定申告はいくらから必要？）が「要修正・照合で承認が止まっています」になった。照合記録 `data/fact-check/influencer-tax-filing-income-threshold.json`（枝 `draft/2026-11-18-influencer-tax-filing-income-threshold`）を調べて、次の 4 つが分かった。試験データは `fixtures/pr796.json`。

1. **同じ文の直しがぶつかって、誤りが残った（A）。**
   「よくある質問」の文「課税所得が195万円を超えて330万円以下の人（税率10%）なら、所得20万円の増加で所得税は約2万円です」に、次の 2 つの指摘が付いた。
   - c42（食い違い）: 速算表は「1,950,000円から3,299,000円まで」なので「195万円以上330万円未満」が正しい。この直しには 10% が要る。
   - c43（資料なし、金額）: 「約2万円」を書いた資料が無い。主張の要約「税率10%の人は所得20万円増加で所得税が約2万円増える」の数字（10・20万・2万）が `repairNumberGuards` の removeNumbers になり、置き換えに 10% が残ると「資料の無い数字が残っています」で採られない。
   c43 が採られないと、`checkSentences` が同じ文の c42 も「同じ文の別の指摘の置き換えを採れませんでした」にする。文は元のまま残り、食い違いが残って承認が止まった。2 回目の直し（`retry_repair`）は書き手の資料の設定（`FACT_CHECK_WRITER_MATERIALS`）のときだけ動くので、本番では動いていない。動いても同じ縛りで弾かれる。
2. **直した内容と、記事の他の所が食い違ったまま残った（B）。**
   c22「ただし申告の義務は残ります。」は、正しく「この場合、確定申告をする必要はありません（…）」に直った（No.2020）。しかし、次の箇所はそのまま残り、直した内容と食い違って読める。照合は文ごとに見るので、これを見つける工程が無い。
   - 見出し「## 基礎控除104万円は申告要否の判定には使わない」
   - 要約（frontmatter の summary）
   - まとめ「- 令和8年分の基礎控除104万円は申告要否の判定には使わない」
   見出しは照合の主張にならず、要約は照合に渡していない。まとめの文（c49）は、基礎控除の金額表だけを根拠に「裏付けあり」になっていた。
3. **速算表の決まりが書き手に渡らなかった（C）。**
   `article-prompt-static.js` の `income_tax_bracket`（「未満／以上」で書く決まり）は、企画や本文に「法人成り・所得税率・税率が逆転・速算表・累進税率」があるときだけ当たる。今回の本文はついでに「税率10%」と書いただけなので当たらず、書いた後の論点別ルールの部分修正（`postfixRules`）にも乗らなかった。
4. **画面の件数が多めに出た（画面）。**
   照合の要点の「本文の変更: 直した 2 件・資料が無く案内に変えた 3 件」は、採れなかった直し（`resolved: false`）も数えている。実際に入ったのは 1 件と 2 件。

## 決定（2026-11-18 利用者）

- A・B・C・画面を先に直す。
- B で食い違う所が見つかったら、承認を止めて一覧に出す。扱いは今の「残った食い違い」と同じ。利用者は差し戻すか、確認欄の印で上書きする（#745 の仕組みのまま）。
- D（判定の文は、根拠の文が判定そのものを書いているときだけ「裏付けあり」にする）は、過去の記事 5 本を実 AI で測ってから決める。この指示書には入れない。

## 安全の条件（全段共通）

- S1 A で、同じ文の食い違い・期限の直しの `correct` などにある数字だけを、資料なしの「消す数字」から外す。それ以外の資料の無い数字は、今と同じく残せば採らない（T3・T4）。
- S2 指摘が 1 つだけの文は、修正の依頼文も結果も今と同じ（T5）。
- S3 B は本文を変えない。見つけた箇所を記録して承認を止めるだけ（T8）。
- S4 B は失敗したら止める側に倒す。呼び出しの失敗・読めない答え・形の違う答えは `revise`。B のせいで `ok` にも `not_run` にもしない（T12・T13）。
- S5 B は、実際に本文へ入った食い違い・期限の書き漏れの直しがあり、`repair !== false` のときだけ動く。それ以外は呼び出しも記録の欄も無い（T10・T14）。
- S6 B の指摘は、記事の題名・要約・本文（見出しを含む）にその文字のまま在るものだけを採る。直した文そのものは指摘にしない（T11・T16）。
- S7 B で止めた記事も、今の上書き（確認欄の印）で承認できる。`fact_check_blocking` の決め方は変えない（T8）。
- S8 C は書いた後の本文で当たる条件を足すだけ。書く前の決まりの選び方（`selectConditionalRuleEntries`）は変えない（T20）。
- S9 画面に出す AI の文は全部エスケープする（T17）。

## 費用
