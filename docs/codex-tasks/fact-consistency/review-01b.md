## 3. 新しい指摘

### Medium 1: `failed` の引き継ぎが 1 回で切れる。今回 B が別の直しで動いても切れる
- **場所**: `scripts/lib/fact-check.js:2086-2090`（`carriedFailure`）、`checkArticle` の 2204-2207 行
- **何が起きるか**:
  - 引き継いだ `failed` は `corrections: []` で保存されます。次の照合で `checkArticle` は `consistency.corrections` の id から after を引くので、空になります。`previousAfters.length > 0` が偽になり、引き継ぎません。
  - 確かめた例: 前回が `failed`（c22 の after が本文に在る）の記録で、直しの無い照合を続けました。2 回目は `revise`（引き継ぎ）、3 回目は `ok` で `consistency` が無くなりました。直した文は本文に残ったままです。
  - 今回、別の文の直しで B が動くと `!record.consistency` が偽になり、前回の `failed` は引き継ぎません。今回の B は今回の直しだけを AI に渡すので、前回の直し（c22）との食い違いは誰も確かめていません。ここは指示書 R17 の文のとおりなので、指示書の直しが要ります。
- **直し方**:
  - B の記録（成功・失敗とも）に、直した文そのもの（例 `afters`）を持たせます。引き継いだ `failed` にも、前回の after をそのまま写します。
  - `checkArticle` は `consistency.afters` があればそれを使い、無い古い記録だけ今の引き方にします。id は照合ごとに `c1…` と振り直されるので、id では引き継がないでください。
  - `failed` を引き継ぐかは「今回 B が動いたか」ではなく、「前回の after が今回の applied に入っていないか」で決めます。
  - 試験: 直しの無い照合を 3 回続けても `revise` のまま。別の直しで B が動いても、前回の `failed` が残る。

### Medium 2: 間に `not_run` や照合の無効が挟まると、引き継ぎが記録ごと消える
- **場所**: `fact-check.js` の catch（2115-2125 行）、早い戻り（1469・1476 行）、`checkArticle` の保存（2254-2256 行）
- **何が起きるか**:
  - 引き継ぎは `checkFacts` の try の中にあります。次の回は、`consistency` の無い記録でファイルが上書きされます:
    - API の失敗・抜き出しの失敗・B の中断（受け入れた直しで、外側の catch に落ちる）で `not_run` になった回
    - `FACT_CHECK_ENABLED=false` の回
  - その回は `not_run` なので止まります（`FACT_CHECK_FAIL_OPEN=true` なら止まりません）。ただ次の照合では、前回の記録に `consistency` が無いので引き継ぎません。
  - 確かめた例: 要約の指摘が 1 件ある記録で、3 回照合しました。
    1. ふつうの照合: `revise`（引き継ぎ）
    2. API が全部失敗する照合: `not_run`。保存された記録に `consistency` は無い
    3. ふつうの照合: `ok`。要約は同じ文のまま
- **直し方**:
  - `checkArticle` で、結果に `consistency` が無く、前回の記録の `consistency` を読めていたときは、前回の分を `carried: true` のまま保存する記録へ写します（少なくとも `not_run`・無効の回。状態は変えない）。Medium 1 の `afters` も一緒に写します。
  - `generate-draft.js` の catch が書く未実施の記録も同じく消しますが、変えてはいけないファイルなので、記録に回してください（記録の保存に失敗したときだけの道です）。
  - 試験: 引き継ぎ → `not_run` → ふつう、の 3 回でも `revise` が残る。

### Low 1: 中断の試験（R9）が B まで届いていない
- **場所**: `scripts/lib/__tests__/test-fact-consistency.js:311-320`
- **何が起きるか**: 初めから中断済みの signal を渡すので、最初の `extract` で「照合の時間切れ」になり、`not_run` で終わります。確かめると、呼び出しは `extract` の 1 件だけでした。B の `if (options.signal?.aborted) throw error;` を消しても、この試験は通ります。
- **直し方**: 偽の AI が `consistency_check` を受けたときに `controller.abort()` してから例外を投げます。そのうえで、`record.calls` に `consistency_check` があること、`status` が `not_run` であること、`consistency.failed` が付いていないことを見ます。

### Low 2: B の誤検出を消す手段が無い（記録に回すのでよい）
- 引き継いだ指摘は判定し直されません。そのため、AI の誤検出も、その文字が記事に残る限り毎回止めます。
- 人が確認欄に印を付けても、次の照合（再生成・手動の照合）で `applyFactResult` が印を消すので、また止まります。
- `where: 'body'` は本文全体で文字を探すので、「不要です。」のような短い text は、直した後も本文のどこかに同じ文字があれば残ります。
- どれも止める側の誤りで、害は小さいです。

### Low 3: `where` が範囲・複数の番号だと、答え全体が `failed` になる（記録に回すのでよい）
- `"12-13"`・`"12, 13"` は `unitNumber` で読めないので、R16 で答え全体が `failed` になります。同じ答えの正しい指摘も画面に出ません。
- `fact-units.js:62` の注にも、AI がこの形で返すとあります。
- 止める側で、指示書どおりです。本物の AI で失敗が多いようなら、最初の番号で読むか、範囲の各単位を対象にするかを決めてください。

### 指示書との違い（不具合ではない）
- `fact-check-article.js` を `--write` なしで動かすと `repair: false` になりますが、`checkArticle` はこのときも前回の `consistency` を渡すので、引き継ぎが働きます。
- R17 の「`repair: false` は渡さないので変わらない」とは文面がずれます。ただ、この道も記録のファイルを上書きするので、引き継ぐ方が安全です。指示書の文の方を合わせればよいです。

### 問題が無かった所
- **R16**: 形の違いと中身の違いの分け方は指示書どおりです。`where` の前後の空白、`null`、`'本文'`、`correction: null` は全部失敗になります。空の `correction` は中身の違いとして捨てます。
- **R19**: 文の分け方（`/[。！？\n]/`）と除外の式は指示書どおりです。表の行は「税率」と同じ行に無いので当たりません。これは R19 で絞った結果で、不具合ではありません。
- **R20**: 単位の `start`・`end` と、直した文の位置は同じ `revisedBody` の上で比べています。全部の出現を拾い、何文にもわたる直しにも重なりで効きます。
- **差分照合**: 記録を毎回読むようになりましたが、差分照合を使うかの判定は別に読んでいて、変わっていません。
- **指摘の引き継ぎ**: `{ ...f, carried: true }` として保存されるので、コードを読んだ限り、文字が残る間は何回でも続きます（実際に試したのは 1 回分です）。

**範囲外（前からの穴）**: 再生成の側は照合記録の中身を読まず、要約の件数しか伝わりません（前回の指摘 2 の一部）。`generate-draft.js` を変えられないため、今回のままです。
