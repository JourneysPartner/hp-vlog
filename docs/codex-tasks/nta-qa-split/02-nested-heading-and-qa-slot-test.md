## A. 入れ子の括弧の見出し

### 今起きていること（Claude が main fcbeb55f で確かめた数字）
- 軽減税率 Q&A は 138 問（概要編 19・事例編 119）。次の 4 問が前の問の本文にくっついている。

  | 問 | 見出し（xpdf の形） | くっついている先 |
  |---|---|---|
  | 概要編 問７ | （「飲食店業等を営む者が行う食事の提供」（いわゆる「外食」）の意義） | `keigen/gaiyo-6w.json`（問６） |
  | 概要編 問８ | （「飲食に用いられる設備」（飲食設備）の意義） | 同上 |
  | 概要編 問10 | （「相手方が指定した場所において行う役務を伴う飲食料品の提供」（いわゆる「ケータリング」） の意義） | `keigen/gaiyo-9w.json`（問９） |
  | 事例編 問44 | （物流センターの使用料（センターフィー）） | `keigen/jirei-43.json`（問43） |

- 原因: 直接形の区切り（`findQuestionMarks` の `directRe`、`（([^（）]{2,60})）\s*(問N)`）は、見出しの中に括弧があると合わない。後ろで札を探す側も、内側の括弧の直後が「の」（空白で区切られない）か、「の意義）」の閉じ括弧が余る形なので拾わない。
- xpdf でも poppler でも、この 4 問の札は外側の「）」の直後にある（直接形）。poppler は括弧の前後に空白を入れる（`（ 「飲食店業等を営む者が行う食事の提供」 （いわゆる「外食」 ）の意義） 問７`）。
- Claude の実験（一時フォルダーの写しで、`directRe` の見出しの中身を `(?:[^（）]|（[^（）]{1,40}）){2,80}` に変えただけ）: 参照 3 種（main の xpdf の本文をつないだもの、poppler の問番号順、poppler のファイル名順）のどれでも、増えるのはこの 4 問だけで、消える問は 0。本文が変わるのは問６・問９・問43 だけ（後ろが切れて短くなる。空白を除けば前の本文の先頭と同じ）。ほかの問の題名・本文は変わらない。
- 分けた後の文字: 今の main のファイル（xpdf）の問６ の本文の文字の多重集合（空白を除く）は、poppler で分けた問６＋問７＋問８ の多重集合と同じ。問９＝問９＋問10、問43＝問43＋問44 も同じ（取り出しの部品が違っても一致する）。
- そのため、本文短縮の更新ガード（`shouldSkipBodyUpdate`、前の半分未満なら更新しない）に当たる: 問６ 1156→334 字（0.29）、問９ 2038→400 字（0.20）、問43 661→288 字（0.44）。このままでは問７ などの新しいファイルだけができ、問６ などはくっついたまま残る（同じ文が 2 か所に入り、問６ の題名と本文が食い違ったまま）。
- 区切りの関数（`splitByQuestion`）を使うのは軽減税率（`keigen`）だけ。

### R1 直接形の見出しに 1 段の入れ子を許す
- `directRe` の見出しの中身に、括弧 1 段の入れ子を許す（例: `/（((?:[^（）]|（[^（）]{1,40}）){2,80})）\s*(問\s?[\d０-９]+(?:\s?[\-－]\s?[\d０-９]+)?)/g`）。2 段以上の入れ子は合わなくてよい。
- 入れ子を含む見出しで新しく拾う区切りにだけ、後ろで札を探す側と同じ除外を当てる:
  - `isIgnoredHeading(見出し)` が真なら拾わない。
  - 札の後ろが `《` `≪` `〈` で始まる、または（空白の後に）「参照」「をご参照」「を参照」「に参照」で始まるなら拾わない。
  - 「の場合」「のとき」の除外は、今の直接形と同じく当てる。
- 入れ子の無い直接形の区切りは、今と全く同じにする（除外も足さない。01d の「範囲外」の記録のとおり、xpdf の結果を変えないため）。
- 後ろで札を探す側（indirect）は変えない。

### R2 題名の空白を整える
- `splitByQuestion` が作る題名（`${qNo} ${見出し}`）の、見出しの部分だけを整える: `（` `）` `「` `」` の前後の空白を除き、続く空白を 1 つにし、前後の空白を落とす。本文は変えない。
- 例:
  - poppler の `問７  「飲食店業等を営む者が行う食事の提供」 （いわゆる「外食」 ）の意義` → `問７ 「飲食店業等を営む者が行う食事の提供」（いわゆる「外食」）の意義`
  - poppler の `問44 物流センターの使用料（センターフィー） ` → `問44 物流センターの使用料（センターフィー）`
  - xpdf の `問10 「相手方が指定した場所において行う役務を伴う飲食料品の提供」（いわゆる「ケータリング」） の意義` → `問10 「相手方が指定した場所において行う役務を伴う飲食料品の提供」（いわゆる「ケータリング」）の意義`
- Claude が確かめたこと: 今の main の 138 問の題名は、この整え方で 1 つも変わらない。poppler で拾う既存の問の題名（`問１  「軽減税率制度」の概要` など 14 件）は main と同じ形になる。

### R3 くっついていた問を分けたときは、短くなった本文を書く（更新ガードの例外）
- `crawlSource` で、区切る資料（R3 の見送りに当たらず、parts が 1 件以上）について、今ファイルがある問 X ごとに「分けた先」を求める。
  - parts の並び（本文の順）で X のすぐ後ろに続く問 Y を順に見る。空白を除いた「（Y の見出し）Y の問番号」（見出しは R2 で整えた後のもの。空白を除くので整える前と同じ）が、空白を除いた X の今の本文に含まれる間だけ、Y を分けた先に入れる。含まれない問が来たら止める。
  - Y は新しい問でも、もうファイルがある問でもよい（同じ月に合わずに見送った後、次の月の取り込みで直るように）。
  - 分けた先が 1 つ以上あり、`sameCharMultiset(X の今の本文, X の新しい本文＋分けた先の新しい本文をつないだもの)` が真なら、X は「分け直し」とする。
- 分け直しの X は、本文短縮の更新ガードを当てずに新しい本文で書く。題名は、今の題名と空白を除いて同じなら今の題名を残す。違えば新しい題名を書き、今ある「題名の変更」（G2）として報告に出す。
- 多重集合が合わないとき（同じ月に国税庁が文を直したときなど）は、今までどおり更新ガードに従う（X は前の本文のまま、警告と件数）。分けた先の問は通常どおり書く。報告に X のファイル名と分けた先の問番号を出す（R4）。
- 分けた先が無いとき、X が短くならないときは今と同じ。区切らない資料、R3 で見送った資料、取得に失敗した資料（F2）も今と同じ。
- 判定と書き込みを分けて試験できるように、判定は関数にして exports に足す（例: `findSplitOffs(parts, existingRecordsByQNo)` → `[{ qNo, children: ['問７', '問８'], matches: true }]`）。
