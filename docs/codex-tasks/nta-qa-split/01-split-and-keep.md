# 01 問の区切りの直し・並び替えだけの変化を残す・問が減る取り込みを止める

背景と厳守事項は `README.md`。参照ファイルは `.tmp-ref/`（コミットしない。中身は `.tmp-ref/README.txt`）。

## R1 問番号が 1 行目の後ろに来る形でも区切る（`splitByQuestion`）
- 今の形「（見出し） 問N 本文」はそのまま拾う（結果を変えない）。
- 加えて、「（見出し）」の後ろ **200 字以内**に、次の条件をすべて満たす「問N」（「問N-M」「問 N」、全角数字も含む）がある形も、その「（見出し）」を問の始まりとして拾う。
  - 「（見出し）」と「問N」の間に「【答】」が無い。
  - 間に別の「（見出し）＋問番号」の組が無い。
  - 「問N」の直後が「《」「≪」「〈」でない（答の中の「問115《２割特例…》をご参照ください」のような参照を拾わない）。
  - 「問N」の直前が「（」でない（「（問 80《…》参照）」を拾わない）。
- 拾った問の本文は、札「問N」を元の位置から取り除き、「（見出し）」の直後に置いた形にする。例:
  - 入力 `（ホテルに対して販売する新聞） 当社は、…週２回以上発行される 問100 新聞は、…`
  - 本文 `（ホテルに対して販売する新聞） 問100 当社は、…週２回以上発行される 新聞は、…`
  - 題名 `問100 ホテルに対して販売する新聞`、q_no `問100`
- 札以外の文字は 1 字も足さない・消さない・並べ替えない（空白の数だけは今の作りどおり詰めてよい）。
- 目次の除外（【答】の有無・150 字未満・点線）と、同じ問が 2 回出たときに長い方を採る決まりは今のまま。

## R2 並び替えだけの変化は今の本文を残す（`saveEntry` まわり）
- 既にある記録と新しい記録で、本文から空白をすべて除いた文字の**多重集合**（どの字が何回出るか）が同じなら、本文・`char_count_body`・題名を既にある記録のまま残す。
  - 題名は空白を詰めて比べる（`問13 「…」` と `問13  「…」` は同じ）。
  - `fetched_at` などの日時は更新してよい（`has-substantive-change.js` は `*_at` を無視するので PR にならない）。
- 1 字でも違えば今までどおり新しい本文を保存する（本物の改訂を取りこぼさない）。
- 既にある「本文短縮の更新見送り」（`shouldSkipBodyUpdate`）は今のまま残す。
- 残した件数を記録に出す（例: `並び替えだけのため本文を残した 120 件`）。

## R3 今ある問が見つからない資料は更新しない（区切る資料だけ）
- 区切る資料（`split: true` または `splitBy` のある資料）ごとに、取り込み前にその資料の問番号の集まり（今の `data/nta-qa/<source>/` のうち、その資料の id で始まるファイルの `q_no`）を控える。
- 新しく区切った結果に、控えた問番号が 1 つでも無い場合:
  - その資料の問のファイルを 1 つも書かない・消さない（その資料の分は今のまま）。
  - 索引（`index.json`）のその資料の行も今のまま残す。
  - 記録に `区切りを見失った問があるため <資料 id> は更新していません: 問100, 問104, …` を出す。
- 新しい問番号が増えるだけの場合は今までどおり取り込む。
- `--only`・`--limit` の指定があるときの扱いは今の `getStaleSplitFileNames`（`limitSpecified` で削除しない）と矛盾させない。

## R4 報告を PR 本文に出す
- 取り込みの終わりに、R2 の件数・R3 の見送り（資料 id と見つからない問番号）・本文短縮の見送りを Markdown にまとめ、環境変数 `NTA_QA_REPORT` で指定されたファイルに書く（未指定なら書かない）。
- `refresh-nta-qa.yml`:
  - Crawl の段で `NTA_QA_REPORT` に一時ファイル（例 `${{ runner.temp }}/nta-qa-report.md`）を渡す。
  - PR 本文を `--body-file` で作り、今の本文の後ろに報告をつなぐ。国税庁の文字（題名など）を `${{ }}` や `$(…)` でコマンドに埋め込まない。
  - 報告に R3 の見送りがあるのに PR が作られない（変化なし）場合は、`::warning::` と `$GITHUB_STEP_SUMMARY` に報告を出す。
- 既存の試験 `scripts/lib/__tests__/test-workflow-run-injection.js` が通ること。

## 試験（`scripts/lib/__tests__/test-nta-qa-split.js` に追加。資料は `fixtures/nta-qa-split/` に小さく切り出す）
1. poppler の並びの抜粋（`.tmp-ref/keigen-jirei-poppler-joined.txt` から問99〜問101、問119〜問121 の前後を切り出す）を区切ると、問99・問100・問101・問119・問120・問121 がそれぞれ別の問になり、本文が「（見出し） 問N …」で始まる。
2. 同じ抜粋で、問99 の本文に「問100」の札も問100 の本文も入らない。
3. 答の中の参照「問115《…》をご参照ください」「（問 80《…》参照）」で区切らない。
4. R1 で札を動かした本文と元の本文で、札以外の文字の多重集合が同じ。
5. 今の形（xpdf の並び）の抜粋の区切りの結果が、直す前と同じ（問番号・題名・本文）。
6. R2: 並び替えだけの 2 つの本文（`.tmp-ref/reorder-pairs.json` の invoice/113 から切り出す）は本文を残す。1 字だけ違う本文（kyoiku_shikin の「制度の詳細へ」）は新しい本文を保存する。
7. R3: 控えの問番号が新しい区切りに 1 つ無いと、その資料のファイルは書かれず消されず、記録に問番号が出る。問が増えるだけなら取り込む。
8. R4: 報告ファイルに R2 の件数と R3 の資料 id・問番号が出る。`NTA_QA_REPORT` が無ければファイルを作らない。

## 受け入れの目安（Claude が `.tmp-ref/` で確かめる）
- `.tmp-ref/keigen-jirei-poppler-joined.txt` を区切ると、`.tmp-ref/keigen-jirei-main-xpdf.json` の 119 問の問番号がすべて出る。gaiyo も同じく 19 問。
- 問ごとに、本文の文字の多重集合が main の本文と同じ（一致しない問があれば一覧で報告）。

## 変えてはいけないもの
- `data/` の中身、照合・生成のコード、他の区切り方の結果、`pdftotext` の呼び方（`-enc UTF-8` のまま。`-layout` などは付けない）。

## 報告の形
- 変えたファイルと要点、R1〜R4 の作り、試験の結果（件数）、受け入れの目安を自分で確かめた結果（区切れた問の数、一致しない問の一覧）、残った疑問。
