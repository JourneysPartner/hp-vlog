## K1 数字の間に空白が 1 つ入った札を、並びに合うときだけ合わせて読む
- `findQuestionMarks` で区切りを集めて本文の順に並べた後、前から順に各区切り i（i ≥ 1）について次をすべて満たすときだけ、札を合わせて読む:
  1. 札が `問` ＋（空白 0〜1 個）＋半角の数字 1〜2 桁だけ（全角の数字・枝番「－」付きは対象外）。
  2. 札のすぐ後ろが「空白 1 つ＋半角の数字 1〜2 桁」で、その後ろが数字でない（例「問1 4 仕入先から」）。
  3. 札をそのまま読んだ番号が、すぐ前の区切り（種類を問わない。目次も含む。前の区切りが合わせて読んだものなら、その番号）以下（`compareQuestionNumbers(そのままの札, 前の札)` が -1 か 0）。
  4. 合わせて読んだ番号 N が、すぐ前の区切りの番号 P について P < N ≤ P＋3。
- 合わせて読むときは、札の文字に「空白＋数字」を含める（例 `card = '問1 4'`）。問番号は今までどおり `card` から空白を除いたもの（`問14`）。`cardStart` は変えない。後ろで札を見つけた区切り（indirect）は、`relocateQuestionCard` で札の文字ごと見出しの直後に動く（本文の文字は変えない）。
- どれかを満たさなければ今のまま。目印（例 `splitDigits: true`）を区切りに付け、試験で見えるようにする。
- 期待: `keigen/gaiyo-14`・`gaiyo-15`・`jirei-34`・`jirei-42`・`jirei-80`・`jirei-81` のファイル名になる（`buildEntryId` は今のまま）。

## K2 入れ子の無い直接形でも、残った問のすぐ後ろで捨てる切れ端は前の問に戻す
- `splitWithMarks` で、入れ子の無い直接形の区切り（`indirect` でも `nested` でもない）の切れ端を捨てるとき（【答】が無い・150 字未満・目次に見える・同じ問番号の競り負け）、**その区切りのすぐ前の区切りが、この回で問として残っている**ときだけ `rejected` に入れる。`splitByQuestion` の (a) の繰り返しで外して区切り直す（切れ端の文字は前の問の本文に戻る）。
  - 同じ問番号の競り負けで負けるのが前に出てきた区切り（`prev.mark`）のときも、その区切りのすぐ前の区切りが残っているかで決める。
  - すぐ前の区切りが残っていない（目次の中、資料の先頭など）ときは今のまま捨てる。目次の区切りは今までどおり問にならない。
- 前後の問番号の確かめ（(b)、`findOutOfOrderIndirectMarks`）は入れ子の無い直接形には当てない（今のまま）。
- 期待: K1 の後の今の全文では、K2 で変わる所は 0（Claude の調べ）。受け入れで「K1 だけの結果と K1＋K2 の結果が同じ」を確かめる。

- sha256 は本文の文字列（`record.body`）を UTF-8 のまま計算する（16 進の小文字 64 字）。
- `saveEntry` で、今あるファイルを読んだ後、`isReorderOnly` より前に: その資料（`relative`、例 `invoice/94-4.json`）が一覧にあり、`sha256(今の本文) === keep_body_sha256` かつ `sha256(新しい本文) === drift_body_sha256` なら、今の本文・題名・`char_count_body` を残して書き（`fetched_at` だけ新しい。R2 の並び替えと同じ書き方）、`{ relative, record, knownDrift: true }` を返す。
