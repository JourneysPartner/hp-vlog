## F1 空白の位置だけの違いも今の本文を残す（R2 の直し）
- `isReorderOnly` の `if (before === after) return false;` のため、空白を除くと全く同じ本文（空白の位置だけが違う）は新しい本文で書き替わる。#761 では 217 ファイルがこれに当たり、毎月 PR の雑音になる。01 の R2 は「空白をすべて除いた文字の多重集合が同じなら残す」なので、空白の位置だけの違いも残す側に入れる。
- 本文が空白まで含めて全く同じ場合は今までどおり（数えない）。
- 報告の文言は「並び替え・空白の違いだけのため本文を残した N 件」にする。
- 試験: 空白の位置だけ違う本文 → 今の本文と `char_count_body` が残り、件数に入る。全く同じ本文 → 件数に入らない。

## F2 取得・取り出しに失敗した資料は、ファイルも索引の行も前のまま残す（直す前からある穴）
- 今は、資料 1 つの取得（`fetchBuffer`）や取り出し（`pdftotext`・本文を抽出できない）が失敗すると `catch` で `failed++` するだけで、区切る資料ではその資料の問のファイルが「古いファイル」として全部消え（`getStaleSplitFileNames`）、どの資料でも索引の行が落ちる（`main()` が同じ `source_key` の行を入れ替えるため）。例: 事例編の PDF の取得が 1 回失敗すると、事例編の 119 問が消える。
- 失敗した資料は R3 と同じく、ファイルを消さず、索引の行も前のまま残す。区切る資料は `<doc.id>.json` と `<doc.id>-*.json`、区切らない資料は `<doc.id>.json` とその索引の行。
- 報告に「取得できなかったため <source_key>/<doc.id> は更新していません（理由）」を出す。理由は例外のメッセージの 1 行目だけ（長さは 200 字まで）。
- `refresh-nta-qa.yml` の「変化なしのときの警告」の対象にこの行も入れる（`::warning::`・`$GITHUB_STEP_SUMMARY`）。
- 試験: 区切る資料の取得が失敗すると、その資料のファイルが残り、索引の行も残り、報告に出る。区切らない資料の取得が失敗すると、索引の行が残る。他の資料は今までどおり更新される。
