## J1（M1、Medium）入れ子の見出しの区切りにも、後ろで札を探す側と同じ 2 つの歯止めを当てる
- 今の形: R1 で新しく拾う入れ子の見出しの区切り（`nestedDirectRe`）は直接形（`indirect: false`）として扱われる。後ろで札を探す側（indirect）にある 2 つの歯止めが効かない。
  - (a) `splitWithMarks` で捨てた切れ端を作った区切りを `rejected` に入れて区切り直す。
  - (b) `filterIndirectMarks`（`findOutOfOrderIndirectMarks`）で、すぐ前後の kept の問番号の間にあるかを見る。
- 起きること（レビューが再現）: 答の中に `（「飲食料品」（食品表示法に規定する食品）の範囲）問３ で説明したとおり、酒類は含まれません。` や `…問７ と同様に判定します` があると、そこに区切りが立つ。切れ端は【答】が無いので捨てられ、前の問の本文が黙って切れる（406→237 字、393→243 字）。半分未満にならなければ更新ガードにも R3 にも当たらず、報告は「特記事項はありません」。今のデータでは当たる所は本物の 4 問だけで影響は無いが、今後の改訂で起こり得る。
- 直し:
  - 入れ子の見出しの区切りに目印（例 `nested: true`）を付ける。`indirect` は false のまま（札の位置を動かさない）。
  - `splitWithMarks` で、入れ子の区切りの本文が捨てられたとき（【答】が無い・150 字未満・目次に見える・同じ問番号の競り負け）は、indirect と同じく `rejected` に入れる。`splitByQuestion` の (a) の繰り返しで外して区切り直す（外れたときは直す前と同じ、前の問にくっついたままの形に戻る）。
  - `findOutOfOrderIndirectMarks` の対象を「indirect または nested」にする（(b)）。前後のどちらかが無い・前後が番号の順でないときは外さない、は今と同じ。本物の 4 問は前後の番号の間にある（問６<７<８、問７<８<９、問９<10<11、問43<44<45）。
  - 入れ子の無い直接形は変えない（レビューの「範囲外」。main の頃からの穴で 01d に記録済み。広げるかは別件）。
- 試験:
  - 作り物の 5 問（既存の A5 の作り方）で、問902 の答の途中に上の 2 つの文をそれぞれ入れる。直す前のコード（`.tmp-ref/crawl-nta-qa-before.js` で採った値を試験の中に固定してよい、または「入れた文を含む問902 の本文がそのまま残る」で確かめる）と同じく、問902 の本文が切れずに残り、区切った問をつないだ文字の多重集合が入力（目次を除く）と同じ。問３・問７ の区切りができない。
  - 同じ文を入れた入力で `crawlSource` を通し、問902 のファイルが書き替わらない（または同じ本文で書かれる）。
  - (b) の確かめ: 入れ子の見出しの区切りが前後の問番号の間に入らない作り物（例: 問901 と問902 の間に「（…（…）…）問 950 本文 【答】…」を本物らしい長さで置く）で、その区切りが外れる。前後のどちらかが無い位置では外さない。
  - A1〜A3・A6・A10 と既存の試験は期待を変えずに通る。
