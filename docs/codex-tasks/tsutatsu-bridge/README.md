# 通達の橋渡し — 質疑応答事例の記事に法令解釈通達の原文を渡す

## 背景

日次生成では、モデルに**法令解釈通達の原文が渡っていない**。渡るのは出典（タックスアンサー／質疑応答事例）の本文までで、通達は「記事を書き終わったあとに、引用した通達番号がカタログに実在するか照合する」という後追いの検査しかしていない。

そのため、通達でしか決まっていない実務論点（源泉徴収の取扱いなど）を、モデルが記憶で書いている。実際に次の事故が起きている。

- 2026-08-20 所基通37-14 は「任意の取扱い」なのに「按分が必要」と書いた
- 2026-08-21 消基通6-4-5 の番号を取り違えた

いずれも、生成後の `applyMissingRulesToBody` が本文から通達番号を拾って原文を添え、事後的に直している。**最初から渡せば起きない。**

一方、質疑応答事例の原典には「**関係法令**」という項目があり、そこに通達番号が書かれている。

```
所得税基本通達181～223共-6
所得税法第216条、所得税基本通達216-1
所得税法施行令第14条、第15条、所得税基本通達2-1、3-3
```

これを橋渡しにして、生成時に通達原文を渡す。

## 先行実装（同じ形の仕組みが既にある）

2026-09-14 に、同じ関係法令欄から**法律**の条文を引く仕組みを入れた（`law-sources.js` の `articlesFromSourceKankei`）。今回はその通達版で、**設計を揃える**こと。

| | 法律（実装済み） | 通達（今回） |
|---|---|---|
| カタログ | `data/law-sources/` | `data/nta-tsutatsu/`（既存・3,596条） |
| 引用検出 | `law-sources.findLawCitations` | `nta-tsutatsu.checkCitations`（既存） |
| 原文ブロック | `law-sources.buildLawProvisionBlock` | `nta-tsutatsu.buildProvisionBlock`（既存） |
| 橋渡し | `law-sources.articlesFromSourceKankei` | **今回つくる** |

**部品はすべて揃っている。** 新規に書くのは橋渡しの関数と、引用検出の穴を2つ塞ぐ部分だけ。

## 効果（実測済み）

質疑応答事例 1,550 件のうち関係法令の記載があるのは 1,542 件。

| | 件数 |
|---|---|
| 関係法令に通達名を含む | **528** |
| 現在の `checkCitations` で1件以上解決する | **517** |
| 通達名はあるが1件も解決しない | 11 |

**517 件が、既存の検出ロジックのまま解決する。** 残りの穴は次の2つ（`01-bridge.md` に詳細）。

- 範囲表記（`181～223共-6`）: 8 件
- 連記の2件目以降（`2-1、3-3` の `3-3`）: 129 件

## 作業の単位

2. `02-tests.md` — テスト

## 守ってほしい前提

- **記事の自動公開はしない。** この変更は生成時のプロンプトに原文を足すだけで、公開フロー（人手のレビュー・承認）には触らない
- **既存の挙動を壊さない。** 差し戻し再生成での通達添付、生成後の番号照合はそのまま残す
- **カタログに無い通達は渡さない。** 実在する条文だけを渡し、無いものは黙って落とす（捏造防止のため `buildProvisionBlock` は既にそうなっている）
