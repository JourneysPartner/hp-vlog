# 01 通達の橋渡しと、引用検出の穴2つ

## A. 引用検出の穴を塞ぐ（`scripts/lib/nta-tsutatsu.js`）

`CITATION_RE` は「通達名 + 番号」の形だけを拾う。関係法令欄では次の2つを取りこぼす。

### A-1 連記の2件目以降（129件）

```
入力: 所得税法施行令第14条、第15条、所得税基本通達2-1、3-3
いま: 所得税基本通達2-1 だけ
望み: 所得税基本通達2-1 と 所得税基本通達3-3
```

通達名のあとに「、」で番号が続いたら、**直前に出た通達名を引き継ぐ**。

引き継ぎを打ち切る条件を必ず入れること。次のいずれかが来たら引き継ぎを終える。

- 別の通達名・法令名が現れた（`所得税法`, `民法`, `租税特別措置法` など「◯◯法」「◯◯令」）
- 「第◯条」の形（法令の条であって通達番号ではない）
- 句点・改行

**注意**: `所得税法第10条、所得税基本通達10-14、10-15` のように、法令の条が先に来る例がある。`第10条` を通達番号として拾ってはいけない。

### A-2 範囲表記（8件）

> **【この節は誤りだった。03-fix-range.md を読むこと】**
> 下の「引けない場合はカタログ側の実際のキーを調べて、そのキーに合わせること」という
> 書き方が、`181～223共-6` を別物の `181-6` に読み替える実装を招いた。
> 「共」の範囲表記はカタログに存在しないので、**検出はするが解決しない**が正解。

```
入力: 所得税基本通達181～223共-6
いま: 検出ゼロ
望み: 181～223共-6 として検出し、カタログと照合する
```

`～` `〜` `~` を含む番号を検出できるようにする。**範囲を展開しないこと**（181-6 から 223-6 までを作らない）。カタログは `181～223共-6` という表記のまま条文を持っているはずなので、まず `normalizeProvisionNo` を通した結果でそのまま引けるかを確認し、引けるならそれでよい。引けない場合はカタログ側の実際のキーを調べて、そのキーに合わせること。**カタログに無い番号を作り出さない。**

### A-3 既存の検出結果を変えないこと

`所基通36-10` `消基通5-9-10` `法人税基本通達9-2-9` `相続税法基本通達11の2-1` は現在すべて正しく検出・照合できている。A-1/A-2 の変更でこれらの結果が変わってはいけない。

## B. 橋渡しを作る（`scripts/lib/nta-source-body.js` もしくは新規モジュール）

質疑応答事例の出典レコードから関係法令欄を読み、通達の原文ブロックを返す関数を作る。

```
入力: topic（source_url を持つ）
処理: resolveSourceFile(topic.source_url) でレコードを読む
      → entry.kankei_hourei を checkCitations にかける
      → found のものだけを buildProvisionBlock に渡す
出力: プロンプトに差し込む文字列（該当なしなら空文字）
```

**設計を法律版（`law-sources.articlesFromSourceKankei`）に揃えること。** 具体的には、

- レコードが無い・壊れている・`deleted: true` のときは**静かに空を返す**（生成は止めない）
- 質疑応答事例以外（タックスアンサー由来）は `resolveSourceFile` が別のパスを返すが、そのレコードに `kankei_hourei` が無ければ自然に空になる。特別扱いは不要
- **1記事あたり最大3条**に制限する。関係法令欄には他法の通達も並ぶため、全部入れるとプロンプトが膨らむ。カタログにある順に先頭から採る

## C. 日次生成に組み込む（`scripts/generate-draft.js`）

法律の条文を組み込んだのと**同じ場所**に足す。

```js
const ntaRefsBlock = ntaRefsList + sourceBodyBlock + figureGuardBlock
  + nonTaxBlock + refPagesBlock + qaBlock + lawBlock;
```

この `lawBlock` の隣に通達ブロックを足す。ログも法律版に揃えること。

```
[source] 法令の原文を添付: 租税特別措置法第70条の4 ／ 機関ページ 0 件   ← 既存
[source] 通達の原文を添付: 所基通2-1、所基通3-3                        ← 追加
```

### 差し戻し再生成には足さないこと

`buildRegenSourceBlocks` は既に「本文が引用している通達」の原文を添えている（`provisions`）。そちらは本文ベースで十分なので**触らない**。二重に足すとプロンプトが膨らむだけ。

## D. やってはいけないこと

- **範囲表記を展開して番号を作らない**（`181～223共-6` から `182共-6` を作る等）
- **カタログに無い通達を渡さない**
- 生成後の番号照合（`selfCheckContent` の `checkCitations`）を消さない
- `buildProvisionBlock` の【厳守】文言を書き換えない（「任意の取扱いを義務と書き換えない」は過去の事故対策）
- 記事の公開フローに触らない
