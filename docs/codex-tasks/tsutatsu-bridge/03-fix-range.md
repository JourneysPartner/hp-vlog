# 03 修正：範囲表記が別の通達にすり替わっている

レビューで欠陥が見つかった。**A-2（範囲表記）のうち「共」の範囲表記への対応を取り下げる。**
A-1（連記）と B・C はそのまま残す。

## 何が起きているか

`findProvision` に入れた `commonRange` のフォールバックが、引用とは**別の通達を返している**。

| 事例の関係法令 | 返していた通達 |
|---|---|
| 所基通 181〜223共-6（源泉徴収税額の再計算） | **181-6 質権を設定した株式の配当等に対する源泉徴収** |
| 所基通 181〜223共-1（源泉徴収をすべき日） | **181-1 無記名の公社債の利子等に対する税額の計算** |
| 所基通 183〜193共-1（源泉徴収税額の計算） | **183-1 支払の確定した日から1年を経過した日** |

`found: true` で通るため、原文ブロックに無関係な通達が「根拠」として出力される。
扶養手当の返還の記事に質権付き株式の配当の通達が渡る状態で、**捏造を防ぐ仕組みが逆に捏造を作っている**。

## なぜ寄せてはいけないのか

`181〜223共-6` と `181-6` は**別の通達**である。前者は181条から223条までに共通する通達の第6項、
後者は181条の個別通達の第6項。番号の見た目が近いだけで、内容の関係はない。

カタログ（所基通1,202条）に「共」を含むキーは47件あるが、すべて `36・37共-1` の**併記形**で、
`181〜223共-◯` の**範囲形は1件も入っていない**。クローラが取り込めていないためで、
**正しい解決先はそもそも存在しない**。

## 直してほしいこと

### 1. `commonRange` のフォールバックを削除（`scripts/lib/nta-tsutatsu.js`）

済み。`findProvision` から `commonRange` の分岐を消してあること。

### 2. `rangeStart` のフォールバックは**戻す**

一緒に消してあるが、これは**消しすぎ**だった。戻すこと。

理由：`rangeStart` は `commonRange` とは性質が違う。

- `所基通36-40～43` → `36-40`（役員に貸与した住宅等に係る通常の賃貸料の額の計算）
- `相基通3-18～3-20` → `3-18`（退職手当金等の取扱い）

これは **36条の40 から 36条の43 までという条文の範囲**で、その左端の `36-40` は
引用されている通達そのものである。すり替わりではない。

さらに、**この解決は今回の変更前から効いていた**。変更前の `CITATION_RE` は `～` を含まないため
`所基通36-40～43` は `36-40` までしかマッチせず、そのまま引けていた。今回 `～` を拾えるように
したので、`rangeStart` が無いと**従来引けていたものが引けなくなる**。

その場合の実害は、`selfCheckContent` が `所基通36-40～43` を「カタログに無い通達番号」として
警告することである。実在する条文の正しい引用に捏造の警告が出るのは誤検知で、
差し戻しの空振りを生む。

なお `rangeStart` が「共」の範囲表記を誤って引くことはない。
`181～223共-6` の左端は `181` で、単独ではキーにならないため未解決のままになる。

### 3. 期待する挙動

```
findProvision('181～223共-6', 'shotoku')  → null   （すり替わらない）
findProvision('36-40～43',    'shotoku')  → 36-40  （範囲の左端。従来どおり）
findProvision('3-18～3-20',   'sozoku')   → 3-18   （同上）
findProvision('181-6',        'shotoku')  → 181-6  （直接指定。従来どおり）

checkCitations('所得税基本通達181～223共-6')
  → citations 1件（no: '181～223共-6'）, found: false, unknown に入る
```

### 4. 範囲表記の「検出」は残す

正規表現（`PROVISION_RANGE_ELEMENT`）はそのままでよい。「共」の範囲表記は
**検出はするが解決しない**状態にする。

理由：`selfCheckContent` が `checkCitations` の `unknown` を使って「カタログに無い通達番号」を
警告している。検出自体をやめると、記事が `所基通181〜223共-6` と書いても**警告が出ず素通り**する。
検出して未解決にしておけば、警告が正しく出る。

橋渡し（`findTsutatsuFromSourceKankei`）は `found` のものだけを採るので、
未解決の範囲表記が記事に渡ることはない。

## テストの追加（`scripts/lib/__tests__/test-tsutatsu-bridge.js`）

もとのテストは「1件検出される」だけを見ており、**すり替わっていても通る**。次を足すこと。

- `所得税基本通達181～223共-6` は検出されるが `found: false` であること
- `findProvision('181～223共-6','shotoku')` が `null` を返すこと
- **`181-6` に解決していないこと**を明示的に確認する（この回帰を二度と起こさないため）
- 同様に `183～193共-1` が `183-1` に解決しないこと
- `findProvision('36-40～43','shotoku')` が `36-40` を返すこと（左端の解決は残す）
- `findProvision('181-6','shotoku')` は従来どおり引けること
- 橋渡しの結果に「共」の範囲表記由来の通達が混ざらないこと

## 実測値（カタログ全1,542事例の関係法令で計測）

| | 修正前 | あるべき姿 |
|---|---|---|
| 引用の検出数 | 670 | 670（変わらない） |
| 解決数 | 664 | **659** |
| 範囲表記12件のうち解決 | 7件（うち5件がすり替わり） | **2件**（`36-40～43`・`3-18～3-20` のみ） |

`commonRange` だけを消し `rangeStart` を戻せばこの数字になる。
いま両方消してあるので解決数は 657、範囲表記の解決は 0 件になっている。
