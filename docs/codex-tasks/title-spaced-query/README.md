# 題名に検索語を空白区切りのまま貼らせない

2026-11-14 の利用者決定（「進めて」）。枝 `fix/title-spaced-query`。

## 何が起きていたか

- 11/14 に公開した記事（#768、slug `reselling-tax-declaration-detection`）の題名が「せどり 確定申告 バレない 無申告が税務署に気づかれる流れと加算税」だった。狙う検索語（target_query）「せどり 確定申告 バレない」を、空白で区切ったまま題名の頭に貼った形。
- 題名は #773・#774 で手で直した（今は「せどりで確定申告しなくてもバレない？無申告が税務署に気づかれる流れと加算税」）。
- 公開中の記事 290 本を調べて、この形はこの 1 本だけだった。

## 原因（11/13 の日次の生成ログ run 43334195251 で確認）

1. 最初に AI が付けた題名が `lintSeo` の題名の点検（`title_missing_query` か `title_too_long`）に落ち、`retryTitleOnce`（`scripts/generate-draft.js` 1618 行、AI 1 回）が動いた。ログには「[seo] 題名を作り直しました: "せどり 確定申告 バレない …"」だけが出ていて、**元の題名と、どの点検に落ちたかは出ていない**。
2. `retryTitleOnce` の指示は「主検索語が渡されたときは、その語を先頭15文字以内に置く。」だけだった。本文用の指示（`article-prompt-static.js` 1301 行）にある「分かち書きした各語を、自然な日本語で」が無い。AI は検索語をそのまま頭に貼った。
3. 作り直した題名を採るかの判定（1796〜1821 行）は、`checkLlmTitle`（字数・禁止語・同じ名詞の繰り返し）と、`lintSeo` の題名の fail の数が減ったかだけを見ていた。どちらも日本語の間の空白を見ないので、fail 0・warn 0 で採用された。
4. `validate.js` にも承認画面にも、この形を止める点検は無い。人の承認（11/13）と Claude の確認（#768 の加算税だけを見た）でも見落とした。

いまの題名をそのまま `lintSeo` と `checkLlmTitle` にかけても、どちらも「問題なし」になる（Claude が 11/14 に確認）。

## 決定（2026-11-14 利用者）

1. 日本語の文字の間に空白がある題名は、点検で不合格にする。
2. 題名の作り直しの指示に「助詞を補って自然な文にする」「検索語を空白区切りのまま入れない」を足す。
3. 題名を作り直したときは、元の題名と落ちた理由をログに残す。

本文用の指示（R5）と `validate.js` の警告（R6）は、1 と 2 を同じ形で広げたもの。

## 安全の決まり

- **T1 今の記事を落とさない。** `content/posts/` の全記事の題名で、新しい fail（R1 の「日本語の間に空白」・R2 の `title_raw_query`）も、R6 の新しい警告も出ない。
- **T2 ほかの点検の結果は変えない。** `lintTitle`・`lintSeo`・`checkLlmTitle` の、今ある判定の結果は変えない。既存の試験は期待を変えずに通る。
- **T3 AI の呼び出しを増やさない。** 題名の作り直しは、今と同じく道ごとに 1 回まで。足すのは「作り直しを始める理由」に `title_raw_query` を入れることだけ。
- **T4 空白入りの題名を採らない。** 作り直した題名が R1 か R2 に当たるときは、ほかの点がよくなっていても採らない。
- **T5 作り直しが失敗したら、今までどおり元の題名を残す。** 検索語の点検の道（1785 行〜）から仮置き（`[要レビュー] {slug}`）にはしない。仮置きの道（1762 行〜）は今のまま。
- **T6 ほかは変えない。** 要約の作り直し、本文、照合、slug、検索語の選び方、承認・公開の流れ、承認画面は変えない。
- **T7 ログには題名と点検の名前だけを出す。** 鍵・本文・出典の中身は出さない。

## 受け入れたこと（弱くなる点）

- 「2026年 確定申告」のように、人が区切りとして空白を入れた題名も R1 で落ちる。このサイトの題名は「？」「｜」で区切っていて、今の 290 本に空白入りは無い。
- 記号・英字・数字のとなりの空白は R1 では見ない（「？ 無申告」「eBay 輸出」「インボイス 2割特例」）。英字・数字を含む検索語の貼り付けは、検索語をまるごと貼ったときだけ R2 で拾う。
- 最初の題名が R1 に当たると、今の決まりどおり仮置きに落ちて、仮置きの道で 1 回だけ作り直す（今ある道）。それも当たれば仮置きのまま。検索語があるときは、仮置きの題名が `title_missing_query` に落ちるので、検索語の点検の道でもう 1 回作り直す（前からの動き。道ごとに 1 回は変わらない）。そこでも採られなければ仮置きのままになり、承認画面で止まる（レビュー L4）。
- 仮置きの道は今のままにするので、R2 だけに当たる題名（英字・数字のとなりに空白を入れた貼り付け。例「インボイス 2割特例はいつまで使える？」）はそこで採られうる。次の検索語の点検の道で作り直し、それも採られなければ、その題名のまま承認に回る。そのときは承認画面の注意書き（`⚠ SEO: title_raw_query`）と validate の警告が出る（レビュー L3）。
- 作り直しが null を返したとき、「元の題名のまま」のログは出ない。`retryTitleOnce` が自分で不採用の理由を出すので足りる（レビュー L5）。

## 対象外（記録だけ）

- 承認画面に題名の点検の結果を出すこと。
- 「バレない」のように、記事の結論と逆向きの語を検索語に選ぶことの是非（題材選びの話）。
- 公開済みの記事の題名の見直し（今は該当なし）。
- 差し戻しで題名だけを直す道（`scripts/lib/partial-revise.js` の `applyTitleOnly`）は、AI が書いた題名を `checkLlmTitle` に通さない。R1・R2 に当たっても validate の警告だけで、承認画面には出ない（前からの穴。人が差し戻しで頼んだ題名なので、承認画面で人が見る。別件の候補）。
