# 05 04 の差分レビューの指摘の修正

`review-04.md`（Opus 5.5 xhigh「軽微を直せばマージ可」）の Medium N1〜N3 と Low N4〜N8 を直す。N9 は記録だけ。行番号はレビュー時点（39708fdc）。

## G1（N1）ルールの部分修正の指示文が「数字を書き換えない」のまま

- `body-patches.js` の**ルールの部分修正だけ**、専用の system 文にする（超過時の短縮の指示文は今のまま）: 「渡した論点別ルールの本文に合わせて、該当する文だけを直す。ルールの本文が示す金額・割合・期限・年は、ルールに合わせて書き換えてよい。それ以外の数字・事実は変えない。新しい事実を足さない。」（04 の「指示文を変えない」の例外として、この新しい部分修正の指示文だけは変えてよい）
- 部分修正が当たったときも、`review_warning` に「論点別ルールを部分修正で反映: <キー>（修正箇所が現行の制度に合うか確認してください）」を残す。直せなかったときの今の警告はそのまま。

## G2（N2）許す数字の範囲が広すぎる

- 許す数字を「数字＋単位」（万円・円・%・年・か月・月・日など）の組で比べる。単位なしの数字だけでは許さない。
- 許す数字の元を、**その文に当たったルールの本文だけ**にする（文ごとにどのルールが当たったかは `targetedSentences` で分かる）。
- 変えた数字は `review_warning` に「30万円→40万円（<キー>）」の形で残す（G1 の警告と同じ行でよい）。

## G3（N3）日次の本文が出力の上限で切れたときの扱い

- 本文が途中で切れたことによる例外（`assertCompleteBody` など）と、応答を読み取れない例外に `contentCandidateFailed = true` を付け、04 の F4 の「候補だけの失敗」（7 日間の除外）に回す。
- 2 種類の例外に固定の診断の文（「出力上限で途切れ」「応答を読み取れない」）を付け、0 本の通知の理由に「Error」ではなくこの文が出るようにする（鍵・本文は出さない）。

## G4（N4）402・404 もその日を終える

- `content-model.js` の「API の失敗」（その日を終える）に、HTTP 402（残高・支払い）と 404（モデル名の誤りなど）を足す。
- あわせて、同じ実行で同じ状態番号の失敗が 2 候補続いたら、その日を終える（3 候補目を試さない）。

## G5（N5）7 日間の除外の後始末

- 記録するとき（`appendWithdrawnTopics`）に、期限切れの `generation-failed-candidate` の項目を落とす。恒久の取り下げの項目は触らない。
- `data/withdrawn-topics.json` の先頭の説明文（`COMMENT`）を「日次生成で取り下げた題材。通常の選定では二度と選ばない（generation-failed-candidate は expires_at までの一時的な除外）。項目を消せば選定に戻る。」に直す（コードの定数。既存のファイルの説明文は、次に書き込むときに新しい文になる形でよい）。
- 期限を「失敗した日の日本時間の 7 日後の 0 時」にそろえる（実行の開始時刻のずれで 8 日にならないように）。

## G6（N6）Gateway の `finish_reason=content_filter` が `end_turn` に変わる

- `gateway-model.js` で `content_filter` をそのまま `stopReason: 'content_filter'` として返す（`length` は今どおり `max_tokens`）。本文を返す呼び出しでは `content_filter` も途切れと同じく失敗にする（`generate-draft.js` の今の判定が働くようにする）。

## G7（N7）日次の作り直しで 2 回目が切れると、完全だった 1 回目も捨てる

- 見出し（h2）が 0 個のときの作り直しなどで、2 回目が途切れ・読めないで失敗したときは、1 回目（途切れの検査を通ったもの）を使う。試験（`test-generation-review-fixes.js` の該当箇所）の期待も合わせて直す。

## G8（N8）差し戻しの通知の段階で落ちても「再生成処理に失敗」と届く

- `regenerate-draft.yml` の「Extract info」と「Notify via Netlify」のステップに id を付け、push の後にこの 2 つが落ちたときは「完了通知に失敗（下書きは更新済み）」と分けて通知する。

## 記録だけ

- N9: 重複確認の再試行で、Gateway では候補 1 件あたり最長 10 分、5 件で最長 50 分になる（以前は 25 分）。日次のジョブの既定の時間（6 時間）には収まる。再試行は待ち時間を置かないので 429 にはほぼ効かない。

## 試験

`scripts/lib/__tests__/test-generation-review-fixes-2.js` に G1〜G8 の試験を書く（偽の AI・偽の fetch で）。特に:

- G1: 部分修正の system 文に「ルールに合わせて書き換えてよい」が入る（短縮の指示文は変わらない）。当たったときも警告が残る。
- G2: 「30万円未満」→「40万円未満」（ルールの本文に「40万円」がある）は通る。「10万円未満」（ルールの本文に「10」はあるが「10万円」は無い）、「65%」（別の文のルールの数字）、単位なしの数字は弾く。変えた数字が警告に出る。
- G3: 途切れ・読めないで 7 日間の除外になり、通知の理由に固定の文が出る。
- G4: 402・404 でその日を終える。同じ状態番号が 2 候補続いたら終える。
- G5: 期限切れの一時的な除外が書き込みのときに消え、恒久の項目は残る。期限が日本時間の日付の境目。
- G6: `content_filter` が失敗になる。
- G7: 2 回目の失敗で 1 回目を使う。
- G8: 通知の段階の失敗の文面。

既存の試験は通ったままにする。期待を変えた場合は理由を報告する。作業中にワークフローを見張る試験（`test-workflow-change-detection.js`）の期待は変えないこと（コミット後は作業ツリーの差分が無いので通る）。
