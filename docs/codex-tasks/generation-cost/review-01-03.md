# 差分レビュー結果（generation-cost 01〜03、`feat/fact-cost-03n`..`65733b18`）

差分と、それが触る呼び出し元・呼び出し先だけを読みました。疑わしい 4 点は偽の AI でその場で動かして確かめました（OS の一時フォルダに使い捨ての台本を置き、実行後に削除。リポジトリのファイルは変えていません）。

## 1. 指摘

### High

**H1. Gateway に切り替えた後、差し戻しの再生成で本文が途中で切れても気づけない**
- 場所: `scripts/generate-draft.js:2187-2197`（`regenerateWithContentModel`）、`scripts/lib/content-model.js:370-374`、`scripts/generate-draft.js:2215-2218`（`callSimpleOpenAI` が `stopReason` を捨てている）
- 何が起きるか: `CONTENT_MODEL_PROVIDER=gateway` で差し戻しが全文の再生成（scope=full）になると、出力の上限は `max(8,100, 16,000)＝16,000` になります。DeepSeek は考える分もこの上限に入ります。上限に達しても `finish_reason=length` は誰も見ていません。
  - 全文の再生成: 切れた本文に `ensureDisclaimer` が免責文を足すので、Validate を通ってコミットされ、「対応版ができました」と通知されます。2026-06 の途切れ事故と同じ形です。
  - targeted: 本文の 60% 以上が残る切れ方だと、縮みすぎの検査を通ります。免責文が無いので Validate で落ちますが、M2 のため通知が出ません。
  - 【推測】16,000 で足りなくなる確率は測っていません。ただし根拠が 2 つあります。照合では 8,000 だと答えまで届かなかったこと（`backlog.md`）、日次の生成に 2〜7 分かかっていることです。
- 直し方: Gateway で本文全体を返す呼び出し（full・targeted・section）は、`generateContent` と同じ 64,000・15 分にする。あわせて、再生成の経路で `stopReason==='max_tokens'` なら例外にして `regenerate_failed` へ流す。指示書 R9 の「`generateSimple` は max(値, 16,000)」の決め方自体に穴があるので、指示書の訂正も必要です。

### Medium

**M1. 重複確認で、AI が答えの `slug` に `url_slug` を返すと重複を見逃す**
- 場所: `scripts/generate-draft.js:2697`・`:685`、`scripts/lib/ai-dedup.js:53`・`:135`
- 何が起きるか: 候補の情報に `slug:` と `url_slug:` の 2 行が並ぶようになりました。答えの形式は `"slug":"候補のslug"` です。AI が url_slug を返すと `r.slug === topic.slug` が成り立たず、重複の判定が捨てられて「重複なし」と記録されます。【推測】起きる頻度は不明です。
- 直し方: 候補は 1 件ずつ渡しているので、`[topic.slug, topic.url_slug].includes(r.slug)` で照らすか、1 件なら slug を問わず `duplicate` を採る。

**M2. 差し戻しの失敗通知が、再生成のステップの失敗にしか出ない**
- 場所: `.github/workflows/regenerate-draft.yml:197`
- 何が起きるか: Validate・commit・push で落ちても通知が出ません（H1 の targeted の場合を含む）。以前から通知は無く、今回の差分で足した通知の条件が狭い形です。
- 直し方: 条件を `if: failure()` にする。

**M3. 「API の失敗」の判定が広すぎて、毎日止まり続けるおそれがある**
- 場所: `scripts/lib/content-model.js:305-314`・`:132-135`・`:334`・`:352`、`scripts/generate-draft.js:2946-2947`
- 何が起きるか: `contentCallError` は、拒否（refusal）・HTTP 400・応答の形が読めない、もすべて API の失敗として扱います。R0 が挙げる認証・利用上限・429・5xx・通信・時間切れより広い範囲です。そのためその日の生成が終わります。話題は記録されないので、翌日も同じ候補が先頭に選ばれ、同じ失敗で止まる、を繰り返します（毎日通知は出ます）。【推測】選定の順位がほぼ同じという前提です。
- 直し方: `status` で分ける。401・403・408・429・5xx・通信・時間切れだけを API の失敗とし、それ以外は「次の候補へ」にする。

**M4. 短縮・部分修正の答えがコードフェンスで囲まれると、必ず失敗する（確認済み）**
