# 01 ガードを入れる

対象は `scripts/crawl-nta-qa.js`。

## A. `splitByQuestion` に「答があること」を求める

他の2つの分割関数に揃える。

```js
// splitByNumberedHeading
if (!/問/.test(body) || !/答/.test(body)) continue;

// splitByParenQuestion
if (!/（答）|【回答要旨】|【回答】/.test(body)) continue;
```

軽減税率Q&A の本文は `【答】` の形で答が始まる。`【答】` を必須にすること。

> 実データで確認済み：目次の行に `【答】` は無く、本文には必ずある。
> `【令和５年 10 月改訂】` のような改訂表示と取り違えないよう、`答` 単独ではなく
> `【答】` で見ること。

下限も 120 から **150** に上げ、他の2つと揃える。

## B. 点線の判定に実際の文字を入れる

いまの判定:

```js
if (/…{3,}|\.{6,}\s*\d+$/.test(body)) continue;
```

国税庁の PDF が使っているのは **`·`（U+00B7 MIDDLE DOT）** で、これにかからない。

```
jirei-52 の末尾: 【令和５年 10 月改訂】 ······················ 22
main に混入している gaiyo-14: ····································· 16
main に混入している jirei-42: ····································· 17
```

点線として扱う文字を広げること。少なくとも次を含める。

| 文字 | コードポイント |
|---|---|
| `·` | U+00B7 MIDDLE DOT |
| `・` | U+30FB KATAKANA MIDDLE DOT |
| `．` | U+FF0E FULLWIDTH FULL STOP |
| `.` | U+002E FULL STOP |
| `…` | U+2026 HORIZONTAL ELLIPSIS |

**末尾（`$`）に限定しないこと。** 目次の行が本文の途中に混ざる場合もある。
「点線が6文字以上続く」ことをもって目次と判断してよい。

この判定は3つの分割関数すべてで使うので、**共通の関数に切り出すこと**。

```js
const DOT_LEADER_RE = /[·・．.…]{6,}/;
function looksLikeTableOfContents(body) { ... }
```

`splitByNumberedHeading` と `splitByParenQuestion` にも同じ判定を足す
（いまは答の有無だけで見ている。重ねて持たせるほうが安全）。

## C. 本文が大きく短くなる更新を拒む（最後の砦）

A と B は「今わかっている失敗の形」しか防げない。PDF の読み順は実行ごとに変わるので、
別の形で壊れることがありうる。**中身の劣化そのものを検出する**ガードを置く。

保存の直前に、同じファイルが既にあれば読み込み、次のときは**書き込まずに既存を残す**。

```
既存の body が 300 字以上あり、
新しい body が既存の 50% 未満の長さになる
```

そのときは警告を出し、既存のレコードを維持する。

```
[warn] 本文が大幅に短くなるため更新を見送りました
       data/nta-qa/keigen/jirei-52.json  707字 → 222字
       PDF のテキスト抽出が目次を拾った可能性があります
```

見送った件数はクロールの最後にまとめて出すこと。

> 50% という比率は「目次の行は本文よりはるかに短い」という実測に基づく
> （jirei-121 は 4,827字 → 130字、jirei-52 は 707字 → 222字）。
> 国税庁が本当に本文を削った場合もここで止まるが、そのときは警告を見て人が判断すればよい。
> **黙って中身を失うより、止めて気づけるほうがよい。**

`fetched_at` だけの更新は従来どおり通ること。このガードは `body` の長さだけを見る。

## D. 既に混入している2件を落とす

`data/nta-qa/keigen/gaiyo-14.json`（241字）と `data/nta-qa/keigen/jirei-42.json`（133字）は、
いま本番のデータに入っている目次の行。どちらも `【答】` を含まない。

**手で消さないこと。** A・B を入れたうえで `node scripts/crawl-nta-qa.js --only keigen` を
実行し、正しい本文で置き換わるか、レコードごと消えるかを確認する。
（クローラの実行と結果の確認は Claude 側でやるので、Codex は実装まで）

## 期待する挙動

```
splitByQuestion に目次の行を与える
  「（コンビニ…）問52 …ますか。 【令和５年 10 月改訂】 ·············· 22」
  → その問は出力に含まれない

splitByQuestion に本文を与える
  「（コンビニ…）問52 …ますか。【答】 イートインスペースを設置している…」
  → 出力に含まれる

同じ問が目次と本文の両方にあるとき
  → 本文（【答】を含むほう）が採られる

既存 707字 のレコードに 222字 の本文を書こうとする
  → 書き込まず、警告を出す

既存 707字 のレコードに 700字 の本文を書こうとする
  → 書き込む（正常な小さい変動）

既存が 200字（300字未満）のレコード
  → 比率のガードは効かせない（元が短い資料もあるため）
```
