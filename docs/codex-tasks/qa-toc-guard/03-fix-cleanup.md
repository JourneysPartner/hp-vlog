# 03 修正：既にある混入が直らない

ガードを入れたあと `node scripts/crawl-nta-qa.js --only keigen` を実行したところ、
**新しい混入は防げたが、既にある混入は残った**。2点直す。

## 実行結果

```
[warn] 本文が大幅に短くなるため更新を見送りました
       data/nta-qa/keigen/gaiyo-23.json  822字 → 399字
[warn] 本文が大幅に短くなるため更新を見送りました
       data/nta-qa/keigen/jirei-4.json   731字 → 195字
[warn] 本文が大幅に短くなるため更新を見送りました
       data/nta-qa/keigen/jirei-8.json  2169字 → 316字
```

`jirei-4` と `jirei-8` は**ガードが正しく働いた**例（既存が正しい本文、新しい方が目次）。
これは期待どおり。

## A. 既存が目次のときは守らない

`gaiyo-23` は**既存の 822字 のほうが目次**で、新しい 399字 は `splitByQuestion` を
通ってきた本文（`【答】` を含む）。それを「短くなるから」と拒んで、**悪いほうを守ってしまった**。

`shouldSkipBodyUpdate` は、**既存の本文自体が品質チェックを通らないときは守らない**こと。

```
既存が【答】を含まない、または looksLikeTableOfContents に当たる
  → 守らない（新しい本文で置き換える）
```

品質の判定は資料によって答の書き方が違う（`【答】` / `答` / `【回答要旨】`）。
`saveEntry` は資料のキーを持っているので、それに応じて判定するか、
「答らしきものを含むか」を緩めに見る共通関数を1つ作ること。

> 判断の軸は「短いかどうか」ではなく「壊れているかどうか」。
> 壊れているものを長さで守ってはいけない。

## B. 取り込めなくなったファイルを残さない

`gaiyo-14`・`gaiyo-15`・`jirei-42` は、新しいガードによって分割結果に入らなくなった。
その結果 index からは外れたが、**ファイルは残ったまま**になっている。

```
index の keigen: 134 件
ファイル:        139 件   ← 5件が index に無い孤児
```

孤児のファイルは記事生成からは参照されない（index 経由で引くため）が、
リポジトリに残ると「あるのに使われない」状態になり、次に調べる人を惑わせる。

分割する資料（`split: true` または `splitBy` がある資料）について、
**その回の実行で書き出さなかったファイルを消すこと**。

- 消すのは `--only` で指定した資料のディレクトリだけ。他の資料には触らない
- `--limit` を付けた実行では消さない（一部しか取得していないため）
- 消したファイルは件数と名前をログに出す

```
[nta-qa] keigen: 取り込めなくなった 3 件を削除しました
         gaiyo-14.json, gaiyo-15.json, jirei-42.json
```

## テストの追加（`test-nta-qa-split.js`）

`shouldSkipBodyUpdate` に次を足す。

| 既存 | 新しい | 期待 |
|---|---|---|
| 822字・`【答】`なし（目次） | 399字・`【答】`あり | **守らない**（置き換える） |
| 822字・点線あり | 399字・点線なし | **守らない** |
| 731字・`【答】`あり | 195字・`【答】`なし | 守る（従来どおり） |
| 2169字・`【答】`あり | 316字・点線あり | 守る |

孤児の削除は、対象ファイル名を決める関数を切り出してテストすること
（実際の削除はテストしない）。

- その回に書き出した名前の集合と、ディレクトリにある名前の集合から、消す対象が求まること
- `--limit` 指定時は空になること
- 分割しない資料では空になること
