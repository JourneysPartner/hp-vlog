## 要点

`scripts/crawl-nta-qa.js` の `splitByQuestion`（軽減税率Q&Aが使う）のガードが、
同じファイルにある他の2つの分割関数より弱いのが原因です。

- **答があることを確かめていない。** 他の2つは確かめています。目次に答はありません
- **点線の判定が実際の文字と合っていない。** 国税庁の PDF は `·`（U+00B7 MIDDLE DOT）を
  使っていますが、いまの正規表現は `…`（U+2026）と `.`（U+002E）しか見ていません

すでに本番データに2件混入しており、2026-09-09 のクロール結果では17件に増えていました。
この本文はそのまま記事生成のプロンプトに渡ります。

やることは4つ。

- **A** `splitByQuestion` に `【答】` を必須にし、下限を 150字 に上げる
- **B** 点線の判定を共通関数に切り出し、`·`・`・`・`．`・`.`・`…` を対象にする。
  末尾に限定しない。3つの分割関数すべてで使う
- **C** 保存時に、既存の本文（300字以上）が50%未満に短くなる更新を**見送って警告する**
- **D** 既に混入している2件は手で消さない（クローラの実行はこちらでやります）

**C がいちばん大事です。** A と B は今わかっている失敗の形しか防げません。
PDF のテキスト抽出は実行ごとに読み順が変わるので、別の形で壊れることがありえます。
黙って中身を失うより、止めて気づけるほうがよい、という考えです。

## テストで必ず入れてほしいもの

**目次と本文の順序に依存しないこと。** 同じ問が目次と本文の両方にあるとき、
どちらが先に現れても本文（`【答】` を含むほう）が採られること。
読み順が変わることが今回の不具合の核心です。
