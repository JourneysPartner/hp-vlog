# 正本の出典はカタログに載っているものを優先する（2026-11-24）

## 背景

PR #806（ネットショップは確定申告しなかったらバレる？）で「そのまま公開」が出典ガードに止められた。

11/23 の日次生成（run 45086695901）のログ:

```
[source] 論点別選定: 延滞税 → No.9205 conf=1 (D)
[source] 論点別選定: 法定調書 → No.N/A conf=0.99 (D)
[source] 論点別選定: 無申告加算税 → No.2024 conf=0.93 (A)
[source] 論点別選定: 重加算税 → No.2026 conf=0.68 (D)
[source] 正本: No.9205 conf=1「延滞税」/ 補助3件
```

- 論点ごとの選定結果から正本を決める `splitPrimaryAndSupplements`（`scripts/lib/topic-sources.js`）は、確信度だけで並べて先頭を正本にする。
- 段 D（AI が国税庁サイトから直接探したページ）は国税庁カタログ（`data/nta-sources/index.json`）に載っていないことがある。No.9205（`taxanswer/osirase/`）はカタログ外。
- 承認時の出典ガード（`scripts/lib/source-guard.js` → `checkSourceAlignment` → `evaluateLlmAutoSource`）は、llm-auto の正本に「カタログ収録・未削除・確信度 0.9 以上」を求める。
- そのため「カタログ外の段 D が最高確信度」の記事は、生成の時点で必ず承認できない形になる。カタログ収録の No.2024（0.93）が正本なら通っていた。

#806 は手で正本を No.2024 に入れ替えて解決済み（commit e9a8e8d25）。この作業は再発防止。

## 方針

- 正本は「承認時のガードを通る候補」の中で最も確信度が高いものにする。判定は承認時と同じ関数 `evaluateLlmAutoSource` を使い、基準を二重に持たない。
- 通る候補が 1 つも無ければ、今までどおり最高確信度を正本にする（人の確認待ちになるのは今と同じ。悪くはならない）。
- ガードの判定そのもの（`source-alignment.js`・`source-guard.js`）は変えない。カタログ外の正本は今後も止める。
- 通知の文面「レビュー画面から出典を修正」は、画面に出典を変える欄が無いので誤り。実際にできることに直す。
