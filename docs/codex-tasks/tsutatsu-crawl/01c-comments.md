# 01c HTML のコメントで消された条文を取り込まない・品質の検査を新しい通達に合わせる（2026-10-16）

## 背景

- Claude が同じ取り込みを一時フォルダで再現して調べた結果（10/16）:

- 照合（#672）は通達の原文を資料として使う。消された古い条文が今の条文として資料になると、古い取扱いを「裏付けあり」にしうる。

## 方針

**国税庁のページで画面に出る文だけを取り込む。** HTML のコメントは条文として読まない。検査は新しい通達の作り（番号の形・同じ番号の配列・削除の跡）に合わせ、コメントの印が残らないことを足す。

## D1 コメントを除いてから読む

- `scripts/lib/tsutatsu-parser.js` の `parseTsutatsuPage`（基本通達用と新しい通達用の両方）と、`classifyTsutatsuPage` の番号らしい行の検出で、ページの HTML から**コメントを除いてから**読む。
- 例外: Dreamweaver の型の印（`<!-- InstanceBeginEditable name="bodyArea" -->`・`<!-- InstanceEndEditable -->` など、`Instance` で始まるもの）は、`parseExtendedPage` が本文の範囲を決めるのに使っているので残す。除くのはそれ以外のコメント。
- 閉じていないコメント（`<!--` の後に `-->` が無い）は、ブラウザと同じく、そこからページの終わりまでをコメントとみなす（画面に出ないため）。
- `hasNtaBody` はもうコメントを除いているので、動きを変えない。
- 目次ページの読み方（`parseIndexPage`）は変えない。

## D2 コメントの中だった条が消えるのを、正しい減少として受け入れる

D1 で、コメントの中にしか無かった条（例: 相続税法基本通達 28-1）はカタログから消える。今の「項目の減少（または消えた番号）のため既存のカタログを保持」（`scripts/crawl-nta-tsutatsu.js` 221〜238 行）のままだと、基本通達は毎回止まる。

- 消えた番号のうち、**前のカタログの本文にコメントの印（`<!--` か `-->`）があったもの**は、正しい減少として受け入れる。ログに「コメントの中だった番号」として番号を全部出す。
- 件数の比較（`count(byNo) < count(previous)`）からも、受け入れた分を引いて比べる。配列の番号は、前のカタログで配列の中のどれかにコメントの印があれば、その番号の減った分を受け入れる。
- それ以外の減少・消えた番号は、今どおり既存を保持して止める（安全側を弱めない）。
- 受け入れた番号は、取り込みの PR で見えるようにする: `GITHUB_OUTPUT` に `comment_removed=<件数>` を足し、`.github/workflows/crawl-nta-tsutatsu.yml` の「Open PR」の本文に「コメントの中だった条（国税庁のページで画面に出ない条）を除いた件数: N 件」の 1 行を足す。番号はログに全部出す。ワークフローの変更はこの 1 行だけにする。

## D3 中身の同じ重複を 1 つにする（新しい通達）

- `provisionsByNumber` の新しい通達用の分岐で、同じ番号の 2 つ目以降が、見出しと本文が前のものと**完全に同じ**なら足さない（最初の URL を残す）。中身が違うものは今どおり配列で持つ。
- `duplicates` の記録は、取り込んだ条の重複（今どおり）のままでよい。

## D4 品質の検査（`test-tsutatsu.js` Test 9）を新しい通達に合わせる

- 同じ番号の配列は、中の 1 件ずつを条として数える（見出し・本文・URL の検査とも）。
- 番号の形は、その通達の取り込みと同じ判定で見る。新しい通達用の判定（`looksLikeExtendedProvisionNo`）を `tsutatsu-parser.js` から書き出し、通達の種類（`hyoka`・`sochi_*`）を渡して使う。基本通達は今の判定のまま。
- 削除の跡（本文が「削除」で始まる、または「により削除」を含み、本文を除くと短いもの）は、見出しが空・本文が短いの検査から外し、件数を別に出す（失敗にしない）。削除の跡でない条の見出し・本文の検査の基準（空 0 件・短い 2% 以下）は変えない。
- 新しく足す: すべての通達で、本文にコメントの印（`<!--`・`-->`）が残る条が 0 件。
- カタログの場所を環境変数 `TSUTATSU_DIR` で変えられるようにする（無ければ今の `data/nta-tsutatsu`）。Claude が一時フォルダの取り込みを検査するため。

## 変更してはいけないもの

- 読み落とし・取得の失敗・項目 0 件・リンク切れの許容範囲で止める安全側。
- 番号の形の判定そのもの（D4 で書き出すだけ）。
- 目次ページの読み方、取得の間隔、ファイルの形（`provisions` の番号 → 条または配列）、検索の索引の形。
- `data/`・`content/posts/*.md`・既存の `fixtures/`（`expected.json` と 66 ページ）。
