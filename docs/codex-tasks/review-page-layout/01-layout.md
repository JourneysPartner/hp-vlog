# 01 レビュー画面の照合の並べ方と見せ方

対象: `netlify/functions/review-page.js` だけ（と試験）。背景と数字は `README.md`。

## R1 画面の並び

`renderReviewPage` の並びを次にする。

1. ヘッダー（今のまま）
2. 更新案の案内と「変更箇所」（`refreshBanner`。今のまま。更新案のときだけ）
3. **照合の要点**（R2。短い）
4. メタ情報のカード（今のまま）
5. 記事本文のカード（今のまま）
6. **事実の照合（詳細）**（R3。今の `renderFactCheck` の中身を土台にする）
7. 修正コメント・結果・操作ボタン（今のまま）

- 更新案の画面でも「変更箇所」は照合より前のまま（`test-fact-check.js` R6 の `変更箇所</div>` < `事実の照合</div>` を保つ）。
- 既存の書き出し `renderFactCheck(meta, record, body)` は残し、詳細の欄（R3）を返すものにする。要点は新しい関数 `renderFactCheckSummary(meta, record, body)` を足して書き出す。`renderReviewPage` の引数は変えない。

## R2 照合の要点（本文より前）

承認の判断に要るものだけを、本文より前に出す。

- 常に出すもの（数行以内）:
  - 状態（照合済み／要修正／未実施／照合の記録なし）。今の `labels` と同じ言葉。
  - 本文を照合が書き換えた件数（「直した」と「資料が無く案内に変えた」を分けて数える。`corrections` の `generalized` で分ける）。
  - 人が確かめる箇所の件数と、その内訳（R4 の分け方の件数）。0 件なら出さない。
  - 「詳細は本文の後ろ」として詳細の欄（`id="factCheck"`）へ移るリンク。
- 止める理由があるときは、**中身ごと**ここに出す（畳まない）:
  - 残った食い違い（`remaining` の `食い違い`・`期限の書き漏れ`）: 今の詳細の欄と同じ赤の表示（文・正しい内容・根拠）。
  - 未解決の資料なし（`remaining` の `資料なし`）: 今と同じ黄色の表示。
  - 状態が要修正（`revise`）のとき、または `meta.fact_check_blocking` が真のとき: 「照合で承認が止まっています」の一文を赤で。
  - 未実施（`not_run`）・古い記録（`stale`）・読めない記録（`read_error`）: 今と同じ文言を黄色で。
- 照合の記録が無いとき: 「照合の記録なし」の一行だけ。
- 長い要約の行（`fact_check_summary`。「主張 58 件: 裏付けあり 39・…」）は要点に出さず、詳細の欄に置く。

## R3 事実の照合（詳細。本文の後ろ）

今の `renderFactCheck` の中身を、本文の後ろのカードに置く。中の並びは変えない（直した箇所 → 資料が無く案内に変えた箇所 → 残った食い違い → 人が確かめる箇所。`test-fact-real-run-fixes.js` E4 の並びの検査を保つ）。

- 状態・要約の行・直した箇所・資料が無く案内に変えた箇所・残った食い違いは、今の表示のまま開いて出す（件数が少ないため）。
- 人が確かめる箇所は R4 のとおり畳む。

## R4 人が確かめる箇所

- `<details>`（最初は閉じている。`open` を付けない）に入れる。開く前の一行（`<summary>`）に、件数・内訳・「承認を止める理由ではありません」を書く。例: 「人が確かめる箇所 35 件（資料が見つからなかった 20・件数の上限で照合しなかった 15）。承認を止める理由ではありません」
- 状態で分けて出す。分け方と見出し:
  - `資料なし` → 「資料が見つからなかった記述」
  - `上限で未照合` → 「件数の上限で照合しなかった記述」
  - それ以外の状態 → その状態の文字をそのまま見出しにする（エスケープして）
- 各分けの中は、記事の見出し（`heading`）ごとにまとめ、記事に出てくる順（`s` の小さい順。無ければ記録の順）に並べる。見出しは 1 回だけ出す。
- 1 件の表示: 文（R5 で整えたもの）と、小さな字で「種類・制度名」。
- 候補の資料（`evidenceRefs` の結果）は、1 件ごとに縦に並べず、**1 行に区切って並べる**（例: 「見た資料: 贈与税の申告と納税・相続時精算課税の選択・…」）。リンクは今と同じく `https://` のものだけ。抜粋（`blockquote`）は今と同じ条件（引用があるとき）だけ出す。
- 今ある一文「この一覧は承認を止める理由ではなく、他に承認を止める理由がなければ承認できます。」と見出し「人が確かめる箇所（資料が見つからなかった記述）」の文字は残す（E4 の試験が見ている）。ただし上限で照合しなかった分も含む一覧なので、見出しは「人が確かめる箇所（資料が見つからなかった記述・照合しなかった記述）」のように足してよい。足す場合は E4 の期待もそれに合わせ、理由を報告する。

## R5 表示する文から書式の記号を除く

画面に出す文（直した箇所の前・後、残った食い違いの文、人が確かめる箇所の文）だけを整える。記録そのものは変えない。

- 書式のタグだけを除く: `strong`・`em`・`b`・`i`・`u`・`mark`・`span`・`br`・`a`・`sup`・`sub`（開き・閉じ・属性つきのどれも）。**それ以外のタグ（`script` など）は除かずに、今どおりエスケープして文字として出す**（E4 の `&lt;script&gt;記述&lt;/script&gt;` の検査を保つ）。
- Markdown の強調の記号（`**`・`__`）を除く。
- 行頭の箇条書きの印（`- `・`* `・`1. ` など）を除く。
- 表の行（`|` で始まり `|` で終わる行）は、両端の `|` を除き、間の `|` を「／」にする（例: 「110万円以内 ／ 通常は不要」）。
- 整えた結果が空になったら、元の文をエスケープして出す。
- 整えたあとに今までどおりエスケープする。

## 変更してはいけないもの

- 照合の記録の形と、`scripts/lib/fact-check.js`・`scripts/generate-draft.js` の処理。
- 承認の差し止め（`review-approve-background.js`）と、承認ボタンの有効・無効の条件。
- メタ情報のカード・記事本文の描き方・操作ボタン・更新案の「変更箇所」。
- `fetchFactCheck`・`factEvidenceExcerpt` の動き（抜粋は引用の前後だけ、を保つ）。
- 既存の書き出し（`renderReviewPage`・`renderFactCheck`・`parseFrontmatter`・`fetchFactCheck`）の名前と引数。

## 試験（新しく `scripts/lib/__tests__/test-review-page-fact-layout.js`）

試験データは `docs/codex-tasks/review-page-layout/fixtures/`（10/16 の実際の下書きと照合の記録。変更しない）。画面は `parseFrontmatter` → `marked` → `renderReviewPage(…, record)` で描く（`handler` の 497〜526 行と同じ順）。

1. 実データ: 本文のカード（`id="articleBody"`）より前の部分を、タグを除いて文字だけにすると、照合の部分（要点）が 600 字以内。人が確かめる箇所の 35 件の文は、どれも本文のカードより前に無い。
2. 実データ: 35 件が全部（R5 で整えた文として）本文のカードより後ろにあり、`<details>` の中にある。その `<details>` に `open` が無い。開く前の一行に 35・20・15 の件数がある。
3. 実データ: 画面全体に `&lt;strong&gt;`・`&lt;/strong&gt;` が無い。表の行「110万円以内 ／ 通常は不要」が出る。
4. 実データ: 要点に「案内に変えた」1 件が数として出て、詳細の欄に前・後の文が出る。要点に長い要約の行（「主張 58 件」）が無く、詳細の欄にはある。
5. 止める理由が本文より前に出る（それぞれ別の記録で）: 残った食い違い（赤・文と正しい内容）／未解決の資料なし／状態が要修正／`fact_check_blocking` が真／未実施／古い記録（本文のハッシュ違い）／読めない記録。どれも本文のカードより前に出る。
6. 記録なし: 本文より前に「照合の記録なし」の一行だけ。
7. 承認ボタン: 1〜6 のどの画面でも、承認ボタンの `disabled` の有無が今と同じ（今の `approvalDisabled` の条件だけで決まる）。
8. エスケープ: R5 で除くタグ以外（`<script>`・`<img>`）は除かれずエスケープされる。`javascript:` のリンクは出ない。属性つきの `<strong class="x">` も除かれる。
9. 状態で分ける: `資料なし` 2 件・`上限で未照合` 1 件・知らない状態 1 件の記録で、3 つの見出しに分かれ、知らない状態の文字がエスケープされて見出しになる。同じ見出しの 2 件で、記事の見出しは 1 回だけ出る。

既存の試験（README の「コードの入口」に並べたもの）はすべて通すこと。並びが変わったために期待を直す場合は、直した箇所と理由を報告する。期待を弱める（検査を消す・緩める）直し方はしない。
