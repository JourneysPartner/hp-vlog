# レビュー画面: 照合の一覧が記事本文の前を埋める問題（2026-10-16）

## 背景

- 10/16 09:05 の日次生成（PR #680「生前贈与の現金のやり方」）は、照合（#672）が本番で初めて動いた下書きです。
- 毛利さんの指摘: レビュー画面が「記事の体をなしていない」。
- 実測（本番のレビュー画面を取得して文字だけにしたもの）:
  - 画面全体 約 14,000 字のうち、**記事本文が始まるまでに約 8,500 字**。その大半が「人が確かめる箇所」35 件。
  - 35 件の 1 件ごとに、候補の資料名が 7〜8 個ずつ縦に並ぶ（35 件 × 約 8 行）。
  - 文の切れ端に太字の記号が残る（「`</strong>` 選ぶ場合は別の届出が必要です（後述）。」が画面に `&lt;/strong&gt;` として出る）。表の行は「| 110万円以内 | 通常は不要 |」のまま出る。
  - 35 件の内訳は「資料が見つからなかった」20 件と「件数の上限で照合しなかった」15 件。どちらも同じ見出し「資料が見つからなかった記述」の下に混ざっている。
- 原因: `netlify/functions/review-page.js` の `renderReviewPage` が、照合の欄（`renderFactCheck`）を丸ごと、メタ情報と記事本文の前に置いている（276 行付近）。照合の欄の中身は 03 R6・03e E4 の指示どおりだが、件数が 35 件になる場合を想定していなかった。

## 方針

レビュー画面を開いたら、まず記事が記事として読めるようにする。照合は「承認を止める理由」だけを上に出し、細目は本文の後ろに置いて、件数の多い一覧は畳む。

- 照合の記録（`data/fact-check/<slug>.json`）の形・照合の処理（`scripts/lib/fact-check.js`）・承認の差し止め（`review-approve-background.js`）は**変えない**。変えるのは画面の並べ方と見せ方だけ。
- 承認を止める理由（残った食い違い・未解決の資料なし・要修正・未実施・古い記録・読めない記録）は、今までどおり本文より前に出す。隠したり畳んだりしない。

- 照合の記録の形、照合の処理、承認の差し止めを変えない。
- 画面に出す文字は今までどおり全部エスケープする。`javascript:` などの危ないリンクを出さない（03e E4 の試験を保つ）。
- 新しい依存関係を足さない。画面の開閉はブラウザの標準の `<details>` で行い、スクリプトを足さない。
- `data/`・`content/posts/*.md`・`fixtures/` を変更しない。
