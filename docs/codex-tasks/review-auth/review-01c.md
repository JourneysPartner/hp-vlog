### 2. 修正で新しく入った問題

**Low-1：古い全体の記録を読んでいる間は「もう一度お試しください」が続き、IP の枠だけが減る（推測を含む）**
- **場所：** `review-auth.js:240`（eventual の読み込み）と `:254-256`（IP、全体の順の書き込み）
- **何が起きるか：**
  - 全体の記録（`global`）は、ログインを試すたびに書き換わります。1 回間違えた直後に正しいパスワードを送ると、古い版を読みやすくなります。すると全体の書き込みが 412 になり、429「もう一度お試しください」が出ます。
  - 反映の遅れは最大で約 60 秒です。この数字は `admin-list-analytics.js:41` の注記によるもので、実際の長さは確かめていません。その間は、何度押しても 429 になります。
  - このとき IP の記録だけ新しい版が読めていると、IP の書き込みは通り、照合をしないまま数が 1 つ増えます（推測）。何度か重なると IP の上限の 5 回に届き、15 分止まります。前に 2〜3 回間違えていると届きやすくなります。
  - 照合に進むことはなく、守りは保たれています。01b の strong の読み込みでは、本当に同時に送られたときにしか起きませんでした。
- **直し方の案：**
  - 全体の書き込みが 412 になったら、直前の IP の書き込みの戻り値の `etag` を `onlyIfMatch` に付けて、IP の記録を元に戻す。ほかの要求が先に書いていれば 412 で戻らないだけなので、数え漏れは起きません。
  - 最低限としては、文言を「1 分ほど待ってからもう一度お試しください」にする。

**Low-2：書き込みの失敗（400・401・403・404 など）で、503 の画面ではなく関数の時間切れになる見込み（推測）**
- **場所：** `review-auth.js:80-81`
- **何が起きるか：**
  - 例外は、SDK の中の `fetch` から投げられます。前回確かめた SDK の再試行は、5xx と 429 のときに 5 秒待ち、最大 5 回やり直します。
  - 例外のときも同じようにやり直すなら、401 や 403 が続く場合は 25 秒以上かかります。関数の時間切れで、Netlify のエラー画面になります。試験が `NODE_ENV=test` で SDK の待ち時間を短くしているのは、この経路を通るためと読めます。
  - どちらの場合も照合には進みません。前は 4xx でも「書けた」扱いで照合まで進んでいたので、安全な側に変わっています。
- **直し方の案：**
  - `fetch` の包みを `login` の呼び出しごとに作り、PUT が失敗したら印を残して 412 の応答を返す（412 なら SDK はやり直しません）。
  - `set` の戻り値を見る前に印を確かめ、印があれば例外にして 503 を返す。
  - 印はモジュール全体で共有しない。同時の要求が混ざるためです。

**Low-3：レビュー画面の表の見た目が、公開サイトと違う**
- **場所：** `review-page.js:322-323`
- **何が起きるか：**
  - 表を `display: block` にすると、`width: 100%` は外側の箱にしか効きません。表の中身は、内容の幅まで縮みます。
  - 公開サイト（`assets/css/blog.css:537-547`）では、表は幅いっぱいで、最小幅は 480px です。
  - そのため、列の少ない表は左に寄って細く見え、スマホでは折り返して表示されます。
  - 横スクロール・縞・hover・枠線は効きます。表には操作が無いので、操作は壊れません。
- **直し方の案：** 見た目の差を許すなら、このままでかまいません。揃えたい場合は、除去処理が自分で包みを出します。表を開くときに `<div class="table-wrapper">` を、閉じるときに `</div>` を出します。今は表の入れ子を捨てているので、この形なら本文の枠は抜けません。

**Low-4：「戻る」で戻ったとき、ボタンが押せないままになることがある（推測）**
- **場所：** `review-auth.js:193-198`
- **何が起きるか：** 401 の画面で「戻る」を押すと、前の画面がブラウザの保存（bfcache）から戻ることがあります。その場合、ボタンは「確認しています…」のままで押せません。`no-store` の画面は普通は保存されませんが、Chrome は条件によって保存します。再読み込みすれば直ります。
- **直し方：** `pageshow` で `event.persisted` のときに、ボタンを元に戻す。

### 3. 特に見てほしい点

**G1・G4：古い記録を読んだ要求が照合に進む経路 → 見つかりませんでした（サーバの条件の扱いは推測）**
- 照合（`:263`）に進むのは、2 つの `set` がどちらも `modified: true` のときだけです（`:254-258`）。
- 古い記録を読んだ場合は、どれも照合の前で止まります。
  - `if-match` が通るのは、読んだ版がサーバの今の版と同じときだけです。古い版を読んだ要求は、中身が「止められていない」でも 412 になり、429 を返します。
  - 古い「記録無し」を読んだ場合は `if-none-match: *` が付くので、サーバに記録があれば 412 になります。
  - 古い「止められている」を読んだ場合は、書かずに 429 を返します（`:247`）。止める側なので問題ありません。
- 同時に送られた要求でも、照合は IP 5 回・全体 30 回までです（試験 `:683-696`）。
- 前提は、Blobs のサーバが条件をいちばん新しい版と比べることです。これは推測です。

**書き込みの失敗で照合に進む経路 → 見つかりませんでした**
- `set` は条件付きの書き込みで、412 以外の応答を全部「書けた」と扱います。その手前の `blobsFetch` が 200・412 以外を例外にするので、`set` が「書けた」を返すのは 200 のときだけです。
- 通信の失敗も例外のままなので、503 になります。
- サーバでは書けたのに応答が失敗し、SDK がやり直した場合は、版が変わっているので 412 になり 429 を返します。止める側なので問題ありません。
- メソッド名の大文字・小文字の違いは `toUpperCase()` で揃えています。
- 読み込みの扱いは変わっていません。読み込みの失敗も 503 になります（試験 `:715-717`）。

**普通の使い方で常に止まる経路 → コードには見つかりませんでした**
- 1 回で正しいパスワードを送る場合は通ります。
- 1 回間違えて少し後に正しいパスワードを送る場合は、Low-1 のとおり、しばらく 429 が続くことがあります。ずっと続くわけではありません。
- **本番で確かめる点（どちらも照合に進む方向ではなく、外れると全員が止まります。推測）：**
  1. edgeURL から読んだ応答に ETag が付くか。付かないと、2 回目以降のログインが毎回 503 になります（`:216`、前回から持ち越し）。
  2. edgeURL から読んだ ETag を、そのまま `if-match` に使えるか。たとえば圧縮で弱い ETag（`W/` 付き）に替わると、条件が一度も合いません。その場合、ログインは毎回 429「もう一度お試しください」になります。`analytics-store.js` も同じ組み合わせですが、`setJSON` が条件を送っていなかったので、本番ではまだ一度も試されていません。
  - **確かめ方：** 公開後に、次の 2 つを試してください。ログ（`audit`）に「ログイン記録の競合」が毎回出ていないかも見てください。
    - 正しいパスワードで 1 回でログインできる。
    - 1 回間違えて、1 分あけて正しいパスワードを送ると通る。

**G2：本文の枠を抜ける入力 → 残っていません**
- 除去後の HTML は node で実際に動かして確かめました。ブラウザでの組み立ては HTML 標準の規則で追ったもので、ブラウザでは確かめていません。
- **前回の 2 つ：**
  - `<li><div><li></div>外の文` は `<li></li><li>外の文</li>` になります。
  - `<table><table></table></table>外の文` は `<table></table>外の文` になります。
- **仲間として試したもの：** `li` の間に `blockquote`・`table`・`span`・`em` を挟む形、`dl` の中の表、表の枠の中の表、見出しの中の見出し、`<p><a>…<ul>`、表の中の `<a>` が行をまたぐ形、`<a>` の中の `<a>`。全部で 40 余りです。
- **抜けない理由：**

  - リンクなどの書式の要素は、ブラウザが後で付け直す書式の一覧から、必ず外れます。外れるのは、除去処理の閉じタグか、表の枠の区切りのところです。そのため、照合の詳細やコメント欄にリンクが広がることもありません。
