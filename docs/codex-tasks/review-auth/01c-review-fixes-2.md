## G1（Medium）条件付きの書き込みが送られていない

Claude が `node_modules/@netlify/blobs/dist/main.cjs`（10.7.9）で確かめた事実:

- `setJSON`（621 行付近）は `makeRequest({ ...conditions, … })` と条件を展開して渡す。`makeRequest`（314 行付近）は `conditions` という名前でしか受け取らないので、`if-match`・`if-none-match` が付かない。**本番では条件の無い書き込みになり、同時の要求は全部照合まで進む。**
- `set`（584 行付近）は `conditions` をそのまま渡すので、条件が効く。
- ただし `set` も、条件付きのときは 412 以外のどの応答（400・401・403・404・500 など）も `{ modified: true }` で返す（609 行付近）。

直し方:

- 書き込みは `store.set(key, JSON.stringify(record), condition)` にする（読む側の `getWithMetadata(key, { type: 'json' })` はそのまま）。`setJSON` は使わない。
- `getStore` に `fetch` を渡す（型は `main.d.ts` 59 行付近 `fetch?: Fetcher`）。その `fetch` は、本物の `fetch` を呼んだ後、**書き込み（PUT）の応答が 200 と 412 以外なら例外を投げる**。読み込みの扱いは変えない（ライブラリの今の扱いのまま）。例外は今どおり 503 になり、照合に進まない。
- `connectLambda(event)` で本番の接続情報を入れる流れは変えない（`fetch` を足すだけ）。
- 試験は、**偽のストアではなく本物のライブラリ**に、偽の `fetch` と接続情報を渡して作る（`connectLambda` 相当の環境の作り方は、ライブラリの `dist` と既存の `track-visit` の試験を参考に）。偽の `fetch` は etag と `if-match`・`if-none-match: *` を本物どおりに扱う（合わなければ 412）。確かめること:
  - 書き込みの要求に、記録があるときは `if-match: <etag>`、無いときは `if-none-match: *` が付いている。
  - 同じ IP から誤ったパスワードを 200 件同時 → 照合が呼ばれるのは 5 回以下。IP ばらばらの 200 件 → 30 回以下。
  - 書き込みの応答が 403・500 → 照合が呼ばれず 503。
  - 01b の偽のストアの試験は残してよい（消さない）。

範囲外（記録だけ）: `netlify/functions/lib/analytics-store.js` も `setJSON` に条件を付けている（186・212 行付近）。同じ理由で条件が効いていない見込み。今回は直さない。

## G2（Low）本文の枠の外に出る入力

レビューで示された入力（除去後の HTML を node で確認、ブラウザの組み立ては HTML 標準の規則で追ったもの）:

| 本文 | 何が起きるか |
|---|---|
| `<li><div><li></div>外の文` | 2 つ目の `<li>` が 1 つ目の `li` を `div` ごと閉じ、残った `</div>` が本文の枠を閉じる。「外の文」が枠の外に出る |
| `<table><table></table></table>外の文` | 画面が後から足す `<div class="table-wrapper">` と表の中の表の組み合わせで、最後の `</div>` が本文の枠を閉じる |

直し方（依存関係は足さない）:

- 除去処理で認めるタグから `div` を外す（中身の文は残す）。記事の Markdown（`marked`）は `div` を作らない。
- 表の中の表は認めない（外側の表が開いている間の `table` の開閉タグは捨てる。中の文は残す）。
- `li`・`dt`・`dd`・`p` の開始タグでは、ブラウザと同じく前の同じ種類の要素（`li` は同じリストの中の `li`、`dt`・`dd` は前の `dt`・`dd`、`p` は開いている `p`）を閉じてから開く。`p` が開いている間に、ブロックの要素（`ul`・`ol`・`table`・`blockquote`・`pre`・`h1`〜`h6`・`hr`・`dl`）が来たら、先に `p` を閉じる。
- 画面が後から `<table>` を `<div class="table-wrapper">` で包むのをやめる（`review-page.js` 209 行付近と 402 行付近）。横スクロールは CSS で行う: `.article-body table { display: block; overflow-x: auto; -webkit-overflow-scrolling: touch; }`（余白など、今の `.table-wrapper` の見た目に近づける）。更新案の差分（209 行付近）も同じ。
- 試験: 上の 2 つの入力と、`<dl><dt><div><dt></div>外`・`<p><table></p>外` で、除去後の HTML に `div` が無い・表の中の表が無い・同じ種類の要素が入れ子にならないこと。レビュー画面全体の HTML で、本文のカードの開始から閉じまでのタグの開閉が揃い、「外の文」が本文のカードの中にあること（文字列で確かめる。解析器は足さない）。`fixtures` の実際の下書きで、本文の表示が変わらないこと（表の包みの `div` が無くなる差だけ）。

## G3（Low）ログインのボタンの 2 回押し

- ログイン画面の nonce 付きスクリプトで、送信のときにボタンを押せなくする（`disabled` と「確認しています…」の表示）。
- 書き込みの競合（`modified: false`）のときの文言を「もう一度お試しください」にし、上限で止めたときの「しばらくしてからお試しください」と分ける（ステータスはどちらも 429 のまま）。
- 試験: ログイン画面のスクリプトに送信時の `disabled` がある。競合と上限で文言が違う。
