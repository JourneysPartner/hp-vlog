あなたは日本の税理士事務所のブログ生成システム（Node.js）の実装担当です。

作業指示は `docs/codex-tasks/multi-source/` にあります。次の順に読んでから実装してください。

1. `README.md` — 背景・実測値・**決まっている設計判断**
2. `01-selection.md` — 論点ごとの出典選定と frontmatter への記録
3. `02-guard-and-render.md` — 承認ガードの判定と、記事末の「参考」欄の表示
4. `03-tests.md` — テスト

## この作業でいちばん大事なこと

**目的は「出典を増やす」ことではなく、「問いを答えられる形に分解する」ことです。**

今のガードは「1つの出典が記事全体を覆っているか」を訊いていて、4つの論点を扱う記事にはそもそも答えられない問いになっています。だから確信度が 0.62 になり、直近の日次記事の71%が「要修正」で止まっています。

論点ごとに訊けば答えられる問いになり、正本の確信度が上がります。**確信度の基準（0.9）は下げません。** 基準を緩めて警告を消すのは目的ではありません。

## 進め方

- `01-selection.md` の A → B → C → D → E の順に実装する
- **`README.md` の「決まっている設計判断」4項目は、調査済みの結論です。** 特に「ネストした YAML リストは使えない」は、リポジトリ内の frontmatter 解析器7つを実際に調べた結果です。もっと良い書き方を思いついても、まずその節を読み直してください
- `scripts/lib/llm-source-selector.js` の `resolveSourceWithLLM` は**論点ごとに呼び分けるだけ**で、中身（Tier の順序・`DEFAULT_MIN_CONFIDENCE = 0.5`）には触らない
- コメントは日本語。「なぜそうしたか」を書く。何をしているかの説明は不要
- 既存コードのコメント密度・命名・書き方に合わせる

## 禁止事項

- `LLM_AUTO_MIN_CONFIDENCE`（0.9）を下げること
- `DEFAULT_MIN_CONFIDENCE`（0.5）や Tier A→B→C→D の打ち切り条件を変えること
- frontmatter にネストした YAML（リスト・入れ子）を書くこと
- `restoreMissingSystemFields` を複数行対応に書き換えること
- 既存記事（`content/posts/` 配下）の変更・マイグレーション
- 補助出典の確信度が低いことで承認をブロックすること
- 記事の自動公開・自動マージに関わる変更
- `assets/js/tax-simulator-boot.js` をコミットに含めること
- ビルドで生成された `blog/` 配下の差分をコミットに含めること
