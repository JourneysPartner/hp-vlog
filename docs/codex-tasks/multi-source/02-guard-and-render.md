# 02 — 承認ガードの判定と、記事末の「参考」欄の表示

## A. 承認ガードの判定

`scripts/lib/source-alignment.js` を変える。

### A-1. 判定の規則（ここを取り違えないこと）

**正本（`source_url`）の判定は今までと1ミリも変えない。**

```
正本が カタログ収録 かつ 未削除 かつ 確信度 >= 0.9   → 通す（今までどおり）
それ以外                                           → 要修正（今までどおり）
```

`LLM_AUTO_MIN_CONFIDENCE = 0.9` は**下げない**。`evaluateLlmAutoSource` の3条件も**変えない**。

補助出典（`source_2_*` 〜 `source_4_*`）は:

```
確信度が 0.9 未満の補助出典があっても、承認はブロックしない。
「この論点は出典が弱い」という注意書きを出すだけにする。
```

### A-2. なぜ補助出典でブロックしないのか

ブロックする規則（全論点が 0.9 以上でなければ要修正）にすると、論点が増えるほど警告が出やすくなり、**この作業の目的と逆の結果になる**。

この変更で実際に直るのは**正本の選ばれ方**である。

```
今:  「No.4409 は "不動産の生前贈与" 全体を覆っているか？」   → 0.62 → 要修正
後:  論点ごとに問い、最も確信度の高いものを正本にする         → 0.97 → 通過
```

問いが答えられる形になった結果、正本の確信度が上がる。基準（0.9）は一切緩めていない。

補助出典は「読者により多くの出典を示す」「生成プロンプトの裏付けを厚くする」ためのもので、**その存在が承認を難しくしてはいけない。** 補助出典が無かった昨日までと比べて、承認が通りにくくなる記事が1本でも出たら、それは実装を間違えている。

### A-3. 注意書きの文言

既存の `taxCategoryNote`（税目が食い違うときの「ブロックしない注意書き」）と同じ扱いで出す。文言には**どの論点が弱いのかを必ず入れる**こと。「確信度が低い」だけでは人が何を直せばよいか分からない。

```
補助出典の確信度が低い論点: 登録免許税（0.62）
```

### A-4. 補助出典が無い記事

`source_2_url` が無い記事（既存265本、および論点語が取れなかった記事）は、**今までと完全に同じ判定結果になること**。新しいコード経路に入れない。

## B. 記事末の「参考」欄

### B-1. 今の状態

`templates/blog-post.html:67` が1件しか出せない。

```html
<p class="blog-source">
  参考：<a href="{{SOURCE_URL}}" target="_blank" rel="noopener noreferrer">{{SOURCE_TITLE}}</a>
</p>
```

### B-2. やること

`scripts/build.js` の `generatePost`（582行目）で、`SOURCE_URL` / `SOURCE_TITLE` の代わりに組み立て済みの HTML を渡す形にする。テンプレート側は新しいプレースホルダ1つに差し替える。

```html
<p class="blog-source">
  {{SOURCES_HTML}}
</p>
```

組み立ての規則:

| 条件 | 出力 |
|---|---|
| 補助出典が無い | `参考：<a ...>タイトル</a>` — **今までと1文字も同じ HTML** |
| 補助出典がある | `参考：` のあとに正本＋補助出典を並べる |

複数件のときの並べ方は `、`（読点）区切りの1行で良い。`<ul>` にすると記事末の見た目が重くなる。

```html
参考：<a href="...">相続時精算課税の選択</a>、<a href="...">土地家屋の評価</a>、<a href="...">贈与税の計算と税率（暦年課税）</a>
```

### B-3. 既存記事の HTML を変えない（重要）

**補助出典が無い記事265本は、この変更の前後でビルド結果の HTML が1バイトも変わらないこと。**

確認方法は `03-tests.md` に書く。`git stash` で変更前の HTML を作って差分を取る手順を必ず実施すること。

### B-4. リンクの属性

既存と同じく `target="_blank" rel="noopener noreferrer"` を付ける。タイトルは `escHtml`、URL は `escAttr` を通す（`build.js` の既存の書き方に合わせる）。

## C. レビュー画面

`netlify/functions/review-page.js` は**素朴な正規表現**で frontmatter を読んでいる（35行目）。

```js
const m = line.match(/^(\w[\w_]*):\s*"?([^"]*)"?\s*$/);
```

連番キーは1行なのでこの正規表現で読める。**この関数は変更しなくてよい。**

レビュー画面に補助出典を表示するかどうかは、この作業では**やらない**。判定理由（A-3 の注意書き）は既存の `review_warning` 経由で出るので、それで足りる。画面の作り込みは別件にする。
