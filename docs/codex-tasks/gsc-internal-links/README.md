# 検索データで選ぶ内部リンク（gsc-internal-links）

2026-11-06 毛利決定:「A（小売・建設から）と B を先に、C・D・F は並行」。この指示書は **A（内部リンク）と C（長い質問の検索語）** の実装分。B（題名・冒頭の答え）は記事の文面の修正なので別に Claude が行う。

## 背景と数字

- X の SEO ポスト（毎週、検索データを見て記事どうしをリンクする方法）を検討した結果。
- 週次サーチコンソール 20261101（期間 2026-10-02〜10-29）: 表示 3,471・クリック 77。表示のある 110 ページ中 84 が平均 4〜10 位（表示の 89%）。「あと一押しで上がる」ページがほとんど。
- 検索語が見えるのは表示の約 8%（268 回）。残りは Google が伏せる。
- 今ある文脈リンク（data/internal-link-terms.json、33 行）は「語 → 記事」の辞書で、本文に**同じ語**が出たときだけ付く。設計の確かめで、小売（公開 11 本）・建設（12 本）では検索語と同じ語が他の記事にほとんど出ず（「塗料」「ペンキ」は 0 本）、辞書を足しても新しいリンクがほぼ付かないと分かった。
- そこで **「リンク元の記事・その本文の言い回し・行き先」を 1 件ずつ指定する方式（以下「指定リンク」）** を足す。候補は Claude が週次データと本文を読んで表にし、毛利が OK を出したものだけを指定ファイルに足す（X のポストの「表を見せて OK を待つ」と同じ流れ）。

## 方針（全段階共通の厳守事項）

1. **記事の Markdown（content/posts/*.md）は 1 バイトも変えない。** リンクは今の文脈リンクと同じくビルド時に付ける。
2. **指定ファイルが空なら、ビルド結果は「全体の規則の変更 2 点」（01 の R4・R5）以外は今と同じ**であること。
3. 既存の辞書（data/internal-link-terms.json）の中身は変えない。中核記事（pickup）・関連記事・出典リンクの仕組みは変えない。
4. 本番の外部サービスへの送信なし。新しい AI の呼び出しなし（候補の選定は人と Claude が行う）。
5. 失敗の扱い: 指定ファイルの**形の誤り**（必須項目の欠け・同じ id・リンク元と行き先が同じ 等）は validate の誤り。**言い回しが本文に見つからない**（記事の更新で文が変わった等）・行き先が未公開は**警告だけ**でビルドは続ける。

## 段階

| 段 | 内容 | ファイル |
|---|---|---|
| 01 | 指定リンクの仕組み（ビルド・点検・試験）と、全体の規則 2 点（同じ行き先は 1 記事 1 回、冒頭の段落にはリンクしない） | 01-placement-links.md |
| 02 | 週次レポートに 4 節（内部リンクの候補／足したリンクのその後／長い質問の検索語／辞書の行き先の点検） | 02-weekly-report.md |

## 元に戻す方法

- 指定リンクを止める: data/internal-link-placements.json の該当行を `"enabled": false` にするか削除。
- 仕組みごと戻す: この枝のマージコミットを revert。

## 受け入れ確認（Claude が隔離の外で行う）

- 関係する試験と masters:test・validate・build がすべて通る。
- main と枝で build し、全記事 HTML の本文リンクの差を一覧にする。指定ファイルが空の状態で、差が「同じ行き先の 2 本目が消えた」「冒頭の段落のリンクが後ろの段落へ移った・消えた」だけであること。
- 指定を 1 件入れた状態で、その記事にだけリンクが 1 本増えること。
- 週次レポートを 20261101 のデータで作り、4 節が出ること。
