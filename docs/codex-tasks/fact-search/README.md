# 照合の検索の取りこぼしを直す（fact-search）

2026-10-23 毛利さん了承。照合（Opus）は今のまま、主張ごとに資料を探す検索（`scripts/lib/fact-evidence.js` の `searchEvidence`）が正しいページを候補 7 件に入れられない取りこぼしを直す。**候補の数（7 件）は増やさない**（判定に渡す資料表を増やさない＝費用を増やさない）。

## 背景

- 10/23 の日次の記事（投げ銭の税金）で、人が確かめる箇所 5 件・候補の外の資料で裏付け 1 件が出たが、内容はどれも正しかった。うち 3 件は検索の取りこぼし:
  - 「投げ銭は一般に雑所得として扱われる」（判定）→ タックスアンサー 1500「雑所得」がカタログにあるのに、主題「投げ銭の所得区分」の「所得区分」に引っぱられて、収用の補償金の所得区分（TA 3555）などが上位になり資料なし。
  - 「雑所得か事業所得かは継続性や帳簿の有無等を総合して判断する」（判定）→ 所得税基本通達 35-2（業務に係る雑所得の例示）があるのに資料なし。
  - 「給与収入が2,000万円を超える人は…申告が必要」（要件）→ TA 1900「給与所得者で確定申告が必要な人」が候補 7 件に入らず、Opus が資料表の別の主張用のページから見つけて裏付け（候補の外）。
- 過去の Opus の照合記録でも、Opus が候補の外から正しいページを見つけた例が同じ形で残っている（贈与税の基礎控除 110万円 → TA 4402 が 8 件、3割特例 → TA 6351、登録事業者は免税にならない → 消法9・基通1-4-1の2 など）。候補の外の裏付けは、兄弟の制度のページを使う危険があるため「人が確かめる箇所」に出る。数字の主張は候補の外を使えないので、取りこぼすと資料なし（止まる）になる。

## 基準（AI を使わない。リポジトリの外）

- `%TEMP%\hpstatus\search-bench\cases.json`: 過去の Opus だけの照合記録（10 記事）から作った基準。
  - **keep 712 件**: 今の検索の候補 7 件に入っていて、Opus が根拠にしたページ。直した後も候補に残すもの。
  - **target 18 件**: Opus が根拠にしたのに今の検索の候補に入らないページ（10/23 の資料なし 2 件＝手で付けた正解を含む）。拾えるようにしたいもの。
  - `articles`: 記事ごとの全主張（資料表の字数を測る用）。
- `%TEMP%\hpstatus\search-bench\bench.js <リポジトリ>`: 本物の `searchEvidence`・`buildPages` で keep・target・記事ごとの資料表の字数を出す。今の main（444afab0）で **keep 712/712・target 0/18・資料表の合計 611,483 字**（`base.txt`・`base.json`）。

## 厳守

- 候補は 7 件のまま。記事自身の資料（主出典・補助出典・`source_bundle`）を先に置く今の順番、条文・通達・TA 番号の直接の引用（`direct`）、制度名の検索（`subjectTop`）は残す。
- 特定の記事・語のための規則（この 18 件の語を並べた同義語の表や、ページ ID の決め打ち）を足さない。一般の順位づけの直しにする（照合で「条を 1 つずつ足す」方式を禁止したのと同じ考え方）。
- AI・ネットワークを使わない。判定・修正・承認の差し止めの仕組みは変えない。カタログ（`data/`）・記事（`content/`）は変えない。

## 元に戻す方法

- PR を戻せば元に戻る（検索だけの変更）。`LOGIC_VERSION` を上げるので、戻した後の照合は過去の判定の使い回しをしない。
