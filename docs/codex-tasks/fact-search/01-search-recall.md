# 01 検索の取りこぼしを直す（候補 7 件のまま）

README を先に読むこと。main（444afab0）の上に積む。対象は `scripts/lib/fact-evidence.js` の `scoreEvidence`・`searchEvidence`（必要なら `scripts/lib/nta-source-matcher.js` の `tokenizeForMatcher` の使い方）。

## 今の作り（`searchEvidence`）

候補 7 件 = 記事自身の資料の上位 3 件（主出典が先頭）→ 制度名だけの検索の 1 位（`subjectTop`、`rankSources`）→ 主張全体の点数の上位から重複を除いた 3 件（`diverse`）→ 残りの記事自身の資料。点数（`scoreEvidence`）は、主張の語（主題・要約・本文の文・`tax_terms`）が本文・題名にあるかを珍しさ（`df`）で重みづけし、**主題の語は本文 2 倍・題名 6 倍**、題名が主題名を含めば加点、別の税目は 0.15 倍、直接の引用は +10000、記事の資料の束は +5。

## 取りこぼしの形（基準の target 18 件）

- **主題が抽象的な名前**（「投げ銭の所得区分」「確定申告の要否」「贈与税の基礎控除の要否」など）だと、主題の語（「所得区分」「要否」）の 2〜6 倍の重みで、その語を題名に持つ別の制度のページ（収用の補償金の所得区分 等）が上位を占め、主張の文の中心の語（「雑所得」「給与」「110万円」）で一致する正しいページ（TA 1500・1900・4402）が 7 件に入らない。
- **題名そのものが主張の文にそのまま出る**ページ（「雑所得」→ TA 1500「雑所得」）が、題名の短さのため点が伸びない。
- 正しいページの主張全体の点数の順位は 4〜201 位（4〜7 位が 3 件＝`diverse` の 3 枠からあふれる、13〜64 位が 12 件、100 位を超えるのが 3 件＝通達 35-2・TA 6498 の 2 件）。上位は主題の語を題名に持つ別のページ（「…の所得区分」「相続時精算課税に係る贈与税の基礎控除」「社宅に係る仕入税額控除」など）。

## 要件

- **R1 候補の数・枠の順番は変えない**: 7 件、記事自身の資料を先に、`subjectTop`、直接の引用（`direct`・TA 番号）の扱いはそのまま。変えてよいのは `diverse` の 3 枠の選び方と、`scoreEvidence` の点数の付け方。
- **R2 一般の直しにする**: 例として次の方向を試し、基準で良いものを採る（全部採る必要はない。別の一般の方法でもよい）。
  - 主題の語がカタログの題名にほとんど現れない、または珍しくない語だけのとき（抽象的な主題）は、主題の語の倍率を下げ、主張の要約・文の語の重みを相対的に上げる。
  - ページの題名（記号・かっこを除いて 2 字以上）が主張の要約か文にそのまま含まれるときの加点（今の「題名が主題名を含む」の加点と対になるもの）。
  - `diverse` の 3 枠のうち 1 枠を、主題を除いた主張（要約＋文）だけの点数の 1 位にする。
- **R3 特定の記事・語のための規則を足さない**: 同義語の表（`synonyms`）・`focus` に語を足さない。ページ ID・題名の決め打ちをしない。基準の 18 件の語を並べない。
- **R4 費用を増やさない**: 基準の資料表の合計字数を今の 611,483 字の **+3% 以内**、各記事 **+8% 以内**にする（`bench.js` の「資料表」）。
- **R5 `LOGIC_VERSION`** を `plan2` から `plan2-s1` に上げる（候補が変わるので過去の判定を使い回さない）。

## 合格の基準（`node %TEMP%\hpstatus\search-bench\bench.js <リポジトリ>`）

- **keep**: 712/712 を目標。外れる場合は**最大 3 件**まで、全件を報告し、それぞれの主張に別の正しいページ（同じ制度を説明する TA・条）が候補に残っていることを示す。
- **target**: **8/18 以上**。10/23 の TA 1900・TA 1500 は**必ず**拾う（通達 35-2 は目標）。TA 4402（110万円）の 8 件の少なくとも半分を拾う。100 位を超える 3 件は無理に拾わなくてよい（そのための特別な規則を作らない）。
- **資料表**: R4 の範囲。
- 拾えない target は理由（何位にいるか、何が上に来るか）を報告する。
