1. **止める側にだけ変わるか・本文が変わらないか**: 3 か所とも、今の条件に「かつ」で足されていました。「直った」の印が使われる所（`:1924`・`:1946` の条件確認だけの修正、`:1948` の残りの計算、`:2069` の使い回し、要約、`outsideCandidateClaims`）と、行を残すことの影響を一つずつ追いました。止める判定を弱める道はありませんでした。

   - 本文、AI への頼み（種類と中身）、修正の中身（直した後の文・戻したか・修正案・2 回目の記録・理由）、`repair_retry` は全部同じでした。
   - 結果が変わったのは `ok`→`revise` の 166 件だけです。残った指摘・再照合の行・人が確かめる箇所は減らず、「直った」が false から true に変わった修正もありませんでした。
   - 照合が「実施できず」になったのは両方の版で同じ 20 件で、新しい道は増えていません（N-S6）。
   - 違いが出た形は、どれも「前に足す」か「2 回目の直しが 1 回目に誤りとされた文を一字も変えずに残した」形でした。後者は止めるのが正しい形です。
2. **含む文と行の対応の付け方**: 再照合の行の文は、変わった所の文章を `splitUnits` で分けた単位そのままです。ふつうの文章では、置き換えを分けた結果と一致します。ずれるときは「行が無い」とみなされて止める側に倒れます。起きるのは、主張が隣の文に付け替えられたときか、閉じていない括弧や強調が行をまたいだときで、どちらもまれです。止めない側に倒れる道は、前の行の閉じていない括弧で文の切れ方が変わる、という理屈の上だけの形で、そのときも main と同じ結果です。
3. **期限の書き漏れと条件確認を外したこと**: 条件確認の除外は必要です（外すと本文が変わる。L2 で再現）。期限の書き漏れを外したことで残る穴は前からある穴そのままですが、README の記録より広いです（M1）。
4. **2 回目の道との組み合わせ**: 全部を採らない予備の道（`revertAll`）では、再照合の行が空になり、修正は全部「戻した」になるので、新しい条件は効きません。元の文に戻した対象では、含む文はふつう本文に無いので、今と同じ扱いになります。残した行には必ず本文の中の文を含むものがあるので、本文に無い文が残った指摘に出ることはありません。承認画面は、残った食い違いの文・正しい内容・根拠を出すだけです。食い違った記録になるのは L1 だけでした。
5. **試験が足りているか**: L2 のとおりです。止めすぎを固定する試験はありません（T3 は README の決めたとおり）。
