# 03c 確かめの「記載なし」と、答え・落とした理由の記録（第 2 段階の続き）

README・03・review-03・review-03b を先に読むこと。03b（7f997a41）の上に積む。**既定は止めたまま**（`FACT_CHECK_CONFIRM=true` かつ書き手の資料があるときだけ動く）。既定（変数なし）・GLM だけの経路・書き手の資料が無い記事の照合は変えない。

## 背景（2026-10-22 の実地 7 本、記録 `fcq2-*`・`fcq-*-seeded`）

- 1 本 11〜37 円（平均 約 18 円）。Opus が書き換えた 5 件はすべて正しく、害の書き換えは 0。だが **7 本とも revise**。
- 確かめ 65 件の内訳: 書き換え 5・残す 4・**Opus 自身が判断できない 26・機械の確かめで落とした 29**・同じ文の答えの不一致 1。
- Opus 自身の判断できない 26 件の多くは「資料に記載が無い」。そのうち少なくとも 12 件は**正しい内容**で、カタログにはあるのに Opus に見せた資料に入っていなかった:
  - 贈与税の速算表 5 行（株の記事）: 確かめに渡す全体の検索が、記事の前付けの手がかり（`tax_terms`「…相続時精算課税」・`source_url`・`source_bundle`）に引っ張られ、精算課税のページ（相法21の13・措法70の3の2 等）だけを返した。手がかりを外した検索では No.4402・相法21の7・**No.4408（贈与税の計算と税率）**が上位に来る。
  - 取消届出書の「15日前」（一人親方）: 消法57の2 の抜粋が、登録申請の段落（政令で定める日）を選び、取消しの段落を選ばなかった。法令の本文は漢数字（「十五日前」「二百万円」）で、抜粋の選び方は記事の「15日前」「200万円」と一致しない。
  - 消費税率 10%（試算の前提）: 同じく手がかりの無い検索なら No.6102（軽減税率制度、標準税率 10%）が上位に来る。
  - ほか: 3割特例が令和8年度改正で新設・法人は不可、令和8年10月1日以降 70%、2割・3割特例はインボイスの保存不要、土日祝で延長されない、など（カタログに 3割特例のページが無いものを含む）。
- 残りは書き手の判断の目安・実務の助言（「1件100万円以上の現場なら登録」「登録すると損は誤解」「通帳を親が管理していれば認められにくい」など）で、資料に記載が無いのは当然のもの。
- **機械の確かめで落とした 29 件は、Opus の答えも落とした理由も記録に無く、原因が分からない**（記録は「確かめの引用・数字・修正文を採れませんでした」だけ）。コードから考えられる候補: ①計算した数字（「1着あたり3,300円」「売上1,000万円なら30万円」「12月17日」など。引用の近くに数字が無い）②Opus がその指摘の候補ではないページ番号を引いた（同じ回の別の指摘の資料）③M2（`canFinalizeStageA`、要件・判定・手続の「正しい」も書き手の資料の 1 位か題名の一意な一致が要る）④文の番号が抜粋の外。どれが多いかは記録が無いと決められない。
- 同じ文の不一致 1 件は本物の誤りの修正（結婚・子育て資金「令和11年」→「令和9年」）を止めた。同じ文の別の主張（18歳以上50歳未満）に Opus が「正しい」と答えただけで、`applyConfirmations` が「一致しない」とした。

## 方針

1. **記録（R1）**: Opus の答えそのもの・Opus に見せた資料・答えを採らなかった理由を、指摘ごとに残す。次の直しはこの記録で決める（今回は M2 や候補の外のページの制限を緩めない）。
2. **記載なし（R2）**: 「資料なし」の指摘で、Opus が見せた資料に裏付けも否定も無いと答えたときは、Opus が具体を外した文で書き換える（止めない）。毛利さんの方針「細かい具体は記事に載せない／誤りは AI 自身が修正まで」に合わせる。
3. **正しい内容を消さない歯止め（R3）**: 記載なしで書き換えるのは「カタログにあるのに見せていない」を減らしてから。資料なしの指摘に、手がかりを外した全体の検索を加え、抜粋は漢数字も数字として選ぶ。表の行は具体を外さない。外す文が多い記事は外さない。
4. **同じ文（R4）**: 同じ文の別の主張が「正しい」なら、その主張の数字を残す書き換えは止めない。

## R1 記録

- **R1-1** 確かめた指摘ごとに、`claims[].confirm` に次を足す（今の `verdict`・`reason` はそのまま。`verdict` は最終の扱い）:
  - `answer`: Opus の答えそのもの `{verdict, evidence, evidence_id, basis, replacement, reason}`。`evidence` は Opus が書いた資料番号、`evidence_id` はその番号を引き直した資料の id（引けなければ空）。各値は `redactSecrets` を通し 600 字まで。Opus の答えが無いとき（呼び出しの失敗・形の不正など）は付けない。
  - `rejected`: Opus の答えを採らなかったとき・答えが得られなかったときの `{code, detail}`。`code` は下の表のどれか 1 つ（最初に引っかかったもの）、`detail` は日本語の短い説明（`repairBody` の理由・例外の文は鍵を伏せて 200 字まで）。
  - `pages`: その指摘に見せた資料 `[{number, id, title}]`（最大 12 件）。`call`: 何回目の呼び出しか（1 から）。
- **R1-2** `code` の一覧（この名前で固定し、試験で 1 つずつ確かめる）:

| code | 意味 |
|---|---|
| `page_not_offered` | 答えの資料番号が、その指摘に見せた資料に無い（同じ回の別の指摘の資料を含む） |
| `rewrite_source` | 書き換え・要件などの「正しい」の根拠が、書き手の資料の 1 位でも題名の一意な一致でもない（03b M2） |
| `basis_unreadable` | 文の番号が読めない・抜粋の外 |
| `quote_missing` | 引用が資料に無い |
| `quote_insufficient` | 引用が短い・主張の数字が引用の近くに無い |
| `replacement_missing` | 誤り・記載なしなのに修正文が無い |
| `replacement_numbers` | 修正文の数字が読めない・引用の近くに無い |
| `not_stated_status` | 資料なし以外の指摘への記載なし（R2-1） |
| `not_stated_table` | 表の行への記載なし（R2-3） |
| `not_stated_limit` | 記載なしで外す文が多すぎる（R2-5） |
| `repair_rejected` | 本文の保全・数字の確かめ（`repairBody`）を通らない。`detail` に理由 |
| `same_sentence` | 同じ文の答えが一致しない（R4） |
| `secret` | 修正文に鍵の形の文字列 |
| `answer_shape` | 答えの形が不正・その指摘の答えが無い・重複 |
| `max_tokens` | 出力が上限に達し、分けてもまた上限 |
| `call_limit` | 呼び出しの上限を超えた |
| `call_failed` | 呼び出しの失敗・時間切れ・Batch の失敗 |
| `no_material` | 確かめの資料を用意できない |
| `exception` | 上のどれでもない例外 |

- **R1-3** `record.confirm` に足す: `verdicts`（Opus の答えの数 `{誤り, 正しい, 記載なし, 判断できない}`）・`rewritten`・`generalized`（記載なしで外した数）・`kept`・`unknown`・`rejected`（採らなかった数）・`rejected_codes`（code ごとの数）・`stop_reasons`（呼び出しごと）。トークンの合計は、`usage` のある呼び出しだけを足し、`usage_complete`（全部にあったか）を付ける（03b N3）。
- **R1-4** 要約の確かめの部分を 1 つにまとめる（03b N4）: `・Opus の確かめ ○ 件（書き換え ○・具体を外した ○・残す ○・判断できない ○、うち答えを採らなかった ○）・○ 回`。
- **R1-5** 記録・ログに鍵を出さない。Opus の答えの全文や資料の本文はログ（標準出力）に出さない（記録の JSON だけ）。

## R2 記載なし

- **R2-1** Opus の答えに `記載なし` を足す。使えるのは、確かめに回った指摘の状態が `資料なし`（数字・要件・判定・手続）のときだけ。食い違い・期限の書き漏れ・条件の不一致への記載なしは採らず（`not_stated_status`）、今の判断できないと同じ扱い（03b H1 のまま）。
- **R2-2** 確かめの指示文に足すこと（意味）:
  - 記載なし＝見せた資料のどれにも、この主張の具体（数字・日付・期間・条件・様式名・判断の目安）を裏付ける記載も、否定する記載も無いとき。似た制度・別の時期・別の対象の記載は裏付けにも否定にもならない。資料を最後まで読んでから決める。
  - 記載なしのときは `replacement` に、元の文から資料に無い具体だけを外した 1 文を書く。裏付けのある内容と数字、文の役割（誤解の例・注意・手順・試算）と話題は残す。資料の外の知識で書き足さない。外すと文が成り立たないときは `replacement` を空にする。
  - 記事が自分で置いた前提（試算・計算例の金額・件数）から計算した数字は、記載なしにしない（計算と資料の数字が合えば正しい、合わなければ誤り、確かめられなければ判断できない）。
  - 同じ文に複数の指摘があり書き換えるときは、全部をまとめて直した同じ 1 つの `replacement` を返す。
- **R2-3** 表の行（`|` で始まる行）は記載なしで書き換えない（`not_stated_table`）。具体を外した表の行は表として意味を失うため（02b〜02c で速算表を「国税庁で確認」に置き換えた害）。
- **R2-4** 機械の確かめ: 記載なしの `replacement` は、状態を `資料なし` のまま `repairBody` に通す（03b L4 と同じ。`keep`・`supported_numbers` で裏付けのある数字を守り、主張の資料の無い数字が残っていないこと）。さらに、元の文に無い数字を入れない（型を問わず）。空・元の文と同じ・通らないものは採らない（`replacement_missing`／`repair_rejected`）。
- **R2-5** 上限: 記載なしで外す文が 1 本で 8 文を超える、または主張の数の 2 割を超えるときは、記載なしの書き換えを 1 つもしない（`not_stated_limit`、今の判断できないと同じ扱い）。要約に `・資料に記載の無い具体が多いため外していません` を足す。数えるのは、機械の確かめを通った記載なしの書き換えの文の数（S6 の `tooManyMissing` と同じ 8 文・2 割の考え方）。
- **R2-6** 採った記載なし: その文を書き換え、`record.corrections` に `generalized: true`・`resolved: true` で残す（再照合はしない＝03 C5 の誤りと同じ）。`confirm.verdict` は `記載なし`、`confirmed_by` を付ける。止める対象から外れる。レビュー画面と公開済み記事の点検で、今の「具体を外した」と同じに表示されること（`test-review-page-fact-layout.js` で確かめる）。
- **R2-7** 採らなかった記載なしは、今の判断できないと同じ扱い（数字の資料なしは止める、要件・判定・手続は人が確かめる箇所）。

## R3 正しい内容を消さない歯止め

- **R3-1** 資料なしの指摘の確かめの候補（`candidatesFor`）: 今の全体の検索の上位 3 件を、**今の検索の上位 2 件＋記事の手がかりを外した全体の検索の上位 3 件**（`source_url`・`source_supplements`・`source_bundle`・`tax_terms` を渡さない。`tax_domain` は渡す）に替える。重複は除き、書き手の資料の上位 4 件・GLM が挙げたページ・Q&A の 2 件は今のまま。食い違い・期限の書き漏れ・条件の不一致の候補は変えない。
- **R3-2** 抜粋の選び方（`pageFor`）: 主張と文の数字（`normalizedNumbers` と同じ読み方。漢数字・万・億を含む）が、文の単位の数字と一致する単位を点で優先する。資料の本文は書き換えない（点を付けるときだけ読む）。例: 記事の「15日前」と法令の「十五日前」、「200万円」と「二百万円」。
- **R3-3** 1 回の上限（8 指摘・30,000 字・ページの上限）と呼び出しの上限（6 回）は変えない。

## R4 同じ文

- **R4-1** 同じ文の指摘は同じ回の呼び出しにまとめる（入りきらないときはその文の指摘全部を次の回へ）。
- **R4-2** `applyConfirmations` の同じ文の判定: 書き換える答え（誤り・採った記載なし）が同じ文に複数あれば、`replacement` が全部同じときだけ書き換える（今と同じ）。同じ文の別の指摘が「正しい」（確かめを通ったもの）なら、その主張の数字を `keep` として `repairBody` に渡し、数字が残るなら書き換えてよい（残らなければ `same_sentence`）。同じ文の別の指摘が判断できない・採らなかったものなら、今どおり書き換えない（`same_sentence`）。

## 変更してはいけないもの

- 既定（変数なし）・`FACT_CHECK_CONFIRM` 未設定・書き手の資料が無い記事の照合（呼び出し・記録・結果）。GLM だけの経路。
- 誤り・正しいの機械の確かめ（M2 の `canFinalizeStageA`・引用の実在・数字の歯止め・本文の保全）。候補の外のページの制限。今回は記録だけ足し、緩めない。
- 03b H1（食い違い・期限の書き漏れは、確かめで消えない限り止める）・承認の差し止め・fail-closed。
- 計画・資料探し・書く段階の規則・ワークフロー（`.github/workflows/`）。
