## ① 計算の確かめ（E1）

- **E1-1** 確かめの答えに `calculation`（最大 3 件の配列）を足す。各要素は `"式=結果"` の文字列（例 `"1月1日−15日=12月17日"`、`"200万円×15%−200万円×10%=10万円"`、`"330,000円÷100=3,300円"`）。数の主張の「正しい」「誤り」で、主張・修正文の数字が資料に直接書かれておらず、資料の数字や記事の前提から計算で出るときだけ使う、と指示文に足す。
- **E1-2** 機械の確かめ（`validateConfirmation`）:
  - 式は数（`normalizedNumbers` と同じ読み方。金額・万・億・%・割・分の・日付・日数）と `+ − × ÷ ( )` と `=` 1 つだけ。読めない式は採らない。
  - 金額・割合の式は分数で正確に計算し、右辺と一致すること（丸めない。「約」「前後」の数は対象外）。
  - 日付の式は「日付 ± N日」の 1 つだけ。年の無い日付は 2027 年と 2028 年の両方で計算し、両方が右辺と一致すること（2 月をまたいで食い違うときは採らない）。
  - 式の数（左辺の数）はそれぞれ、引用（Opus が引いた資料の文）か、記事の前提（その文・直前の見出し・前後の文。表の行なら同じ表の見出しの行と前後の行）に出ていること。右辺の値を左辺に使わない（その値が引用にもあるときを除く）。
  - 右辺は、「正しい」なら主張の数字（文に出ている数字）のどれか、「誤り」なら `replacement` の数字のどれかであること。
  - 計算を通った数字（右辺）と、式に使った記事の前提の数字は、引用の近くに数字が要る確かめ（`sufficientQuote` の数字の部分・修正文の数字の確かめ）から外す。残りの数字は今どおり引用の近くに要る。引用の実在・長さの確かめは今どおり。
  - 通らなければ採らない。code は新しく `calculation_rejected`（`detail` に、読めない・計算が合わない・数の出どころが無い・右辺が主張に無い のどれか）。
- **E1-3** 記録: `confirm.answer.calculation` に Opus の式を残す。

## ③ 食い違いへの記載なし（E3）

- **E3-1** 状態が食い違い（GLM）・条件の不一致の指摘で、型が要件・判定・手続のものに Opus が記載なしと答えたら、書き換えず、止めずに**人が確かめる箇所**へ出す（状態は `資料なし` にし、`confirm.verdict` は `記載なし`、`confirm.rejected` は `not_stated_status` のまま。記録で区別できるよう `confirm.review: true`）。
- **E3-2** 数字の型（金額・割合・期限・適用年・番号）の食い違い・期限の書き漏れへの記載なしは、今どおり止める（03b H1）。

## ④ 記載なしは税の具体だけ（E4）

- **E4-1** 確かめの指示文に足す: 記載なしは、税の制度の具体（税額・税率・控除額・限度額・期限・適用年・対象者や要件の条件・届出や申請の様式名・手続の順序）にだけ使う。会計・計算の一般の説明（売上原価＝期首＋仕入−期末 など）、言葉の意味の説明、記事の想定読者や構成の説明は、資料に無くても記載なしにせず「判断できない」とする。
- 機械では確かめない（指示文だけ）。試験は指示文にその文があることと、偽の Opus が判断できないと答えたとき今どおりの扱いになることだけ。

## ⑤ GLM の遅さ（E5）

- **E5-1 思考の量**: 照合の提供元が Gateway のとき、`FACT_CHECK_EFFORT`（判定・修正など）と `FACT_CHECK_EXTRACT_EFFORT`（抜き出し）を Gateway の呼び出しに `reasoning: { effort }` として渡す（今は `null` にしている）。値は今の確かめ（`low`・`medium`・`high`・`xhigh`・`max`）のまま。未設定なら今どおり送らない。
  - `scripts/lib/gateway-model.js` の `callGateway` は本文の生成（`content-model.js`）・補助（`aux-model.js`）と**共有**。引数 `reasoningEffort` を足し、渡されないときは要求の本文を今と一字一句同じにする（試験で、今の呼び出し元の要求の本文が変わらないことを確かめる）。
  - 記録の `effort`・`extract_effort` に実際に渡した値を残す。
- **E5-2 GLM が終わらないときは今の本番の照合に戻す**: 提供元が Gateway の照合が、時間切れ（`照合の時間切れ`・`GatewayTimeoutError`）・通信の失敗・Gateway の 5xx（再試行の後）で終われなかったときは、その記事を**既定の照合**（Anthropic・`FACT_CHECK_MODEL` の既定・全体の検索・Batch は今の設定のまま、書き手の資料の段 A/B と確かめは使わない）でやり直す。1 回だけ（やり直しが失敗したら今どおり not_run）。
  - 記録に `fallback: { from: 'gateway', reason: <固定の短い理由> }` を残し、要約に `・GLM の照合が終わらなかったため Opus で照合` を足す。鍵・応答本文は残さない。
  - 認証の失敗・設定の誤り（鍵が無い・未対応のモデル）は戻さず、今どおり not_run（設定の誤りを隠さない）。
- **E5-3 1 回の時間**: Gateway の 1 回の上限の既定を 900000 から 600000（10 分）にする（`FACT_CHECK_TIMEOUT_MS` で上書きできるのは今どおり、上限 900000 も今どおり）。

## 変更してはいけないもの

- 既定（変数なし）・書き手の資料が無い記事の照合（呼び出し・記録・結果）。本文の生成・補助の Gateway の呼び出し（`callGateway` の要求の本文）。
- 誤り・正しいの機械の確かめのうち ① で外す数字以外（引用の実在・長さ・M2・本文の保全）、候補の外のページの制限、03b H1（③ の要件・判定・手続を除く）、承認の差し止め、fail-closed。
- 計画・資料探し・書く段階の規則。ワークフロー（`.github/workflows/`。`effort`・`extract_effort` の入力は既にある）。
