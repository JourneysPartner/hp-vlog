## 直すもの（03f）

試験は `test-fact-plan-03.js` に「03f-H1」などの名前で足す。レビューの再現の条件（入力・偽の答え）と同じにする。

### H1 引用の確かめから外すのは、計算の答えと日付の起点だけ
- `verifyCalculations` が返す「外す数字」は、**右辺（計算を通った数字）と、日付の式の起点の日付だけ**にする。左辺の数（日数・金額・割合）は、引用か記事の前提に出ていること（出どころの確かめ）は今どおり求めたうえで、主張・修正文の数字なら今どおり引用の近くに要る。
- 試験: 上の ①〜③ が `quote_insufficient`（または `calculation_rejected`）で止まり revise。03e の正しい例（12月17日・控除額・3,300円）は今どおり ok。

### M1 同じ文で制度名が違う指摘の資料は、確かめには使わせない
- 同じ文で制度名が違う指摘の資料は、資料表（Opus が読む）には出してよいが、その指摘の `evidence_ids` と `validateConfirmation` に渡す資料には入れない（同じ制度名＝末尾のかっこ書きを外して同じ、のときだけ共有）。
- 試験: 上の住宅取得等資金と結婚・子育て資金の文が `page_not_offered` で止まる。同じ制度名の共有（12月17日の例）は今どおり採る。

### M2 やり直しの Opus は effort を既定にする
- やり直しでは effort・extract effort を未指定（Opus の既定）にする。環境変数に戻らないよう、やり直し専用の明示の指定にする。
- 試験: `FACT_CHECK_EFFORT=low`・`FACT_CHECK_EXTRACT_EFFORT=low` の Gateway の照合が時間切れ → やり直しの Opus の要求に `output_config` の effort が付かない。記録の `effort` は null。

### L2〜L4
- L2: `calculation` が空の配列・`null`・空の文字列なら「付けていない」と同じに扱う。
- L3: やり直しも失敗したら要約は `・GLM の照合が終わらず、Opus でのやり直しもできませんでした` にする。やり直しの記録に、失敗までの GLM の呼び出し（`calls[]` の task・model・usage）を `fallback.gateway_calls` として残す（鍵・応答本文は残さない）。
- L4 (c): 表の行が本文で見つからないときは、表の前提を足さない。(d): 主張の数字が全部外れたときも、資料に読めない割合があれば止める確かめは今どおり掛ける。(a)(b) は記録だけ（右辺が主張の数字と一致し、左辺の数が引用か記事に出ていることまでは求めているため）。
