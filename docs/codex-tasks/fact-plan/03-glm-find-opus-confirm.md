# 03 GLM が探し、記事を書き換える・外す文だけ Opus が確かめる（第 2 段階）

README・02・review-02〜02c を先に読むこと。第 1 段階（計画・書く段階の規則・記録を本番へ、照合は Opus のまま、段 A/B と S1〜S6 は既定で止める＝02d）の上に積む。**既定は止めたまま**作り、実地で確かめてから変数で切り替える。

## 背景

- GLM だけで照合と自動の修正を行う形（02〜02c）は、1 本 5〜10 円と安く、誤りもよく見つける。しかし GLM の判断が回ごとに揺れるため、機械の決まり（候補の外のページの制限・3 割の判定・話題の歯止め など）で「誤りなら書き換える／正しければ残す」を分けると、書き換えすぎ（正しい文を壊す・正しい内容を外す）か、書き換えなさすぎ（誤りを通す）のどちらかに穴が残った（review-02〜02c の High は 4 → 3 → 2）。
- 実例: 誤解の例を逆の意味に書き換えた／関係ない一般論に置き換えた／兄弟の制度のページ（教育資金 4510・結婚子育て 4511）の数字で正しい住宅資金の文を書き換える道／正しい「15日前」「12月17日」や贈与税の速算表を「国税庁で確認」に置き換えた／本物の誤り（配偶者控除 2,500万円・令和11年・届出で承認不要）を 3 割の判定で通した。
- 一方、記事を書き換える・外す文は 1 本 3〜20 件と少ない。そこだけ Opus に、資料に照らして 1 件ずつ確かめさせれば、安全の判断を機械の決まりではなく Opus に任せられる。

## 方針

- 抜き出し・判定（段 A/B・聞き直し・条件の確認）は今のまま GLM（`FACT_CHECK_PROVIDER=gateway`）。
- **記事を書き換える・外す前に、Opus が確かめる**（「確かめ」と呼ぶ）。対象は、修正に回る指摘すべて: 食い違い・期限の書き漏れ・数字の資料なし（具体を外す）・要件・判定・手続の資料なし（S6 で具体を外す）・条件の確認の不一致。
- Opus が「誤り」と認め、その根拠の引用と直した文が機械の確かめを通ったものだけ書き換える。Opus が「正しい」と認めたもの（資料に裏付けがある）は書き換えない。Opus が「判断できない」ものは、今の規則どおり（数字は止める・要件などは人が確かめる箇所）。
- 確かめの判断を Opus に任せるので、確かめを使うときは 02b〜02c の機械の決まりのうち「書き換えるかどうか」を分ける決まり（3 割の判定 `unrelatedCorrect`、候補の外の食い違いの制限の一部）は使わない。引用の実在・数字の歯止め・止める範囲・fail-closed は今のまま。

## C 確かめの仕組み

- **C1 切り替え**: `FACT_CHECK_CONFIRM`（既定は止める、`'true'` のときだけ）と `FACT_CHECK_CONFIRM_MODEL`（既定 `claude-opus-5-5`、提供元は Anthropic）。確かめは `FACT_CHECK_WRITER_MATERIALS=true` のときだけ動く。
- **C2 確かめに渡すもの**（指摘ごと）: 記事の文（直前の見出し・前後の文つき）、指摘の種類（食い違い・期限の書き漏れ・資料なし・条件の不一致）、GLM の答え（根拠ページ・basis・correct。参考として）、**根拠の候補のページ**（その主張の書き手の資料の候補の上位 4 件と、GLM が挙げたページ。資料なしの指摘には、全体の検索（`searchEvidence`）の上位 3 件と国税庁 Q&A の関連する問（`findQaByKeywords` で主張の語から最大 2 件）も加える。正しい「取消届出書は…15日前まで」のように、裏付けが書き手の資料の外にある場合に Opus が見つけられるようにするため。番号つきの文で、basis の前後と主張の語の出る所を中心に 1 ページ最大 3,000 字）。
- **C3 Opus の答え**（JSON）: `{"id","verdict":"誤り|正しい|判断できない","evidence_id","basis","replacement","reason"}`。
  - 誤り: `replacement` に、根拠に合わせて直した記事の文（元の文の位置にそのまま入る 1 文。見出し・前後の文の役割＝誤解の例・注意・手順などを変えない。直す所以外は元の文のまま）を書く。期限の書き漏れは、期限を足した文。資料なしで具体を外すときは、具体を外した文。
  - 正しい: `evidence_id`・`basis` に裏付けの文を書く（書き換えない）。
  - 判断できない: 書き換えない。
- **C4 機械の確かめ**（今の判定・修正と同じ部品を使う）: 誤り・正しいのとき、`evidence_id`・`basis` の引用が資料に実在すること（`quoteExists`）、誤りのときは `replacement` の数字が引用の前後 300 字にあること（`sufficientQuote` と同じ考え方。具体を外す場合は残した数字だけ）、`replacement` が `repairBody` の保全の確かめ（表の列数・改行・長さ・見出し・本文の他の文を変えない）を通ること。通らなければ、その指摘は「判断できない」扱い。
- **C5 結果の扱い**:
  - 誤り＋確かめを通った: `replacement` で書き換える（GLM の修正の呼び出しは使わない）。再照合はしない（Opus が根拠と直した文を確かめ、機械の確かめも通っているため）。記録に `confirmed_by`・`confirm` を残す。
  - 正しい＋確かめを通った: その主張を裏付けあり（根拠は Opus の引用）にして書き換えない。条件の確認の不一致から来たものも同じ。
  - 判断できない（確かめを通らない場合を含む）: 書き換えない。数字の資料なし・数字の食い違い・期限の書き漏れは今どおり止める（revise）。要件・判定・手続は人が確かめる箇所（承認は止めない）。
- **C6 呼び出しの数と費用**: 指摘を根拠の候補のページが重なるものでまとめ、1 回の確かめに最大 8 指摘・資料は合計 30,000 字まで。即時（Batch は使わない）。effort は既定（指定なし）。上限のトークンは出力 8,000。記録の `calls[]` に `confirm`。1 本の確かめの呼び出しが 6 回を超える見込みなら、超えた分は確かめずに今の規則（止める・人が確かめる）にする（費用の上限）。
- **C7 失敗**: Anthropic の呼び出しの失敗・時間切れ・読めない答えは、その指摘を「判断できない」扱いにし、照合全体は止めない（ただし数字の指摘は今どおり止める側）。

## D 02c の残りの直し（確かめを使わないときも）

- **D1（review-02c 新M1）** 段 A と段 B の歯止めの行を足すときに `total` を 2 重に数えない。
- **D2（review-02c 新H1）** 確かめを使わないとき（GLM だけ）の `unrelatedCorrect` は、止めない扱いをやめ、止める（revise）扱いにする。数字の種類と期限の書き漏れには使わない。`01b-F2` の期待と、S5・S5-7・02b-M1・02b-L2 の試験の入力を 02b の時点に戻す。
- **D3（review-02c N1 の残り）** 確かめを使わないとき、段 B でも書き換えに使う根拠ページに N1 と同じ確認（題名の一致が一意、または候補の 1 位）をかける。

## 変更してはいけないもの

- 既定（変数なし）の照合は今の本番（Opus・全体の検索・Batch）と同じ。書き手の資料が無い記事も同じ。
- 引用の実在確認・数字の歯止め・止める範囲・承認の差し止め・fail-closed。
- 計画・資料探し・書く段階の規則・記録。

## 試験（`test-fact-plan-03.js`。偽の GLM・偽の Opus、ネットワークなし）

1. 既定・`FACT_CHECK_CONFIRM` 未設定では確かめが動かず、呼び出し・記録が今と同じ。
2. GLM が兄弟のページ（4511「50歳未満」）で正しい住宅資金の文を食い違いにする → Opus が「正しい」（4508 の引用）→ 書き換えない・裏付けあり。
3. GLM が正しい「取消届出書は…15日前まで」を資料なしにする → Opus が「正しい」（Q&A の引用）→ 書き換えない。Opus が「判断できない」→ 今どおり（期限の資料なしは止める）。
4. GLM が誤り（配偶者控除 2,500万円）を食い違いにする → Opus が「誤り」＋replacement（2,000万円）＋4452 の引用 → 書き換え、再照合なし、ok。
5. 誤解の例（「父母それぞれからもらえば枠が2倍になると考える」）を GLM が食い違いにする → Opus が「正しい」→ 書き換えない。
6. Opus の replacement の数字が引用の近くに無い／表の列数が変わる → 判断できない扱い（書き換えない、数字なら止める）。
7. Opus の呼び出しの失敗・読めない答え → 判断できない扱い、照合全体は止めない。
8. 確かめの呼び出しが 6 回を超える記事 → 超えた分は確かめず今の規則。
9. D1〜D3 の再現（review-02c の条件どおり）。
10. 記録の `confirm`・`confirmed_by`・`calls[]` の `confirm`、要約の文（`・Opus の確かめ ○ 件（書き換え ○・残す ○・判断できない ○）`）。
