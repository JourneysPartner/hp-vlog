## 直すもの（01b）

`LOGIC_VERSION` は `plan1` のまま（未マージ）。試験は `test-fact-plan-01.js` に足す（F1〜F12 の試験を、P7 の番号とは別に「01b-F1」などの名前で）。

### F1（指摘 1 High）計画の注意書きを増やさない

- 計画の注意書き（資料なしの制度・計画の失敗）は、**生成時（`buildCanonicalFrontmatter`）だけ**で書く。`recordMaterialMetadata` では足さない。
- 差し戻しの復元に失敗したときの注意書き（`restoreArticlePlan`）も、` / ` で区切った部分ごとに既にあれば足さない。`restoreArticlePlan` の資料の解決は 1 回にまとめ、その結果から 2 つのブロック（`planBlock`・`fullPlanBlock`）を作る。
- 試験: 資料なしの制度がある記事・`fact_plan_status: failed` の記事それぞれで、照合が revise（変更前の推奨は publish）→ 部分修正の差し戻しを 2 回 → 注意書きの数と `fact_check_prev_recommendation`（publish のまま）が変わらず、その後の照合 ok で `recommendation` が publish に戻る。

### F2（指摘 2 Medium）段 A の食い違い・期限の書き漏れは、全体の検索の候補にも根拠ページがあるときだけ確定する

- 段 A の答えが食い違い・期限の書き漏れで、その根拠ページ（`evidence_id`）が、その主張の全体の検索の候補（`candidates(c)`。AI を使わない）に**入っていなければ**、段 A の結果を採らずに段 B で判定し直す（今より悪くならないようにする）。
- 段 A の裏付けありは今のまま確定（候補の外の資料の扱いは今のまま）。
- 試験: 書き手の資料に正しいページが無く、別の制度のページを根拠にした段 A の食い違いが段 B に回る。全体の候補にも入るページを根拠にした段 A の食い違いは段 A のまま。

### F3（指摘 3 Medium）改正情報は判定の候補にしない

- `change:` の id は `fact_materials` に記録として残すが、段 A の候補（`searchWriterEvidence`）には入れない。
- `resolveMaterial` の改正情報の URL は `reference`（URL の部分）から取る。
- 試験: `change:` を含む書き手の資料で、段 A の候補に改正情報が入らない。

### F4（指摘 4 Medium）差し戻しの復元で資料を制度ごとに振り分ける

- 記録した制度名と、**解決できた**資料だけを入力にして、`findSystemMaterials` と同じ関連の確かめ・並べ方を AI なしで流し直し、制度ごとに振り分ける（候補の範囲は記録した資料だけ）。どの制度にも振り分けられない資料は「その他の資料」にまとめる。抜粋は制度名で行う。
- 引けない id は飛ばして続ける（ブロックを消さない）。飛ばした件数を注意書きに 1 回だけ出す（F1 の重複の規則に従う）。
- 試験: 8 制度の記事の差し戻しで、各制度の下に関連する資料が付き、どの制度にも当たらない資料は「その他の資料」。1 件引けない id があってもブロックは付く。

### F5（指摘 5 Medium）計画の資料探しの並べ方

- 並べ方: 関連の確かめ（今のまま）→ **税目の絞り込み** → **題名が当たる（条件 1 と 3）** → **種類（タックスアンサー → Q&A → 質疑応答 → 法令・通達）** → 検索の点 → 本文の出現回数。法令・通達は今どおり題名が当たるものだけ。
- 税目の絞り込み: 制度名に税目の語（贈与・相続・所得税・法人・消費税・インボイス等）があればその税目のページだけ、無ければ記事の税目（`tax_domain` から決まる 1 つの税目）と違う税目のページを外す。ページの税目は `fact-evidence.js` の `evidenceTax` と同じ決め方、Q&A は `tax_category_code`。記事の税目が決まらないときは絞らない。
- 検索の点（`scoreEvidence`）には、記事の `tax_terms` を入れない（制度名だけで点を付ける）。名前は NFKC にした形を渡す（小文字化・空白除去をしない）。
- 試験の期待（本物のカタログ、上位 2 件のどれか／両方）:

| 制度名（記事の `tax_domain`） | 期待 |
|---|---|
| ２割特例（小規模事業者に係る税額控除に関する経過措置）（invoice_system） | Q&A 問114 が入る。No.6503・消基通の貸倒れの項・No.6118 は入らない |
| 3割特例（invoice_system） | Q&A 問114-2 が入る |
| 棚卸資産の評価方法（bookkeeping_expenses） | 所得税の法令・通達（例 所令102・所法47）。法人の質疑応答・No.1110 は入らない |
| 低価法（bookkeeping_expenses） | 所基通 47-9 か 47-11。法基通は入らない |
| 贈与税の配偶者控除（inheritance_tax） | No.4452 が入る |
| 相続時精算課税制度（inheritance_tax） | No.4103 が入る |
| 贈与税の基礎控除（inheritance_tax） | 所得税の No.1199 は入らない |
| 小規模宅地等の特例（inheritance_tax） | No.4124 が入る |
| 簡易課税制度（invoice_system） | No.6505 が入る |

- 「要判断」として今の選び方を固定している試験（`test-fact-plan-01.js:421-435`）は、上の期待に書き換える。

### F6（指摘 6 Low）再照合の段 A の必須の根拠

- 必須の根拠が 4 件を超える主張は、照合全体を止めずに段 B（全体の検索、上限 7 は今のまま）に直接回す。

### F7（指摘 7 Low）段 A の判断を段 B で消さない

- 「同じ制度の期限の書き漏れは記録済み」で資料なしになった主張は段 B に回さない（段 A の結果のまま）。
- 段 A の答えが食い違い・期限の書き漏れで確認で落ち（`rejected_answer` あり）、段 B が裏付けありにした主張は、段 B の結果を採ったうえで「人が確かめる箇所」に残す（段 A の答えの種類と根拠ページが分かる形で）。承認は止めない。

### F8（指摘 8 Low）引けない id

- 記録に引けた件数（`resolved`）を残し、引けない id があれば要約に `・書き手の資料のうち引けない ○ 件` を足す。1 件も引けなければ書き手の資料が無いときと同じ今の経路（Batch あり、段 A/B なし）にする。
- `qaCatalog()` は壊れた Q&A のファイルだけを飛ばす（例外で照合全体を止めない）。
- PDF の URL だけの参照は、その URL の問が 1 つに決まるときだけ id にし、複数あるときは id にしない（記録しない）。

### F9（指摘 9 Low）計画の答えの数字を書き手への指示に入れない

- 書き手へのブロックに `why` を出さない。資料なしの制度の行に「名前に含まれる数字・期間も書かない」を足す。

### F10（指摘 10 Low）計画の呼び出しの時間上限

- 計画の呼び出しを 90 秒で打ち切る（`AbortSignal.timeout(90000)` など。content-model の `signal` を使う）。打ち切り・失敗は固定の文を 1 行ログに出し、`failed` にする。

### F11（指摘 11 Low）規則 1 の文言

- 「添付した資料（このブロックと上の資料）と、この後の論点別ルールに書いてあることだけを書く」にする。

### F12（指摘 12 Low）試験の穴

- 計画あり（既定）で Gateway の偽の通信を使い、要求が 2 回（計画・本文）あること、計画が HTTP 500 でも本文の生成が続き注意書きが付くこと、ログ・記録・前付けに鍵が出ないことを確かめる試験を足す。
- 試験名「LOGIC_VERSIONは03u」を直す。
