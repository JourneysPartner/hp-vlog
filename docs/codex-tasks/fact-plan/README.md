# 書く前に扱う制度と資料を決め、書き手と照合で同じ資料を使う（fact-plan）

2026-10-20 に毛利さんの指示（「照合の仕方・仕組みを詳細に把握した上で、今のやり方が適切か、無駄がないか、もっと適切な方法が無いか再考して」）で照合の作りを見直し、試しの結果を見て「第 1 段に進めて」となった作業。

## 1. 背景（数字）

### 1.1 いまの照合の中身（5 本、Opus 03w・03x の記録）

| 項目 | 実測 |
|---|---|
| 判定に渡した資料 | 182 ページ・約 25 万字。**根拠に使われたのは 40 ページ・字数で 29%** |
| 裏付けありの根拠が、書き手に渡した資料 | 194 件中 99 件（51%） |
| 同じ事実の繰り返し（表・本文・まとめ） | 251 件中 66 件（26%） |
| 人が確かめる箇所 | 60 件（1 本 12 件）＋上限で照合しなかった主張 18 件 |
| 費用の内訳 | 抜き出し 20%・判定 62%・修正と再照合 18%（5 本 212 円、Batch） |

### 1.2 根本の問題

1. **書き手が、渡された資料の外の制度まで書いている**。「資料に無い論点は制度名と案内まで」は指示文にあるが、確かめる仕組みが無い。#644 の既知の誤り 4 件のうち 3 件（配偶者控除の居住要件＝No.4452、生前贈与加算の段階＝No.4161、精算課税の受贈者＝No.4103）は、書き手に渡していないページの論点（書き手の資料は No.4508・4510・4511・4405）。残る 1 件（結婚・子育て資金の期限）は渡した資料にある期限の書き落とし。#642 は書き手の資料が汎用ページ（No.2210）1 枚で、在庫評価の中身はほぼ記憶。
2. **照合は書き手が何を見たかを知らない**。記録に残るのは主出典・補助出典と最大 20 件の `source_bundle`（一人親方の記事は空）。書き手には国税庁 Q&A・改正情報も渡しているが、照合のカタログに無い。
3. **後から全カタログで探す作りが重い**。主張ごとに最大 7 ページ（1 ページ最大 6,000 字）。7 割は使われない。修正後の再照合も抜き出し・検索からやり直す。

### 1.3 試し（2026-10-20、台本はリポジトリの外）

#642・#644・一人親方の題材で、「DeepSeek に扱う制度を最大 8 つ挙げさせる → 制度名でいまの検索から 2 ページずつ → 書き手への指示に足す（本番の生成コードはそのまま）」で書かせ、本番と同じ照合（Opus、main のコード）にかけた（run 39408685691・39408690650・39408695874）。

| | #642 新 / 元 | #644 新 / 元 | 一人親方 新 / 元 |
|---|---|---|---|
| 食い違い | 0 / 2 | 0 / 6 | 1 / 0 |
| 期限の書き漏れ | 0 / 0 | 1 / 1 | 2 / 0 |
| 資料なし | 2 / 15 | 2 / 4 | 10 / 13 |
| 最終 | ok / ok | **ok / revise** | revise / ok |
| 照合の円（Batch 換算） | 23 / 38 | 81 / 75 | 58 / 46 |

- 根拠のある主張の **94〜95% が書き手に渡した資料**を根拠にしていた。
- #644 は前回の誤り 3 件が出なかった（計画した制度だけを資料どおりに書いた）。
- 一人親方が悪化した原因は**資料探しの外れ**: 制度名「２割特例（小規模事業者に係る税額控除に関する経過措置）」に対し、いまの検索が「基準期間がない法人の納税義務の免除の特例」と消基通の貸倒れの項を返した（全角の「２」、長い名前、本文の語を見ない）。書き手はそのまま 2 割・3 割特例の具体を書いた。**正しいページは手元にある**（本文に「2割特例」を含む No.6351・6498・6101、インボイス Q&A の問 114〜116。「3割特例」は No.6505・Q&A 問 115-2・117）。#642 でも「棚卸資産の評価方法」に No.1110（雑損控除）が選ばれていた。
- いまの照合のままでは費用は減らない（3 本 162 円 vs 元 159 円、全体を探すため）。照合を書き手の資料から判定し、再照合を根拠ページだけにすると試算 **約 95 円（−40%）**。
- 主張が増えて上限 40 件にかかり、照合しない主張が増えた（#642 13 件・#644 9 件）。

## 2. 方針

- **書く前に**、扱う制度の一覧を作り（AI 1 回、本文と同じモデル）、制度ごとに資料を引く（AI なし）。資料が見つからない制度は書き手に「名前と案内まで」と伝える。
- 書き手に渡した資料（主出典・補助出典・計画で引いたページ・Q&A・法令・通達・改正情報）を**記録に残す**。
- 照合は、**まず書き手の資料で判定**し（段 A）、資料なしになった主張だけ今と同じ全体の検索で判定し直す（段 B）。
- 書き手の資料が記録されていない記事（公開済み記事・計画の失敗・切り替えで止めたとき）は、**今と全く同じ**照合をする。

## 4. 全段階共通の厳守事項

- 照合の判定の確かめ（引用の実在・数字が引用の前後 300 字にあるか・候補の外の資料の扱い・期限の書き漏れ）、止める範囲と承認の差し止め、fail-closed を弱めない。
- 書き手の資料が無い記事の照合は、今と同じ呼び出し・同じ結果にする（既存の試験の期待を変えない）。
- 計画や資料探しが失敗しても、生成そのものは今と同じやり方で続ける（計画は品質を上げる仕組みで、生成を止めない）。失敗はレビューの注意書きに出す。
- 鍵・トークンをログ・記録・例外の文に出さない。依存関係を足さない。
- 記事（`content/posts/*.md`）とカタログ（`data/`）は変えない。

## 5. 元に戻す方法

- リポジトリ変数 `FACT_PLAN_ENABLED=false` … 計画と計画の資料の添付を止める（生成は今と同じ。新しい前付けの項目も書かない）。
- 照合の段 A/B・S1〜S6 は**コードの既定で止まっている**。`FACT_CHECK_WRITER_MATERIALS` が未設定・空・`false` のときは、`fact_materials` があっても今と同じ照合をする。
- 動作確認のため段 A/B・S1〜S6 を使う場合だけ、リポジトリ変数 `FACT_CHECK_WRITER_MATERIALS=true` を明示する。元に戻すには変数を削除するか、空または `false` にする。照合の提供元の既定は Anthropic（Opus）のまま。
- 計画・W1〜W3・前付けへの記録は、この照合の切り替えとは独立して既定で動く。
- どちらも PR を戻せば完全に元に戻る。
