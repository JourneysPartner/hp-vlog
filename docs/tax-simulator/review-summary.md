## 実施方法

1往復を「Codexレビュー → Codex修正 → Claude Codeレビュー → Claude Code修正」とし、正式に5往復実施した。Claude側は全5回ともコマンドで `--model claude-opus-5 --effort xhigh` を指定し、レビュー記録および実行メタデータで `claude-opus-5` を確認した。

`--model opus` が実際には `claude-opus-4-8` を返した事前試行は正式回数に含めず、`rounds/preflight-*` として隔離した。

## 往復ごとの主な改善

### 第1往復

- `taxYear` 単独依存を廃止し、所得税年、住民税年度、法人事業年度、消費税課税期間、相続開始日、社会保険適用月を分離。
- 金額・率・端数処理、結果状態、警告、スナップショット再現性を定義。
- 2026年度の3割特例、7・5・3割控除、子ども・子育て支援金を成立・公布済み一次資料に合わせた。
- 相続人、役員報酬、法人内部留保、住民税前年課税の重大な誤解経路を修正。

### 第2往復

- 個人所得、法人所得、繰越欠損金、役員給与、相続税の計算順序を具体化。
- インボイス相手先別税込1億円上限と超過部分の扱いを定義。
- 外部資料のraw原本不変保存と検査用コピーを分離。
- 相続税計算を段階化し、課税価格段階と税額控除段階を分離。

### 第3往復

- 結果、適用可否、警告、除外項目、使用マスター、出典artifact、handoff、Wire型を整合。
- `professional_review` の多義性を廃止し、結果停止 `blocked`、警告重大度 `critical`、入力モード `simple/detailed` を直交化。
- ブラウザ内メモリだけで計算し、Storage API、URL、履歴、Service Worker、第三者送信経路への残留を禁止。
- 出典レビューの独立性、不可視文字、電子透かし、カナリア、トラップストリート、Mountweazel、OCR誤認の検知・隔離・再確認を規範化。

### 第4往復

- 根拠のない「概算精度：標準」を廃止し、計算済み・推定・除外・範囲・停止を表示。
- 結果通知とフォーカス移動の二重読み上げを解消。
- グラフ代替表、強制色、400%拡大、モバイル金額入力、長時間計算の中止・進捗を定義。
- 税務YMYLページの監修・訂正・緊急停止、未承認noindex、静的canonical、入力値を含まないmetadata/JSON-LDを公開ゲート化。

### 第5往復

- 4ツールの内訳型とシミュレーターサービス契約を定義。
- 純粋関数へ実行時刻と読取専用マスタースナップショットを明示注入し、暗黙参照を排除。
- `partial` の未計算値を0円として合計できない型へ修正。
- 一次資料が1点しかない場合の代替統制を定義し、複製資料で件数を水増ししない形で実装可能性を確保。
- 初期公開の対応プロフィールと、共通エンジン・マスター・個別ツール・本番公開の承認を分離。

## 外部情報の取扱い

制度値の確認には国税庁、財務省、厚生労働省等の一次資料を使用した。検索結果要約や民間シミュレーターを税率根拠に使用していない。重要根拠は仕様内の `SourceReference` 台帳、raw artifact、ハッシュ、該当箇所、独立レビュー、差分・失効管理へ接続した。

## 残課題

次は仕様レビューではなく、実装前のマスター整備・入力詳細設計・監修作業である。

- 相続税各段階の端数規則、生前贈与加算期間、小規模宅地等の限度面積等のマスター登録。
- 2割特例の対象課税期間、届出期限、役員給与改定期限、繰越欠損金、国保等の対象期間・対象者別マスター登録。
- 対応プロフィール外を確実に検知するスクリーニング設問の列挙。
- `ExcludedItem` と入力項目のコードカタログ、マスタースナップショット索引、4入力スキーマの確定。
- CSP許可オリジン、停止判定配信、CDN無効化等の配信構成確定。
- 税理士によるゴールデンケース、計算順序、対応プロフィール、公開コンテンツの最終承認。

未登録・未承認値は安全側に `blocked` となるため、上記が残っていても誤った確定額を公開する仕様にはなっていない。

## 追加往復の判断

現時点で第6往復は不要。5往復目で残った課題は、新たな仕様矛盾ではなく具体的な制度値、入力カタログ、配信構成、税理士承認の整備である。これらを埋めた後、実装着手前の「マスター・入力スキーマ監査」を別工程として1回行うのが適切。
