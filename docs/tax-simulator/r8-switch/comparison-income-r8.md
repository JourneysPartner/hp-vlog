## 3. シミュレーターがいま令和8年分で使っている値（コードの行つき）

### 3-1. 結論

1. **公開中の画面は令和8年分を計算していない。計算年は 2025 年（令和7年分）に固定されている。**
   - `src/ui/hojinnari/context-builder.js` 5行 `const SUPPORTED_YEAR = 2025;`、44–47行で `incomeTaxYear` が 2025 以外なら `throw new RangeError('第1版の計算対象年は2025年だけです')`。
   - ④役員報酬も同じ関数を使う（`src/ui/yakuin-hoshu/app.js` 9行 `require('../hojinnari/context-builder.js')`、516行で呼び出し、22行 `incomeTaxYear: 2025`）。
   - ①の画面表示 `src/ui/hojinnari/app.js` 404行「計算対象年：2025年（令和7年分）」。④→①の受け渡しも `src/simulators/browser-entry.js` 199行 `const year = 2025;`。
   - 公開中のバンドル `assets/js/tax-simulator.6079c936.js`（2c524574, 2026-09-03）にも「第1版の計算対象年は2025年だけです」「計算対象年：2025年（令和7年分）」が入っている。
   - したがって今日の結果は BD-R7・SID-R7／APDX5-R7・人的控除（58万円の要件）で計算されている。新版の本文でも令和7年分の値は変わっていないので、**今日の公開結果に誤りは生じていない**。

2. **エンジンを令和8年分（taxYear 2026）で呼ぶと、給与がある計算は例外で止まる。**
   - `src/tax-engine/income/salary-income.js` 80–82行:
     ```js
     const appendixRecords = masters.find('salary_income_after_deduction_appendix5', searchCriterion);
     const bandRule = appendixRecords.find(record => record.method === 'floor_to_band_then_deduction_table');
     if (!bandRule) throw new Error('別表第五の帯規則が利用できません');
     ```
     別表第五のレコードは 2025 年分しか無いので、2026 年は**収入の大小にかかわらず**（660万円以上でも）ここで止まる。給与所得控除の算式表 SID-R8（97–101行で使う）には届かない。
   - サービス側は例外を握りつぶさず投げ直す（`src/simulators/hojinnari/service.js` 1339–1342行、`src/simulators/yakuin-hoshu/service.js` 750–753行）。画面は「計算を完了できませんでした。入力内容とマスターの検証状態をご確認ください」を出す（`src/ui/yakuin-hoshu/app.js` 544行）。①④の法人側は役員報酬＝給与なので、2026 年は**必ず止まる**。
   - **前年（2025 年）の値で黙って計算することはない**（給与の部分については）。止まる。

3. **給与が無い計算（個人事業だけ）は、2026 年でも止まらずに「complete」で通る。** そのとき使う値:
   - 基礎控除: BD-R8（enacted・大綱由来）104万／67万／62万円 … 改正後の本文と一致。
   - 人的控除の金額: 無期限のレコード（扶養 38/63/48/58万、配偶者 38/48 …）… 改正後も同じ。
   - **所得要件: 令和7年分の 58万円のまま**（扶養・配偶者）… 改正後（62万円）とずれる。
   - 生命保険料控除: 23歳未満の扶養親族の特例なし … 改正後とずれる（該当者のみ）。
   - 施行前（enacted）や導出値（derived）である旨の注記は**出ない**。

4. **年度マスターの「対応年」の宣言はエンジンで使われていない。**
   - `TY-SUPPORTED-2026`（support_status `supported_with_pending_law`、`_caveat`「結果に施行前である旨と概算である旨を表示すること」）、`supported_years._how_to_use`「未対応なら resultStatus: blocked を返し、前年値へ黙ってフォールバックしない」（`data/tax-year/tax-year-master.json`）。

## 6. 次の手順の案（台帳 C-1・設計書・仕様書の決まりに沿って）

決まりの確認（**コード**・文書）
- 仕様書 §48: 本番に入れてよいのは `effective`、または「対象期間に適用されることが公布済み法令から確認できる」`enacted` だけ。→ 大綱だけを出典にした BD-R8・SID-R8 は、条文で確かめるまで本番の令和8年分には使えない。
- 仕様書 §50-1-3・18: 重要値は法令本文と所管官庁資料の 2 点で照合。§50-1-20: 同じ言語モデルの読み取りは何回でも 1 者。転記者と照合者は別の人。→ **この比較表は「自動の読み取り 1 回」にあたる。人による原本照合が別に要る。**
- 設計書 §6-1・§1-1: 値の自動書き換えはしない。タックスアンサーの本文から直接転記しない。
- 鮮度チェックの指示: 影響があれば新しい値でレコードを追加し `unverified` から二者確認。影響が無ければ `source_hash` だけ更新。
