## 1. 画面の全体構成

URL `/tools/hojinnari-simulator/`。1ページアプリで、次の画面フローを持つ。

```
[入力STEP 1〜3] → （追加質問・入力不足の解消） → [結果]
```

- **初期表示**: マウント直後から入力STEP 1を表示する。導入画面・開始ボタン・所要時間表示は設けない。「入力と計算はこのブラウザ内で完結し、金額を保存・解析送信しません。」をSTEP 1上部に常設する
- **入力STEP**: 下記 §3。STEP表示は「STEP n / 現時点の総STEP数」をテキストで（§61-1）
- **結果**: 下記 §5。再計算・入力に戻る・入力をクリア・印刷を常設
- 第1版は**かんたん計算のみ**提供する。`precision` 切替UIは置かず `"simple"` 固定で送る（サービスは simple/detailed 同一計算。詳細計算タブは対応範囲拡張（deferred B-1/B-7）と同時に追加する）。「かんたん」の呼称は §5 のとおり画面に表示するが、精度の一語評価はしない
- ④から有効なHandoffを受けた場合だけSTEP 3に引継通知と「リロードすると消えます」を表示する。通常起動時は表示しない
- ツールページは共通header/footer partialを使わず、事務所名・ホーム・税務コラム・お問い合わせ・無料相談の純CSS専用ヘッダと、コピーライト・トップリンクだけの専用フッタを使う（`main.js`は読み込まない）
- ページ上部のH1は初回STEP 1では通常表示し、STEP 2以降・計算中・停止・結果では `.simulator-intro--compact` で縮小してリードを隠す。H1自体はDOMに残す
- STEP・結果等の画面遷移ではアプリ領域先頭へスクロールしてから、新画面の見出しへ `preventScroll` 付きでフォーカスする。同一画面の入力エラーは従来どおりエラー要約へフォーカスする

## 5. 結果画面

上から順に:

1. **結果見出し**（フォーカス先・§61-1）: 「試算結果（2025年分・平年度比較）」＋結果状態。状態は英語列挙値を表示せず、complete は「計算完了」、partial は「一部概算」、blocked は「停止」とする
2. **判定サマリー**（§6・§11・§61-1・§67）:
   - 判定バナーは `combinedReferenceDifference` の符号に応じて「法人化が有利の試算」／「個人事業が有利の試算」、差の絶対値が1万円未満なら「ほぼ同等の試算」と表示する。断定表現にしない
   - 「法人化メリット（＋なら法人化が有利）」はサービスが返した `combinedReferenceDifference` をそのまま表示する。主役数値として金額を一段大きい太字で表示する。マイナスは `▲` と赤系の文字色を併記する
   - 3行比較表の列は「項目／①個人事業／②法人成り／①−②差引／コメント」。税金行は、個人側を所得税＋住民税＋個人事業税、法人側を個人の所得税＋住民税＋法人税等とする。社会保険行は、個人側を本人社会保険、法人側を役員本人負担＋会社負担とする。いずれもサービスが返す `burdens` の加算表示のみとし、税額・保険料を再計算しない
   - 計行は上2行の合計とし、①−②差引が `combinedReferenceDifference` と一致することをビューモデルで検査する。不一致は表示を続行せず例外とする
   - 差引がプラスなら「負担減」、マイナスなら「負担増」、計行は「法人化有利」／「個人事業有利」／「ほぼ同等」。マイナス金額は `▲` を付け、色だけに頼らない
   - 直下に「※法人側の社会保険は役員本人負担と会社負担の両方を含みます（会社負担は法人の経費として法人税等の計算に反映済み）。下の比較表の合計行とは集計の視点が異なります。」と注記する
   - 表コンテナ内だけを横スクロール可能にし、印刷時も判定バナー・3行表・注記を含める
3. **結論カード**（§6）: 断定しない定型文。例:
   「本シミュレーションの入力条件では、**法人化した場合のほうが年間 約81万円 手残りが増える**試算となりました。」
   併記（§11）: 個人事業の手取り／法人化後に個人が使える資金／法人に残る資金／税・社会保険の合計負担（両者）。直下に警告文（§11 そのまま）「法人内部に残る資金は社長個人が自由に使える資金ではありません。」
   設立・維持コスト未入力時: 「法人設立・維持費用（登記・税理士報酬等）は含まれていません」
4. **比較表**（§11 の9行）: 所得税／住民税／個人事業税／法人税等（法人税・地方法人税・法人住民税・法人事業税・特別法人事業税の合計）／本人社会保険／会社社会保険（内訳表示のみ・合計へ再加算しない注記）／個人手取り／法人税引後利益／法人＋個人手残り。該当しない欄は「―」、0円と区別（§11）。差額列に＋/▲併記
   - 「結果の詳細」に所得税エンジンの `orderedIncomeDeductions` の順序を保った所得控除内訳を個人事業・法人化の2列で表示し、配偶者控除・配偶者特別控除・扶養控除を含める
5. **消費税**: バッジ「消費税：比較対象外」（§12）＋除外項目一覧（partial 時は理由付き）
6. **計算範囲**（§5）: 「計算済み n / 対象 m 項目」＋内訳（直接入力／制度既定値／概算（国保）／除外）。対象項目カタログは①で固定（所得税・復興税・住民税・個人事業税・国保・国民年金・法人税・地方法人税・法人住民税・法人事業税等・社会保険・消費税）
7. **警告・前提**: §61 の level 別（critical→attention→info）。前提（assumptions）は折りたたみで全文。「配偶者・扶養親族ご自身の国民健康保険料・国民年金保険料（世帯分）は含めていません。法人化後の被扶養者・第3号被保険者の扱いの差も未反映です。」を明示
8. **根拠**: 計算版・マスタースナップショットID・法令基準日・出典一覧（§7・§59）
9. **アクション**: 役員報酬の最適化へ（④導線・§13）／結果を印刷・PDF保存（§59）／入力を修正する／入力をクリア（§57-1）／個別相談の案内（リンクのみ。金額送信はしない・§57-3 未実装のため）

- partial（法人所在地が違う等）: 結論カードに「概算の前提が含まれます」を明示し、除外項目を5の位置で表示
- 再計算時は旧結果を破棄して見出しへフォーカス（§61-1）

## 8. 移行年度比較（transition_year・§10。設計 2026-09-03・実装前レビュー用）

| 項目 | 備考 |
| --- | --- |
| 法人設立日 | 日付。**個人事業はその前日に廃業と仮定**（別日はv2） |
| 個人期間の売上・経費 | 1/1〜設立前日の実額（**年額の月割按分はさせない**。§10の期間帰属入力） |
| 法人期間の売上・経費 | 設立日〜12/31の実額（役員報酬を除く経費） |
| 役員報酬（月額） | 設立月から12月まで毎月支給と仮定（定期同額） |

- 年齢・自治体・青色区分・家族・所得控除・資本金は既存の共通入力を流用
  （所得控除は個人の年間控除としてそのまま適用）

### 8-2. 計算仕様

**共通フレーム**: 移行暦年（1/1〜12/31）。結果に `comparisonBasis: "transition_year"` と
各期間の開始日・終了日を必ず表示する（§10の必須要件）。

**「この年に法人化」列:**

1. 個人側: 個人期間の事業所得（青色特別控除は所得を限度に適用・月割なし）
   ＋ 給与所得（役員報酬×支給月数）を**同一暦年で合算**して所得税・住民税を計算。
   個人事業税は**事業主控除の月割**（290万×個人事業月数/12。月数は暦により1月未満切上げ
   — 登録済みマスター `individual_business_tax_owner_deduction` の proration_rule に従う）
2. 社会保険: 個人期間は国民年金（月額×月数）＋国保（年額計算×加入月数/12の月割・概算注記）。
   国保の賦課基礎は、個人期間の事業所得（給与所得を含めない）から基礎控除43万円を差し引く。
   法人期間は健保・厚生年金（設立月に資格取得と仮定・標準報酬×月数。会社負担分は法人損金）
3. 法人側: **初事業年度 = 設立日〜12月31日（12月決算と仮定・注記表示）**。
   所得 = 法人期間売上 − 経費 − 役員報酬 − 会社負担社保。
   法人税・地方法人税・法人住民税（法人税割＋**均等割の月割**: 月数は暦により1月未満切捨て・
   全体が1月未満なら1月、確定額は100円未満切捨て）・法人事業税・特別法人事業税
4. 手残り = 個人の手取り ＋ 法人税引後利益（既存 steady_state と同じ定義の期間版）

**「個人のまま」列**: 個人期間＋法人期間の売上・経費をすべて個人の年間として既存の個人計算
（同一金額を両列の双方に計上しない。§10）。

**帰属主義（設計判断）**: 両列とも「移行年の経済活動に起因する税・社保」で比較する。
住民税（翌年度賦課）・国保も移行年所得ベースで計上し、**納付時期のずれは税額と別レイヤー**として
assumptions に明示（§10「予定納税、中間納付、納付時期は税額そのものと別レイヤーで扱う」）。

### 8-3. 設計判断（レビュー対象）

| 論点 | 判断 | 理由 |
| --- | --- | --- |
| 新規マスター | **法人住民税均等割の月割規則1件を新規登録**（地方税法52条4項・312条4項: 暦による月数・1月未満切捨て・全体1月未満は1月）。登録PRは**承認保留**でお渡しする | 事業主控除の月割は登録済み。均等割のみ未登録 |
| 消費税（②連携） | 移行年度モードでは対象外（include:true は blocked）。基準期間リセットの論点は注記＋②ツールへの導線で案内 | 法人成り年は個人・法人の課税期間が2本立ちで②入力が倍になる。v2（B-11と同時） |
| 設立日＝廃業翌日・12月決算・設立月から支給 | 第1版の固定仮定（すべて注記表示） | 入力4点で成立する最小構成。別日・任意決算期はB-11 |
| 国保の月割 | 年額×加入月数/12 の概算（賦課期日・軽減判定の細部は自治体条例依存のため注記） | マスター化は自治体別になるため概算注記が誠実 |
| 繰越欠損金・申告調整・交際費月割 | 既存どおり対象外（blocked） | steady_state と同じ範囲 |

### 8-4. 結果表示

- 判定バナー（既存様式）: 「この年に法人化した場合、しない場合と比べて手残りが約◯円増える/減る試算」＋主役数値強調
- 比較表は既存9行様式を流用し、**期間注記行**（個人期間◯/◯〜◯/◯・法人期間◯/◯〜◯/◯・12月決算仮定）を表の直上に必ず表示

### 8-5. ゴールデン方針

実装指示時に全額を手計算で確定する（走査系ではないが、**構成要素ごとに独立に検算**する）。
端数の出ない設立日（7月1日設立: 個人6ヶ月・法人6ヶ月）を主ケースとし、
事業主控除 1,450,000円（290万×6/12）・均等割 35,000円（7万×6/12）を含む。
月数境界（7月15日設立→個人7ヶ月切上げ・法人5ヶ月切捨て）は単体テストで検証する。
