# ④役員報酬シミュレーター 画面仕様書（U3・第1版）

作成日: 2026-08-29
前提: `ui-design.md`（基盤）・`hojinnari-ui-spec.md`（共通パターン: 金額入力・エラー表示・結果画面の作法・a11y はすべて①と同じ部品・同じ規約）。本書は④固有の差分だけを定める。
対象: 仕様書 §35〜§44・§13・§13-1、④サービスの実装済み契約（12か月同額・配偶者控除・扶養控除・障害者控除・小規模企業共済等掛金控除・協会けんぽ・従業員0の第1版）

## 1. 画面構成

URL `/tools/yakuin-hoshu-simulator/`。

```
[モード選択] → [共通入力] → [モード別入力] → [結果]
```

- **モード選択**（§36）: 3枚のカードから選ぶ。文言は仕様書どおり
  「最適な役員報酬を探す（MODE A）」「欲しい手取りから逆算（MODE B）」「役員報酬から手取り計算（MODE C）」
- **初期表示**: マウント直後からモード選択を表示し、導入画面は設けない。「入力と計算はこのブラウザ内で完結し、金額を保存・解析送信しません。」を画面上部に常設する
- STEP表示・戻る保持・エラー要約・計算中/完了通知は①と同一規約
- ツール専用の純CSSヘッダ/簡素なフッタを使い、共通partialと `main.js` は使わない。ヒーローはモード選択では通常表示、共通入力以降・計算中・停止・結果ではH1を残したまま `.simulator-intro--compact` で縮小しリードを隠す
- 画面遷移はアプリ領域先頭へのスクロール後、`preventScroll` 付きで新画面見出しへフォーカスする。同一画面の入力エラーはエラー要約へのフォーカスを維持する

## 2. 共通入力（STEP 1）

| 画面項目 | 入力先 | 備考 |
| --- | --- | --- |
| 役員報酬控除前利益 | profitBeforeOfficerCompensation | §40 の定義を欄外注記:「会計上の税引前当期純利益から役員報酬と会社負担社会保険料を**除いた**金額。申告調整前・繰越欠損金控除前」 |
| 資本金 | capital | ①と同じ補足 |
| 会社の所在市区町村 | context.jurisdiction | ①と同じ6自治体＋「その他」（団体コード入力）。役員の住所地と同一である前提を注記（officerResidenceSameAsCompany: "yes" 固定。異なる場合は対象外の案内） |
| 年齢を入力してください | officer.ageAtYearEnd | 年末時点の年齢。①と同じ補足 |
| 本人の障害者区分 | officer.disability | 対象外 / 一般障害者 / 特別障害者。本人には同居特別を出さない |
| 配偶者はいますか | spouse | 「はい」の場合だけ合計所得金額を入力。給与収入だけなら年収−55万円、無収入なら0円を目安として案内。「70歳以上」チェックは ageAtYearEnd:71 |
| 配偶者の障害者区分 | spouse.disability | 対象外 / 一般 / 特別 / 特別（同居） |
| 扶養親族の人数 | dependents | ①と同じ5年齢帯。代表年齢17・20・40・71・71、70歳以上は親、それ以外は子として変換。同居/別居を livesTogether へ反映。16歳未満は入力不要と注記 |
| うち障害のある方 | dependents[].disability | 一般 / 特別 / 特別（同居）の人数。同居特別を同居扶養から先に割当し、人数関係を組立時に検証 |
| 小規模企業共済・iDeCoの掛金（年額） | deductions.smallEnterpriseMutualAid | 既定0円。掛金自体は手取りから差し引かず控除だけへ反映 |
| 計算対象年・事業年度 | context | 2025年・暦年事業年度固定（①と同じ）。健康保険は協会けんぽ固定・従業員0・賞与/期中改定なしを注記 |

- spouse / dependents は該当入力がある場合だけ Wire に付け、未入力は従来どおり単身とする
- 「単身」の固定前提は撤去し、生命保険料（新一般・新介護医療・新年金・旧一般・旧年金）、地震保険料・旧長期損害保険料、ふるさと納税、住宅ローン控除額を入力できる。16歳未満の扶養親族に係る障害者控除は対象外
- 医療費控除・雑損控除・ふるさと納税以外の寄附金控除は対象外。ふるさと納税は確定申告を前提とし、ワンストップ特例を使用しない旨を表示する
- assumptions に「小規模企業共済・iDeCoの掛金そのものは支出として差し引いていません（積み立てた資産はご本人に残るため）。税負担の軽減効果だけを反映しています」を表示する

## 3. モード別入力（STEP 2）

- **MODE A**: 探索範囲（いくらから探すか=現在の月額または下限／いくらまで探すか=上限・**空欄可**。空欄なら利益÷12を刻みで切り捨てた月額を上限として導出する〔MODE B のサービス導出と同じ・§38 の既定上限は入力の既定値。2026-09-02 実機フィードバック反映〕）・刻み（1万円/5万円）・最適化基準（§39 の3基準を**文言ごと**表示して選択。既定は「法人＋個人の手残り最大」）。基準C選択時のみ「最低限確保したい個人手取り（月額）」「会社に最低残したい額（年額）」を追加表示
- **MODE B**: 希望手取り月額・刻み
- **MODE C**: 役員報酬月額

## 4. 結果画面

### MODE C（順算）

結果見出し直下に「法人＋個人の手残り（年間）（この試算では）」＋金額を主役数値として大きな太字で表示する。続けて§44 の形: 額面 → ▲社会保険 → ▲所得税 → ▲住民税 → 個人手取り の縦の内訳＋法人側（役員報酬・▲会社負担社保・法人所得・▲法人税等・税引後利益）＋法人＋個人手残り。①の結果部品（―と0円の区別・根拠表示・印刷・クリア）を流用。「結果の詳細」には所得税エンジンの `orderedIncomeDeductions` の順序を保った所得控除内訳を表示し、配偶者控除・配偶者特別控除・扶養控除を含める

### MODE A（探索）

- 結果見出し直下に「最適な役員報酬（月額）（この試算では）」＋金額を主役数値として大きな太字で表示する。その後に結論カード（§41 の文言）: 「今回の条件では、月額役員報酬 **○○円前後** で法人＋個人の年間手残りが最大となる試算です。」＋必須の但し書き（§41 そのまま）「税・社会保険上の数値比較であり、会社の資金繰りや生活費、将来の年金額等まで含めた『最適』を意味するものではありません。」
- 選択した**基準の明示**（§39。基準Bは「法人留保と個人可処分所得を同価値とみなす仮定」を必ず併記）
- **上限付近**（nearUpperBound）: 「探索上限の付近に最良点があります。上限を広げると結果が変わる可能性があるため、最適とは断定できません」— 主役ブロックと結論カードのどちらにも金額を表示しない
- **候補表**（§61-1 のグラフ規約に従い、v1 はグラフなし・表のみ）: 既定の行は「最適点・その前後1刻み・探索の上下限・手残りの符号や順位が変わる境界点」に限定し、表の前に選定規則を文章で明示。「全候補を表示」の展開で全件。列は §42 の系列（月額・法人＋個人手残り・個人手取り・会社留保・税負担・社会保険負担）
- 基準C: 制約を満たす候補が無い場合の案内（制約の緩和を促す）

### MODE B（逆算）

- 結果見出し直下に「必要な役員報酬（月額）（この試算では）」＋金額を主役数値として大きな太字で表示し、続けて§43 の形: 「必要役員報酬 約○○円/月」＋会社負担社会保険（年額）＋会社年間総コスト（報酬年額＋会社負担社保）
- 順算で再検証済みであることを前提表示。解が探索範囲に無い場合は主役ブロックにも**範囲を大きく表示**し、単一額を断定しない（summary.range・§7）

### 共通

- warnings / assumptions / 計算範囲 / 根拠（版・スナップショットID・基準日・出典）は①と同じ配置
- 主役数値ブロックは全モードで印刷対象に含める
- **④→①の導線（§13）**: 結果画面に「この報酬額で法人成りの損得を比較する →」。押すと同一SPA内で①へ遷移し、§13-1 の Handoff（下記）を渡す

## 5. ④→① Handoff（§13-1）

- メモリ内オブジェクトのみ（直列化・URL・ストレージ禁止）。フィールドは §13-1 の要求どおり**月額だけを渡さない**:
  報酬月額・事業年度（暦年）・標準報酬の決定方法（第1版は定時決定前提の固定値）・賞与の有無（なし固定）・支給計画の種別（12か月同額）・sourceSimulator("yakuin_hoshu")・sourceResultStatus・calculationContext（スナップショットID/ハッシュ込み）
- ①側の受け入れ: スナップショットID・ハッシュ・期間の一致を検証し、不一致なら**流し込まずに**「条件が変わったため引き継げませんでした。もう一度④で計算してください」を表示（§13-1: 自動変換しない）。sourceResultStatus が blocked の Handoff は作らない
- 一致すれば①のSTEP 3「役員報酬（月額）」へ値を設定し、「④の結果から引き継ぎました」を表示。**④が算出した税額・手取りを①の結果へ転記しない**（①で再計算する・§13-1）
- リロードで消えることを①側で明示（§57-1）
